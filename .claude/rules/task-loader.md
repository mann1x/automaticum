# Task loader conventions

- Tasks are read from `task.Roots` (`internal/task/task.go`): `Public` is the repository's `tasks/`, `Private` the root the local configuration names in `private_tasks` (`Daemon.PrivateTasks` in `internal/config/local.go`, shown in `examples/config/automaticum.toml`; empty means none). `LoadAll` and `Find` take a `Roots`, never a bare path; tests pass `task.Roots{Public: "../../tasks"}` (`internal/gate/gate_test.go`, `internal/run/run_test.go`).
- The daemon gets its roots from `taskRoots()` in `internal/daemon/daemon.go` and the command line from `place.tasks()` in `cmd/automaticum/config_cmds.go`; a new reader of tasks calls one of those, never `filepath.Join(repo, "tasks")`.
- Both roots use the `<suite>/<task>/task.toml` layout. A task in the private root must say `private = true`; a private task needs a `canary` of 16 characters or more (`validate` in `internal/task/task.go`); the same suite and id in both roots is an error. Prove a loader rule in `internal/task/task_test.go`. A `[[fixture]]` is laid over the seed (`Verify` in `internal/task/exec.go`), so one with no `files` is the seed as given and `validate` allows it only with `expect = "fail"` (`TestSeedFixture`).
- A training-pool task (D105, revised 2026-10-23) is public, in a suite of the repository's `tasks/` whose name starts with `train-`, and says `training = true` (`Task.Training` in `internal/task/task.go`): its runs are rollouts for training, not measurements, and it is never an eval or a held-out gate (`manic_miner` is). `validate` refuses a `train-*` task without `training = true` and a training task outside a `train-*` suite, so one is never taken for an eval; `TestTrainingFlag` proves both refusals. The private root is not used for the pool.
- The pool today is `tasks/train-ml/` (one task per language layer pair: C, C++, C#, Go, Python, Rust, TypeScript), `tasks/train-sh/` (shell) and `tasks/train-game/space_invaders/`. Each task is `task.toml` (`training = true`, `layers`, a pinned oracle `image` per step) · `checker.json` (the steps and the `tests` list the compiled checker reports) · `checker/` (the checker source) · `fixtures/` (`good/` and `bad-*/` laid over `seed/`) · `oracle/` (`build.mjs` · `run_tests.logic.js`) · `seed/` · `NOTES.md` (what the fixtures prove). Before committing a new one run `automaticum task build <suite>/<task>` and `automaticum oracle verify <suite>/<task>`; the oracle image must carry `libatomic.so.1` for the compiled checker (slim images lack it).
- The oracle container's `/tmp` (`RunOracle` in `internal/task/exec.go`) and the lane container's `/tmp` (`Execute` in `internal/run/run.go`) are tmpfs mounted `exec`, as in the build container: a compiled language's checker builds its tests there and runs them, and the agent's own `go test` or `cargo test` does the same. Do not mount either `noexec` again.
- Private task text never leaves the owner's hosts (060 §7): not exported, embedded or sent to a cloud endpoint. The private root and its tasks are never committed to the public repository; its path lives only in the untracked local configuration.
