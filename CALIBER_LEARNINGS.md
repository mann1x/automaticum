# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** Source and spec edits made with an inline `python3 - <<'EOF' ... s.replace(old, new)` do nothing, without an error, when the anchor text does not match. Do every replacement through a helper that asserts the anchor occurs exactly once (`def rep(a, b): global s; assert s.count(a) == 1, (a, s.count(a)); s = s.replace(a, b)`), so a missed or repeated anchor stops the edit before the file is written. After each such edit, grep for the new text (`grep -c 'func newName' <file>`, `grep -n 'X6' docs/specs/*.md`) before building or committing, and when filling placeholders end each file's block with an assertion that none is left (`assert 'PENDING' not in s`) before writing the file. The same id often appears in a second file (an `X` or `O` row is in both `decisions.md` and the spec that owns it): grep for it across `docs/specs/` and update every copy. Keep the edit, the container build and the run of the new binary in separate Bash calls: a single call that chained all three came back as a failure with no output at all.
- **[gotcha]** The local Cerebriline SDK checkout (path in `docs/local/hosts.local.md`) is read-only for this project and can sit detached on an old release tag, so features reported as "landed on main" are missing from the working tree. Do not check anything out: compare with `git merge-base --is-ancestor <tag> HEAD`, find a feature with `git log --all --oneline -S'<name>' -- sdk/packages`, and read newer code with `git show origin/main:<path> | sed -n 'A,Bp'` or `git grep -n <pattern> origin/main -- <path>`. In `git grep`, options such as `-A8` or `-i` must come before the pattern as well as before the revision (`git grep -n -A22 -E '<pattern>' origin/main -- <path>`); written after the pattern or after the revision they fail with `fatal: unable to resolve revision: -A8`, and the rest of the Bash call still prints, so the missing block is easy to overlook.
- **[env]** The tests of `internal/docker` and `internal/task` start real containers on the local Docker engine; they skip themselves with `-short`, without a socket, or when an image cannot be pulled. They bind-mount `t.TempDir()` into containers, so `TMPDIR` must be a directory on a real disk that the engine can see, and `AUTOMATICUM_TEST_ARTEFACTS=<dir>` keeps the built oracle (about 150 MB) between runs instead of rebuilding it each time: `mkdir -p <tmp> && TMPDIR=<tmp> AUTOMATICUM_TEST_ARTEFACTS=<cache> go test -count=1 ./internal/task/`.
- **[gotcha]** A `docker.Mount` source must be an absolute host path. A relative one (a task loaded from `../../tasks` in a test) is taken by the engine for a volume name and the create call fails with `docker: 400: ... includes invalid characters for a local volume name`; make the path absolute where it is loaded (`filepath.Abs`), not at each call. The oracle of `tasks/custom/manic_miner` is a Node single executable and needs `libatomic.so.1`: in a plain `debian:bookworm-slim` it dies with `error while loading shared libraries: libatomic.so.1`, so run it in the Node image pinned in `task.toml`, or in an image that has `libatomic1`.
- **[convention]** Files under `tasks/` are kept byte for byte, because every file of a task is hashed into its identity and the `manic_miner` seed has CRLF line endings on purpose. `.gitattributes` marks `tasks/**/*.html` and `tasks/**/oracle/*.js` as `-text`; after staging a task run `git ls-files --eol tasks` and expect `i/crlf w/crlf attr/-text` for the seed and the fixtures. Never let an editor, a formatter or a `sed` without care normalise them, and add a `-text` line for any new file type whose bytes matter.
- **[convention]** A task artefact is pinned twice in `task.toml`: its build image by digest (`node@sha256:...`) and its result by `sha256`. Build it in a container with `--network none`, twice into two directories, and compare the two hashes before writing the pin; any change to an input (`oracle/build.mjs`, `oracle/run_game.logic.js`) or to the image gives another binary, and `task.Env.Build` then refuses it with `ErrArtefactChanged`. Fix that by rebuilding and updating the pin in the same change, never by loosening the check. After building, confirm the fixtures: the known-good page passes and the seed and the weakened page fail.
- **[gotcha]** Material taken into the repo from outside it carries private strings in places that are easy to miss: the SDK's source comments name real hosts and sessions, and the old harness's scripts, change logs and provenance files hold host nicknames, model tags and absolute paths. Before copying a file from the old harness into `tasks/`, grep that file for the private-string pattern, and when a spec or a comment needs a fact from an SDK comment or an old change log, restate it in neutral words with the file and line instead of quoting it.
- **[gotcha]** The pre-commit hook prints Caliber lines (for example `caliber: refreshing docs...`, `caliber: 14/25 events recorded — need more before analysis`, `caliber: 15 learnings never activated`, or a line of `CALIBER_LEARNINGS.md` text) as the last lines of `git commit` output; they are not errors, so confirm the commit with `git log --oneline | head -1`. Give `git commit` a long timeout because the hook can run an analysis. `.wolf/memory.md` shows as modified again straight after a commit; that is expected and is no reason to amend.
- **[gotcha]** `git add -A internal spike docs cmd .wolf/...` leaves out files at the repo root: an edited `README.md` stayed unstaged and needed a second commit. When a pass touched the README status block, the `Makefile` or `.gitattributes`, or created a new top-level directory (`arms/`, `examples/`), name them in the `git add`, and run `git status --short` after the commit to see what was left behind.
- **[convention]** Files under `tasks/` are kept byte for byte, because every file of a task is hashed into its identity and the `manic_miner` seed has CRLF line endings on purpose. `.gitattributes` marks everything under `tasks/` as `-text` (`tasks/** -text`); after staging a task run `git ls-files --eol tasks` and expect `i/crlf w/crlf attr/-text` for the seed and the fixtures. Never let an editor, a formatter or a `sed` without care normalise them.
- **[pattern]** A sub-agent's hand-back is a claim to check, not a result. Before committing its work, run `gofmt -l`, `go vet` and the tests yourself, count the files of the old corpus before and after the test run (`find <corpus> -type f | wc -l`; the corpus is read-only, so the counts must be equal), and grep the files it touched for private names. Read its "not established" section: a fact from the brief that it could not find in the corpus is stored and written up as "reported", never as "documented" (one re-mapped run's kill, 2026-10-13), and the session that supplied the fact is told so by mailbox. Sub-agents leave `.wolf/` alone: add their new files to `.wolf/anatomy.md` and the row to `.wolf/memory.md` yourself.
- **[gotcha]** The names of the old harness's sibling lanes are private, and they show up in the import report's keys and in `go test -v` output of `internal/legacyimport` (`<lane>/native`, `<lane>:verdicts-native.txt`). Tracked code, tests and specs never name them: a rule applies to "any sibling lane" by a property of its files, and specs say "the larger sibling lane" and "the smaller sibling lane". Add the lane names to the private-string pattern when scanning `internal/legacyimport/`, `cmd/` and `docs/specs/100-legacy-import.md`.
- **[env]** On a host that holds the old corpus, `go test -short -count=1 ./internal/legacyimport/` takes under a second, while `make test` runs that package in full under `-race` and took 260 s: give `make test` a timeout of 10 minutes. The full dry run alone is `AUTOMATICUM_LEGACY_REPORT=<file> go test -count=1 -run TestRealCorpusDryRun -timeout 9m ./internal/legacyimport/` (about 26 s, 12.8 GB read); it writes the report to the file, which is read with `grep -v '^warning\|^re-mapped' <file> | cut -c1-900` and never copied into the repo.
- **[env]** `CGO_ENABLED=0 go build -o <scratch>/automaticum ./cmd/automaticum` builds the command line on the host without the link image; that binary has the arm, task, oracle, lane and endpoint commands, and `legacy import` and `store check` answer "this build has no store". `go vet` and `go test` on `./cmd/automaticum/` need `CGO_ENABLED=0` on the host as well. `arm validate|show|diff` and `task ls|show` need only the checkout (run from the repo root or pass `--repo`); `task build`, `oracle verify`, `lane ls` and `endpoint ls` need a configuration directory (`--config` or `AUTOMATICUM_CONFIG`). Make one outside the repo on a real disk: copy `examples/config`, set `data_root` and `repo` to absolute paths, drop from the lane file every endpoint that has no file under `endpoints/` (a lane naming a missing endpoint is refused), and create the token with `(umask 077; head -c 32 /dev/urandom | base64 > token)`.
- **[convention]** A new command in `cmd/automaticum` is one entry in the `cmds` map of `main.go` under its `"<noun> <verb>"` key plus one line in the usage text. Parse its flags with `args = parse(fs, args)`, not `fs.Parse(args)`: Go's `flag` stops at the first argument that is not a flag, so `automaticum oracle verify demo/answer -repeats 2` printed the usage error until the helper was used. A command that opens the store goes in `store_cgo.go` with a stub returning `errNoStore` in `store_nocgo.go`. A new pure-Go package is added to the `test` target of the `Makefile` (recipe lines start with a tab) and to the `make test` sentence in `CLAUDE.md`.
- **[convention]** An arm states every setting; nothing has a default and an unknown field is an error. An arm that exists only to be extended carries `template = true` at the top (the mark is not inherited); without it `automaticum arm validate` lists what it leaves unstated and exits 1. A child switches a feature off by stating only the switch (`enabled = false`, `owner = "tag"`, `mode = "off"`): the settings inherited under it are dropped, and restating one of them beside the switch is refused. `internal/config/config_test.go` reads `arms/base.toml`, so after any edit under `arms/` run both `automaticum arm validate` and `go test -count=1 ./internal/config/`.
- **[pattern]** A new method on the `store.State` interface is four edits, not one: the interface in `internal/store/store.go`, the DuckDB implementation in `internal/store/duck/duck.go` (bump `SchemaVersion` when it adds a table; so far every change only adds tables, which the schema creates when missing), a test in `internal/store/duck/duck_test.go` run with `make test-store SPIKE_ROOT=<dir>`, and the in-memory fakes in `internal/run/run_test.go` and `internal/daemon/daemon_test.go`. The fakes embed `store.State`, so a method they lack still compiles and only fails when it is called. Packages above the store (`internal/run`, `internal/daemon`) reach it only through `store.State` and small interfaces, which keeps them pure Go and testable on the host.
- **[pattern]** Test `internal/run` and `internal/daemon` with `-race`, as `make test` does: the first run of `internal/run` under the detector found two goroutines appending to one slice. A race report is mostly standard-library frames, so rerun one sub-test and filter them: `go test -count=1 -race -run 'TestVerdicts/pass$' ./internal/run/ 2>&1 | grep -v 'path/filepath\|/usr/local/go' | head -50`. For a test that depends on order or timing, confirm the fix with `-count=3`.
- **[convention]** A field of a run's record holds what was established, never what was merely asked for. The SDK release of a run is the one the lane image's label or the runner reports, not the one the arm names; a run that established none leaves the field empty and the command line prints "not established". Apply the same rule to any new record field, and add a test that a run which never got that far records nothing for it.
