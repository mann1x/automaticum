# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[pattern]** A daemon/CLI-only change (no runner protocol, no lane layer) needs no image rebuild and leaves the basis unchanged: `make build`, `scp` both binaries to `<install>/bin/.new/`, compare `sha256sum` both sides, then in one `set -e` ssh call recheck idle (`lane-1 … idle` and `^0 queued`, else `exit 3`), `systemctl stop`, swap, `git checkout -q <sha>`, `systemctl start`, check `/v1/status`. Tell clients not to use a new flag until you confirm deployed — an older daemon refuses unknown fields.
- **[pattern]** To prove new library code on real lane-host data without a deploy, write a throwaway `internal/<pkg>/zz_real_test.go` that skips unless an env var is set, `go test -c -o <scratch>/<pkg>.test ./internal/<pkg>/`, delete the test file immediately so it's never staged, `scp` the binary and run it with the env var over ssh, then `rm`. Cross-check counts against `run show -json <run>`.
- **[pattern]** The pre-commit hooks (caliber refresh, then gitleaks) make `git commit` slow and noisy. Give the Bash call ~400000 ms timeout and `git commit -q -F - <<'EOF' … 2>&1 | grep -E "caliber:|leaks|scanned|refused"`, then print `echo "commit rc=${PIPESTATUS[0]}"` before `git push` (the grep's own exit code would hide a refused commit).
- **[gotcha]** `.wolf/memory.md` rows use linux-gpu-1's local clock (UTC+1); the lane host and journal use UTC. Get a row's time from `date +%H:%M` on linux-gpu-1. A daemon's `up for` counts from your own deploy's restart; check `systemctl show automaticumd -p NRestarts -p ActiveEnterTimestamp` before suspecting a crash.
- **[gotcha]** A harness-killed TIMEOUT run (stopped at wall + ~2 min grace, not by the runner at the wall; no runner `end` line; basis says "the run did not record its SDK") whose last agent event is a `capped_thinking` / `thinking-condensing` notice means the SDK's thinking-condensation side call did not honour the session abort (4.100.266: the side call never gets the AbortSignal, and the loop checks `throwIfAborted` only after it returns). It is an SDK defect (bug-045), not a harness bug; the TIMEOUT verdict still stands. Fixed upstream in @cerebriline/sdk 4.100.268 (Cerebriline 21938f7f52): abort now reaches the note, retrospective and compaction requests, which also stop streaming past 16,000 chars or on self-repetition.
- **[gotcha]** The private-string gate can hit an SDK build's `package-lock.json` on npm registry URLs of `@scope/<name>` packages whose name equals a gate token. Read each hit line: a `"resolved": "https://registry.npmjs.org/..."` URL is a false positive; re-filter only those exact URL lines and confirm nothing else matches, never skip the check.
- **[gotcha]** `automaticum arm validate -repo <dir>` exits non-zero (rc=1) whenever any arm names an endpoint the installation lacks, even though the ids it prints are valid. In a migration/deploy script, never gate on its exit code (`arm validate … || exit`) — capture the output and assert on it (`grep -q ": valid,"`), then diff the sorted before/after id lists to prove ids are unchanged.
- **[pattern]** To confirm an SDK bugfix actually shipped in a pinned build, don't trust the release note alone: grep the installed minified bundle for the fix's markers and compare old vs new (`setAbortSignal`/`abortSignal` counts in `@cerebriline/core` and `@cerebriline/agents` `dist/index.js`, `16000`/`16e3` for a length cap). A rising count across versions is the evidence; window matches with a `python3 -I` `re.finditer` script, not ugrep.
- **[gotcha]** A twin arm's `arm validate` on a host that lacks the endpoint, and `arm validate -repo <dir>`, exit non-zero (rc=1) whenever any arm names an endpoint the installation lacks, even though the ids printed are valid — expected. In a migration/deploy script never gate on its exit code (`arm validate … || exit`); capture the output and assert on it (`grep -q ": valid,"`), then diff the sorted before/after id lists to prove ids are unchanged. Use `arm diff <floor or previous twin> <new twin>` for a twin (must show only `endpoint` and `model.model`, floor id unchanged); real validation happens on the lane host once the endpoint file exists.
- **[gotcha]** A stub smoke `run start` finishes SKIPPED with reason `gate model_tag: endpoint stub does not answer /api/version` when no stub server is listening on the endpoint's `base_url`. Start `automaticum stub serve` and confirm `curl -s -m3 http://172.17.0.1:7412/api/version` answers `{"version":"0.0.0-stub"}` BEFORE `run start`, or every run of the batch is wasted.
- **[pattern]** Launch the stub server detached over ssh so it survives the Bash/ssh call: `cd <install>/work && setsid nohup <bin>/automaticum stub serve -listen 172.17.0.1:7412 -script stub/<x>.json >> stub.log 2>&1 < /dev/null &`, then `sleep 2; curl -s -m3 .../api/version`. A plain foreground `stub serve` holds the call open until it times out. Stop it by PID with the bracket trick: `P=$(pgrep -f "[s]tub serve -listen 172.17.0.1:7412"); kill $P`.
- **[pattern]** The lane host keeps ready-made stub scripts under `<install>/work/stub/` (`fix-manic.json`, `fix-answer.json`, `say-done.json`, `hang.json` (holds the model request open, sends nothing), `loop-reasoning.json`, the plan scripts). Use `fix-manic.json` + `run start -arm stub-sdk-<ver> -task custom/manic_miner` for a PASS smoke, and `hang.json` + `-task demo/answer -wall-s 60` to exercise the wall path.
- **[pattern]** To prove a new test actually catches the bug it targets, drop only the fix with `git stash push -q <impl-file>`, run the test (it MUST fail, printing the pre-fix state), then `git stash pop -q`. Don't trust a test that was only ever seen passing against the fixed code.
- **[pattern]** A twin arm (same engine, template, sampler, guards and SDK; only the weights differ) is a small file: it `extends` the floor arm, sets a new `endpoint` name on the same `base_url` (so its runs never pool with the floor's), plus `[model] model = <new catalogue tag>`, and needs a matching model entry. These files are the installation's and live in `<config>/arms` and `<config>/models`, never the repo (D118).
- **[gotcha]** `run ls -arm <name>` resolves the name to an id and filters on `arm_id`; a stored run with an empty `arm_id` is invisible to it. The daemon test rig's fake runner records no resolved arm, so a finished run's arm name from `GET /v1/runs` is `""` in the rig — to test code that reads the arm from a record, call it directly on a hand-built `store.Run` whose `Arm`/`ArmID` is set; don't assert on the rig's own finished runs.
- **[gotcha]** When a Python script rewrites `.wolf/buglog.json`, plain `json.dump(d, f, indent=2)` escapes non-ASCII (`§`→`\u00a7`) and drops the trailing newline, rewriting old entries in the diff. Use `open(p,'w').write(json.dumps(d, indent=2, ensure_ascii=False) + '\n')`, then check `git diff --cached .wolf/buglog.json | grep -c '^-[^-]'` prints 0. The same ensure_ascii/newline rule applies to any JSON state file you rewrite.
- **[pattern]** Before a commit, run the private-string check besides gitleaks: grep the tracked files (`git ls-files -z | grep -zv -e CALIBER_LEARNINGS.md -e package-lock.json | xargs -0 grep -IlniE "$P"`) and the added lines of `git diff --cached` for private host nicknames, absolute paths and addresses. `xargs grep` exiting 123 and `grep` exiting 1 both mean nothing found. Never write the private pattern list itself into a tracked file.
- **[gotcha]** The SDK's Ollama provider sends one-time first-use probe chats to `/api/chat` (`options.num_predict == 1`, `stream:false`, a user/assistant/tool message triple) BEFORE the first real turn. The stub answers these at once (empty assistant message, `done_reason` `length`, no `prompt_eval_count` so the SDK decides channel as before) and does NOT record them in `Chats()`, so a `hang` turn holds the real turn and not the probe. To deliberately hold the probe (e.g. to test an abort landing on it), set `hang_probe = true` on the Script.
- **[pattern]** To confirm an SDK probe/abort-signal fix actually shipped, grep the installed `@cerebriline/llms/dist/index.js`: find `options:{num_predict:1}` and check whether `signal` appears within ~900 chars of it (the probe `fetch` carries `signal:o` only after the fix). 4.100.268 → absent, 4.100.269 → present. A rising `AbortSignal.timeout` count across versions is corroborating evidence; window the matches with a `python3 -I` `re.finditer` script.
- **[gotcha]** A clean `git push` prints only `remote:` lines, so `git push … | grep -v "^remote:"` exits 1 (grep matched nothing) even though the push succeeded. Don't read that exit code as failure — confirm with `git log --oneline -1 origin/main` and `git status -sb`.

- **[pattern]** For a per-arm gate summary point clients at `automaticum compare -all -batch <floor> -batch <twin>…`. `run ls -arm <name>` resolves the arm from the current checkout, so it omits runs of an earlier version of that arm (another id); use `-model` or `-arm-id`. `run start` prints the batch id on its first line; a run-id prefix is not a batch id.
- **[convention]** A metric name must never carry free text (a sentence, count, or quoted tool name) — every run would get its own and none would pool in `compare`. Key by stable fields: notices are `notices.<type>.<kind>.<phase>`, else `notices.<reason>`, else `notices.<type>` (D116). Count an event announced at start and end once, at phase `completed`.
- **[gotcha]** `.claude/rules/runner-protocol.md` writes out the current `AnalysisVersion`. When you bump it in `internal/ingest/analyse.go`, update that rule and the dated note in 070 §2. Stored runs keep their old metrics until `automaticum reanalyse` runs on the lane host after the deploy.
