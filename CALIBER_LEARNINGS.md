- **[pattern]** `git commit` runs the Caliber refresh and the gitleaks pre-commit hooks, which take a while. Run the commit with `run_in_background`, chaining `echo rc=$?`, the `git show HEAD` private-string grep and `git log --oneline -1`. When it finishes, grep its output for `no leaks found`, `rc=0` and the grep's `rc=1` (no match) before you push.
- **[pattern]** To get a real run's material for a temporary test, call the lane host's CLI by path with `AUTOMATICUM_CONFIG` set. `automaticum logs <run>` prints the event stream and `automaticum logs --kind wire <run>` prints the wire capture. `automaticum run show <run>` lists which blob kinds the run has. Redirect the output to a scratch directory on persistent disk, never /tmp (a run's material can be over 100 MB). Delete the scratch copies, on the host and locally, once you are done.
- **[gotcha]** The event stream has no `content_end` for a turn the output limit or the wall limit cut off. The SDK's retry after the output limit (`max_tokens_turn_recovery`) is not in the event stream at all: only the wire capture holds that answer. Any new reader of `content_start`/`content_end` must keep a block that never ended. `Events.Read` keeps these as `Block.Unfinished` (`scan.flush`). An unfinished block ends at its last delta, not at the time of the flush. Since analysis version 17, `Events.WireAnswers` adds the wire-only answers as blocks with `Block.Request != 0`. It matches them by time overlap, not by text, so a new block reader must tell event-stream blocks from wire blocks.
- **[gotcha]** `Events.TurnStarts[i]` is the i-th `iteration_start` seen, not turn `i+1`. A stream can start at a later iteration or skip one. To map a time to a turn, use the iteration number recorded with each start, never the index.
- **[pattern]** `ReadWire` parses agent answers in two places: the Ollama `/api/chat` answer (`message.content`/`thinking`) and the OpenAI-compatible SSE answer (`delta.content`/`reasoning_content`/`reasoning`). A new answer field on `Request` must be read in both. Assert it in both fixtures: the `answer` fixture used by `TestReadWire` in `ingest_test.go`, and the stream in `TestOpenAIWire` in `openai_test.go`.
- **[gotcha]** `go build ./...` on the host fails, because some packages need the cgo link image. To check that the code compiles before a test, run `go build ./internal/... && CGO_ENABLED=0 go build -o /dev/null ./cmd/automaticum`, then `go vet` on the package you changed.
- **[correction]** A new guard of the harness is built as a detector first: it observes, records where it would have tripped as a finding and as metrics, and `detect` shows it. The owner asked "shouldn't this guard be part of detect?" Stopping a run on it is only an arm opt-in through `guards.stop_on`, never the default. Clients track rates across checkpoints, and a guard that stops runs changes the very thing they measure. Leave existing arms and shipped guards as they are.
- **[convention]** Never replace an out-of-range or unparseable request parameter with its default without saying so. Refuse it with a 400 that names the valid range. `/v1/runs?limit=100000` once returned 50 runs silently: the owner called it a bug, and the fix is bug-078. The run list is capped at 10000 (`maxRunList`), so pass `--limit 10000` or less.
- **[gotcha]** `automaticum detect --json` prints one pretty-printed JSON document with the keys `header`, `runs`, `total`, `groups` and `end`. It is not JSON lines, and parsing it line by line fails. Use `json.load(f)["runs"]`. `detect --all --finished` covers only finished runs, so it returns fewer runs than `run ls`. To get a run's `sdk_release`, join with `run ls --json`.
- **[pattern]** When a detector's counting rule changes, measure its threshold again on the new count; never carry the old maximum over. For `duplicate_definitions`, keying definitions by class moved the limit from 3 to 1. Update the canary test's expected numbers with a comment giving old → new. Add positive and negative controls in `controls.go`. Bump `detect.Version` (library) and `AnalysisVersion`. Then check with `CGO_ENABLED=0 go run ./cmd/automaticum detect --self-test`.
- **[pattern]** To end a run from the daemon with a particular verdict, cancel the flight's context with a typed cause (`context.WithCancelCause`, like `run.GuardStop`). Then add an `errors.As` case to the "What ended it" switch in `internal/run/run.go`, which sets `Facts`; `Decide` in `verdict.go` maps those facts to the verdict. Test it like `TestOperatorAbortAndEndpointChange`: `newWorld`, with the fake runner calling `cancel(cause)`.
