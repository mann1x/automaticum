# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[env]** `go test` and `go test -bench` put `t.TempDir()` under `/tmp`, which is tmpfs here. The blob tests and benchmarks write hundreds of MB and call fsync, so run them with `TMPDIR` set to a scratch directory on a real disk (`mkdir -p <dir> && TMPDIR=<dir> go test ...`) and delete that directory afterwards. If the scratch directory is inside the repo, remove it before `git status` or staging.
- **[gotcha]** In `internal/store/lance`, Arrow arrays that come back from `lance-c` through the C Data Interface own their buffers only until the record batch is released. `array.String.Value(i)` aliases that buffer, so copy every string with `strings.Clone` before releasing, or search hits contain garbage. When building a `FixedSizeList` column, `AppendNull()` already adds the child slots: adding them again panics with `fixed-size list value count must equal list length times list size`.
- **[convention]** Test fixtures for `internal/legacyimport` are synthetic: they mimic the old harness's file formats (`build.txt`, `exit.txt`, `verdicts-*.txt`, wrapped event stream, state tar) but copy none of its data, use placeholder model names (`model-a:Q4`) and an `endpoint.invalid` URL. Never copy real run files, model tags, host names or paths from the legacy corpus into a tracked test; inspect the corpus read-only and re-create the shape by hand.
- **[pattern]** A sub-agent told to stay inside one package (as for `internal/store/blob`) does not update `.wolf/anatomy.md` or `.wolf/memory.md` and says so in its report. After the hand-back the parent session adds the anatomy entries and the memory row itself, and re-runs `gofmt -l internal/`, `go vet` and the package's tests before building on the result rather than trusting the reported test output.
- **[gotcha]** The link image (`automaticum-build:ml228-amd64`) has no `/usr/bin/time`: a job wrapped in `/usr/bin/time -v` dies at once with exit 127, while the `docker wait` task still reports "completed (exit code 0)" because the wrapper script ended with `echo`. Time a job with `s=$(date +%s) ... $(( $(date +%s) - s ))`, read peak memory from `/sys/fs/cgroup/memory.peak`, write `exit $rc` into the result file, and read that file rather than the notification.
- **[pattern]** Run long measurements and real imports as a detached, named container with `--cpus` and `--memory` caps (the host is shared and often loaded), wait on it with `docker wait <name>` under `run_in_background`, and have the job write one result file per step plus a `progress.log` (start time, load average, exit code) under `$SPIKE_ROOT/work/results/`. While such a container is running, never rebuild the binary it mounts: build the changed program under a new output name (`bench2`, `bench3`, ...) and `docker rm` the finished container before reusing its name.
- **[gotcha]** `internal/legacyimport` has a test, `TestRealCorpusDryRun`, that runs against the real legacy corpus whenever `AUTOMATICUM_LEGACY_ROOT` is set or the untracked `spike.local.toml` has `legacy_root` (and `legacy_state_archive`). Without `-short` it reads about 30 GB of streams and the package takes over two minutes under `-race`, so `make test` is slow on a host that has the corpus; use `go test -short` for a metadata-only pass (under a second) and `-run 'Test[^R]'` to leave it out. The counts it asserts were taken on 2026-10-13 and move if the old harness runs again; the verdict-file check is the part that must keep holding.
- **[convention]** The legacy corpus and its state archive are only ever read. Mount them `:ro` in any container (`-v <legacy>:/legacy:ro`), and around every import or dry run record the file count and total bytes before and after (`find <dir> -type f | wc -l`, `du -sb <dir>`) and state both figures in the report. Import targets and benchmark data go under `$SPIKE_ROOT/data/`, never inside the legacy tree.
- **[env]** A container that must reach the local Ollama server (embeddings for the store benchmarks) needs `--network host`; without it `127.0.0.1:11434` is the container itself. Before starting an embedding job, look only (`curl -s http://127.0.0.1:11434/api/ps`, `nvidia-smi --query-gpu=memory.used,utilization.gpu --format=csv,noheader`) to see whether the GPU is in use, and do not unload anything.
- **[convention]** What a measurement, spike or import turns up is never written into a spec as a decision. Each change it suggests goes in as an inline `**Open**` item with a recommendation, plus an `O` row in `decisions.md` section 3 with "the owner" in the waits-for column. Take the next unused `O` number and never reuse one named in the "Closed since" line. Choices the code already makes that the owner has not seen are listed under their own heading in the spec, saying so. In the same pass bump the `**Status:**` line of every spec touched and update the status sentences in `110-acceptance-and-roadmap.md`, `010-architecture.md` and the `README.md` status block. A new subsection is appended at the end of its section with the next number; existing section numbers do not move.
- **[gotcha]** The import report and the result files under `$SPIKE_ROOT/work/results/` (for example the `InvalidNotes` and `Runs` fields of the legacy import report) quote the old harness's own notes, with real host nicknames, model tags and paths. Never paste them into a spec, a report or a test. Describe such reasons in neutral words ("a swallowed template") and give counts only.
- **[gotcha]** There is no `duckdb` command-line client on the host or in the build images. To look at the tables of a store, run the query through the Go binary (`automaticum store check -data <dir>` prints the row counts) or add the query there and rebuild in the link image; do not install a client on the host.
- **[pattern]** When a report or spec is written while measurement jobs are still running, mark each missing figure with one literal token that grep finds (`PENDING`, or a placeholder such as `T11-RESULT`), and run `grep -rn 'PENDING\|-RESULT\|-VERDICT\|-PEAK' spike/ docs/specs/` before committing: it must print nothing, or the commit message says which figures are still missing. Wait for such jobs with a background `until [ -s <result>.json ] || [ -s <result>.err ] || [ $i -ge N ]` loop: the result files exist with 0 bytes from the start because of the shell redirection, so test with `-s`, never `-f`.
- **[gotcha]** Source edits made with an inline `python3 - <<'EOF' ... s.replace(old, new)` do nothing, without an error, when the anchor text does not match. After each such edit, grep for the new text (`grep -c 'func newName' <file>`) before building. Keep the edit, the container build and the run of the new binary in separate Bash calls: a single call that chained all three came back as a failure with no output at all, leaving it unknown which step had failed.
- **[convention]** `make test` runs `go test -race` on the pure-Go packages on the host. `make test-store SPIKE_ROOT=<dir>` runs `go test -tags lance ./internal/store/...` in the link image and is the only way to test `internal/store/duck` and `internal/store/lance`; anything that imports the Lance wrapper (the tests, `spike/001-store/bench`) needs the `lance` build tag.
- **[pattern]** Before every commit, and before `git push` to the public repo, scan all tracked files for private strings and expect `CLEAN`: `git ls-files | grep -v CALIBER_LEARNINGS.md | xargs grep -IlniE "<pattern>" || echo CLEAN`, where the pattern lists the real host nicknames, the absolute path prefixes, the LAN address prefix and the disk ids from `docs/local/hosts.local.md`. Raw result files copied from `$SPIKE_ROOT/work/results/` into `spike/001-store/results/` get the same scan plus the container mount paths (`/data/`, `/archive`) before they are staged.
- **[gotcha]** `docker stats` (and the cgroup memory figure) for a benchmark container includes file cache: a run showed 22 GiB there while the process's own peak was 5.5 GB. Report memory from the process's peak RSS (`VmHWM`, the `peak_rss_mib` field the benchmark writes), not from `docker stats`. When a job ends, read how it ended with `docker inspect <name> --format 'oom={{.State.OOMKilled}} exit={{.State.ExitCode}}'`, the last lines of `progress.log` and the head of the `.err` file before using its numbers.
- **[pattern]** After changing a type or option in `internal/store/store.go`, everything that imports it must be rebuilt, and most of it only builds in the link image. Run one container command chained with `&&` and a closing sentinel: `go vet -tags lance ./... && go test -tags lance -count=1 ./internal/store/... && go build -tags lance -o /dev/null ./spike/001-store/bench/ && go build -o /dev/null ./cmd/automaticum && echo ALL-OK`, and treat a missing `ALL-OK` as failure. `gofmt -l` on the host stays silent about a missing import in a test file; only this step shows it. Then run the pure-Go tests on the host with `-short`.
- **[convention]** Record the option the owner actually picked, with its condition, not the one that was recommended (on 2026-10-13 the owner chose "confirm, re-check at milestone 6" over the plain "confirm"); say in the `.wolf/cerebrum.md` line when the choice differed from the recommendation. A report that listed questions for the owner (`spike/001-store/REPORT.md` section 6) gets a dated "Decided" paragraph with the `D` numbers above the list, and the list itself stays as it was put. Decisions that change an interface (a default, a new field) are then applied to the code and tested in the same session.
- **[gotcha]** The pre-commit hook prints a Caliber line (for example `caliber: 14/25 events recorded — need more before analysis`) as the last line of `git commit` output; it is not an error, so confirm the commit with `git log --oneline | head -1`. Give `git commit` a long timeout because the hook can run an analysis. `.wolf/memory.md` shows as modified again straight after a commit; that is expected and is no reason to amend.
- **[pattern]** In an inline Python edit that fills placeholders, end each file's block with an assertion that none is left (`assert 'PENDING' not in s`, `assert '**Open' not in s`) before writing the file, so a replacement whose anchor did not match stops the edit instead of passing silently.
- **[gotcha]** Source and spec edits made with an inline `python3 - <<'EOF' ... s.replace(old, new)` do nothing, without an error, when the anchor text does not match. After each such edit, grep for the new text (`grep -c 'func newName' <file>`, `grep -n 'X6' docs/specs/*.md`) before building or committing, and when filling placeholders end each file's block with an assertion that none is left (`assert 'PENDING' not in s`) before writing the file. The same id often appears in a second file (an `X` or `O` row is in both `decisions.md` and the spec that owns it): grep for it across `docs/specs/` and update every copy. Keep the edit, the container build and the run of the new binary in separate Bash calls: a single call that chained all three came back as a failure with no output at all.
- **[convention]** Record the option the owner actually picked, with its condition, not the one that was recommended (on 2026-10-13 the owner chose "confirm, re-check at milestone 6" over the plain "confirm", and a public task directory over the recommended private one); say in the `.wolf/cerebrum.md` line when the choice differed from the recommendation. In a multi-select question, an option the owner left unticked is written down as "offered and not chosen", not silently dropped. A free-text answer is recorded in the owner's terms (for example "every run records the SDK release version") as its own `D` row. A report that listed questions for the owner (`spike/001-store/REPORT.md` section 6) gets a dated "Decided" paragraph with the `D` numbers above the list, and the list itself stays as it was put. Decisions that change an interface (a default, a new field) are then applied to the code and tested in the same session.
- **[gotcha]** The pre-commit hook prints a Caliber line (for example `caliber: 14/25 events recorded — need more before analysis`, or a line of `CALIBER_LEARNINGS.md` text) as the last line of `git commit` output; it is not an error, so confirm the commit with `git log --oneline | head -1`. - **[gotcha]** `git add -A internal spike docs cmd .wolf/...` leaves out files at the repo root: an edited `README.md` stayed unstaged and needed a second commit. When a pass touched the README status block, the `Makefile` or `.gitattributes`, name them in the `git add`, and run `git status --short` after the commit to see what was left behind.
- **[correction]** Embeddings are updated by hand (owner, 2026-10-13, D52): "with this amount of data we clearly can't do it scheduled or automatic". Never design, schedule or start an embedding pass from the daemon, an ingest step or a cron entry; ingest writes chunks without vectors and the operator starts a pass for a stated scope (`automaticum embed start|status|stop`).
- **[pattern]** "chk mail" from the owner means the pgvector mailbox of this session: `mcp__pgvector__mailbox-list`, then `mailbox-read` with the ids, then `mailbox-ack` with a short note saying what will be done with each point. The peer sessions' mailbox names are in the untracked `docs/local/hosts.local.md`. Facts a peer session reports go into the spec with the date and with what was and was not checked ("§6 checked row by row; §6.1 and §6.2 not checked"); a proposal from a peer that contradicts an owner decision (such as defaults for guards, against 030 §5.1) is not adopted, and the spec says so in one sentence.
- **[gotcha]** The local Cerebriline SDK checkout (path in `docs/local/hosts.local.md`) is read-only for this project and can sit detached on an old release tag, so features reported as "landed on main" are missing from the working tree. Do not check anything out: compare with `git merge-base --is-ancestor <tag> HEAD`, find a feature with `git log --all --oneline -S'<name>' -- sdk/packages`, and read newer code with `git show origin/main:<path> | sed -n 'A,Bp'` or `git grep -n <pattern> origin/main -- <path>`. In `git grep`, options such as `-A8` or `-i` must come before the revision; after it they fail with `fatal: unable to resolve revision: -A8`.
- **[gotcha]** When the owner names an SDK release as done, check it read-only before building on it (`npm view @cerebriline/sdk version`, `git tag --sort=-creatordate | head -3` in the checkout). On 2026-10-13 the owner said 4.100.250 was released while the registry still showed 4.100.249: write the discrepancy into the plan, check again at the step that installs it, and stop and report if it is still missing. Never fall back to another build on your own (D54: a run whose SDK release version cannot be established does not start).
- **[pattern]** A milestone plan lists the owner's answers in a "Decided by the owner" table with the next free `D` numbers, and every design choice of its own under "Proposals in this plan (approve with it, or strike)". Once the plan is approved, the first step records all of it before any code: one `D` row per answer, further `D` rows for the approved proposals, the `O` row a proposal closes removed and its number added to the "Closed since" line, the specs and status sentences updated, and one dated line in `.wolf/cerebrum.md`. Sub-agents sent to survey the old harness or the SDK checkout are told to change nothing and to write `<host>:<port>` in place of any real host name or address in their report.
