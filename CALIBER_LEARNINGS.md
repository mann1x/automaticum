# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** `go build ./...` from the repo root always reports `no required module provides package github.com/northwind/...`: those are the task checkers under `tasks/train-ml/*/checker`, which import their task's own packages, and the noise can hide a real error. Build the packages you changed (`go build ./internal/daemon/`, `CGO_ENABLED=0 go vet ./cmd/automaticum`) instead. A bare `go build ./cmd/automaticum` writes an `automaticum` ELF binary at the repo root, which `git add -A` then stages. Prefer `go vet`, or `go build -o /dev/null`, and check `git status --short` for a stray `A  automaticum` before committing.
- **[pattern]** Thresholds ported from the SDK hold per release, not for the SDK as a whole: the reasoning-loop guard changed at 4.100.258 while the code still cited 4.100.250/251. Before trusting or extending a port, loop over every pinned build's `node_modules/@cerebriline/agents/dist/index.js` (or `core/dist/index.js`), regex out the default config object (e.g. `=\{minChars:4000,window:60[^}]*\}`) and print a sha1 of the class body. Equal hashes mean the same code, and the first differing build is where to read. When a replay does not confirm a guard trip, read the SDK's notice metadata for that turn (`kind`, `period`, `cycles`, `sample`) before assuming the detector is wrong: it names the rule the port is missing.
- **[pattern]** Fixtures do not show what a real stream does. To try analysis on a real run, add a temporary env-gated test `internal/ingest/zz_real_test.go`: skip when `REAL_EVENTS` is empty, call `ReadEvents`, then `Analyse(&store.Run{ID: "x", Harness: os.Getenv("REAL_SDK")}, ev, nil)`, and print chosen metrics and findings. Run it with `-count=1 -v`, compare under two `REAL_SDK` values when rules depend on the release, and `rm` it before staging. The event stream stays in a scratch directory, outside the repo.
- **[fix]** Deploying to the lane host: `scp` onto the running `bin/automaticumd` fails with `Text file busy`, and the same `scp` silently overwrote `bin/automaticum` with no copy to go back to. Copy each binary to `bin/<name>.new` and compare sha256 on both ends. Then, in one `set -e` ssh script: gate on `automaticum status` (lane `idle` and `0 queued`), `systemctl stop`, `mv` the old binary to `.prev`, `mv` `.new` into place, start. On the host the CLI is not on PATH: call `<root>/bin/automaticum` with `AUTOMATICUM_CONFIG=<root>/config`. Full steps are in the `learned-lane-host-deploy` skill.
- **[pattern]** Never write "the SDK emits no event for X" from one run's stream. That claim went into 070 and the audit from a run with the change protocol off, while the bundle has `atomic_transaction`, `atomic_empty_attempt` and `atomic_plan` notices. Search `node_modules/@cerebriline/core/dist/index.js` for `kind:"<prefix>[a-z_]*"` and its `dispatchAgentEvent` calls first. When porting an SDK observer, its verdicts land only where the SDK calls `inspect` (for the struggle detector, `content_end` and `iteration_end`). A test's expected firing turn must therefore sit at such an event, not at the notice that changed the state.
- **[gotcha]** A stored run's event stream (`logs <run> --events -json`, or a scratch `.jsonl`) wraps every SDK event twice. Lines look like `{"t":...,"k":"event","event":{"type":"agent_event","payload":{"event":{...}}}}`, mixed with `"k":"runner"` notes, so counting `e["type"]` or `e["event"]["type"]` only gives `agent_event` and `chunk`. Read `e["event"]["payload"]["event"]`: the notice kind is in `.metadata.kind` and the phase in `.metadata.phase`.
- **[pattern]** To list what is still unbuilt in one spec, grep the audit rows instead of reading the file: `grep -n "^| 070" docs/audit/2026-11-01-spec-vs-code.md | grep -E "NOT BUILT|PARTIAL" | cut -c1-210`. When a change closes a row, update its status (`BUILT`, `PARTIAL`, or `OPEN` with the `O` id) and its evidence in the same commit.
- **[gotcha]** In the daemon, `notifyEnd` runs after a run's end is visible and after the lane is free. In tests, `waitFinished` returning does not mean the notifications went out: use `waitFor` on the count before asserting on captured notifications. A new notification kind also changes exact counts in existing tests such as `TestGates`. In code, state that must hold for the lane's next run (a quarantine, say) cannot be set in `notifyEnd`, because the scheduler can start the next run first. Set it in the run's goroutine before `delete(d.flights, ...)`.
- **[convention]** An Open item the owner drops does not become a `D` row. It goes into `docs/specs/decisions.md` section 5 (Not adopted) with its O id and reason, and its audit rows get the status `NOT ADOPTED`. After closing O items, find every marker with `grep -n "O3[1-9]" docs/specs/*.md` (with the ids at hand): they also sit in 020, 050, 065, 070 and 090, and in the closed-items list of `decisions.md`.
- **[gotcha]** The Open table in `docs/specs/decisions.md` §3 lists only items still open. `grep '^| O'` there gives a low id (O29) while O30 to O39 are already used and closed. Take the next id from every spec with `grep -ohE 'O[0-9]+' docs/specs/*.md | sort -t O -k2 -n -u | tail -1`. Then add the new row, the `**Open (O<n>):**` note in the spec and the audit row's `OPEN` status in one change.
- **[convention]** Anything a spec says a suite declares waits for the suite definitions `suites/*.toml` (milestone 5): the `runaway` size, the visible-character floor, a subset's headline such as `loop_rate`, the canary length band. No suite loader exists today and the task loader has no suite-level fields. Do not invent a task field for it. Say so in the spec and mark the audit row `SCHEDULED (m5)`.
- **[gotcha]** A multi-file python heredoc followed by `; echo ok` or a new line hides a failure: the traceback scrolls past, `ok` still prints, and the files written before the failing step stay changed. Chain with `&&` and write each file with an `assert a in s` on the anchor first. After a failure, rerun only the steps that did not apply, since the earlier replacements are already in place.
- **[gotcha]** The daemon tests' `memState` embeds a nil `store.State`. A handler that calls a store method `memState` doesn't override still compiles, then panics at runtime. When a new handler uses another store method (e.g. `ToolCalls`), add that method to `memState` first. `memState`'s `ListRuns` filter has its own field list, which ignores `RunFilter.Since`, so a window on `Since` is not exercised in the rig. The rig's `memBlobs` is a read-only map: a test whose handler stores blobs needs a store with a `Put` and a lock, as `syncBlobs` in `rescore_test.go`.
- **[env]** A full `make test` takes close to 5 minutes, nearly all of it `internal/legacyimport` under `-race`, so pass a Bash timeout of 600000 ms. While iterating, use `go test -race -count=1 -run <Test> ./internal/daemon/`, and `CGO_ENABLED=0 go test` for `cmd/automaticum`. `make test` does not compile `cmd/automaticumd`, so after changing the daemon's wiring there run `CGO_ENABLED=1 go vet ./cmd/automaticumd/`. When you pipe it through `grep -v "^ok\|cached"`, read the result from `echo rc=${PIPESTATUS[0]}`, since the pipe's own status is grep's.
- **[env]** The `internal/docker` tests that run without `-short` (`TestRun`, `TestRunChanges`) use the host's real Docker engine and pull `debian:bookworm-slim`. `make test` passes `-short`, so they never run there. After touching `docker.go`, run them by hand under a claim: `claude-hooks-res run <host>:shared -r "<why>" -- go test -run '<Test>' -v ./internal/docker`. Only the real engine shows its quirks: `GET /containers/{id}/changes` reports a container's mount points and the directories above them as added or changed, which is why `docker.notMounts` exists.
- **[env]** `git commit` here runs a pre-commit hook that does `caliber refresh` (rewriting `CALIBER_LEARNINGS.md`) and a gitleaks scan of the staged diff. It can take minutes, so pass a Bash timeout of 300000 ms and give the message with `git commit -q -F - <<'EOF'`. Before `git push`, scan the commit itself with `git show HEAD | grep -niE "$P"`: rc 1 means clean.
- **[pattern]** Go edited by a python heredoc is not formatted, and neither `go build` nor `go vet` complains: a new field beside aligned struct fields leaves the file unformatted. Run `gofmt -l internal cmd` after such edits and `gofmt -w` what it lists. When a scripted edit uses a new package, add the import with `grep -q '^\t\"path\"' f.go || sed -i '0,/^import (/s//import (\n\t\"path\"/' f.go`, then let `gofmt -w` put it in order.
- **[gotcha]** The OpenWolf post-write hook adds an anatomy entry and a memory row only for files made with the Write tool, and its description is a stub such as `Struct: written`. Files made with a Bash heredoc (`cat > x_test.go`) get no entry at all. After a batch of new files, run `grep -n '<file>' .wolf/anatomy.md` for each and add the missing ones. Where there is a stub, replace it with the real description: adding a line beside it leaves the file listed twice.
- **[convention]** A mutating route takes its dry run as the query parameter `?dry_run=1`, not a body field: the handler checks `dryRun(r)`. The CLI uses `addMutation(fs)`, `m.on(c, path)` and `m.dryNote()`, which also bring `--idempotency-key`. Read these helpers before adding a new mutating command.

- **[gotcha]** Detector options reach more than ingest. `detect.Block` is called from `internal/ingest` (`DetectOptions`, `blockOptions`), `handleDetect` in `internal/daemon/api.go`, `automaticum detect` in `cmd/automaticum/client_cmds.go` and `export.Spans`. For any option that depends on the run, run `grep -rn "detect.Options{" --include=*.go internal cmd | grep -v _test` and pass it at every site, or the views disagree with the stored findings.
- **[gotcha]** `TestRunImported` asserts an exact `len(m.findings)`, so a new detector that fires on its stream fails it even when the detector is right. `store.Finding` prints `Evidence` as decimal bytes, which fills the failure output: pull out `Detector`, `Turn` and `Count` with a small regex over the output instead of reading it. A rule that groups calls by turn must treat `Turn: 0` as a turn that is not known (an imported stream without iterations), not as one shared turn.
- **[gotcha]** `.claude/rules/runner-protocol.md` writes out the current `AnalysisVersion`. When you bump it in `internal/ingest/analyse.go`, update that rule and the dated note in 070 §2. Stored runs keep their old metrics until `automaticum reanalyse` runs on the lane host after the deploy. A new ingest detector needs all three of these:
  - an entry in `owned`, otherwise `reanalyse` keeps its old findings beside the new ones;
  - an entry in `Versions`, otherwise the basis does not name it;
  - the `AnalysisVersion` bump.
  A metric family written at zero on every run (`struggle.*`, `transactions.*`, `integrity.*`) also needs its prefix in the zero-hiding list of `run show` in `cmd/automaticum/client_cmds.go`. A report that reads new metrics must count runs below the new `analysis.version` separately (as `report struggle` does), not as "never held".
