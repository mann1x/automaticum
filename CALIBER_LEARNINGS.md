# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** An endpoint `kind` is not always an SDK provider id. `llamacpp` is an OpenAI-compatible llama-server and the SDK has no provider of that name; passing it through gives `Unknown or disabled provider "llamacpp"` before the first chat request, and since D89 the run is `ABORTED` (before that `FAIL`, cell exit 10). Always map kinds with `config.ProviderFor(kind)`; when adding a kind, grep the SDK's `@cerebriline/llms/dist/index.js` for the provider id. A mode C cell with no chat request on the wire is a harness bug — check `logs <id>` for an agent `"type":"error"` event.
- **[gotcha]** The CLI uses Go's `flag` package, so flags must come before positional arguments. `automaticum run invalidate <run> "<reason>"` prints only usage; use `automaticum run invalidate --reason "<why>" <run>`. Likewise `automaticum run start -arm stub demo/answer` fails with usage — the task is a flag: `run start -arm stub -task demo/answer`.
- **[pattern]** When you add a field to the runner's last line (`End` in `internal/run/protocol.go`) that a harness rule depends on, make it a pointer (`*int`) so `nil` means "an older runner did not report it" and the old rule still holds. Document it in `runner/PROTOCOL.md`. In `run_test.go` you can override an `endLine` field by passing the same JSON key again in `more` (encoding/json keeps the last). Add rows for the new value, the old value, and the field missing.
- **[convention]** When the owner gives a host a new neutral name, add it in four places: the neutral-name lists in `CLAUDE.md` and `.claude/rules/spec-conventions.md`, the real-name row in the untracked `docs/local/hosts.local.md`, and the public-repo memory note. Then add the host's private nickname and ssh alias to the leak-check grep. Ask for the name before a new host appears in any tracked file.
- **[correction]** When you quote a resource figure (free disk, Docker root, GPUs), say which host and which mount it came from, and measure it where the work will run. BFCL and SWE-bench run on blackswan-2, which has its own daemon (D93; ssh alias in `docs/local/`), not the dev host. Lines from `df` under `/var/lib/docker/overlay2/*/merged` only show this host's Docker filesystem.
- **[pattern]** To install automaticum on a fresh host: make the tree on a data disk, not the root fs that holds Docker's root (D95); `git clone` the repo and `git checkout` the exact HEAD commit as the install's `repo`; copy the dev host's binaries (they are glibc-2.28-baselined, so portable); rsync the SDK bundles (`data/sdk/`) and their archived packages (`archive/sdk-packages/`); then `automaticum sdk verify <build>` reproduces each offline at its pinned hash. Run the daemon as a systemd unit (`examples/systemd/automaticumd.service`): `Requires=docker.service`, `RequiresMountsFor=<data disk>`.
- **[env]** A fresh host must have every pinned image pulled before the checks that use them: `docker pull` the `node@sha256:` digests before `automaticum sdk verify` and `image build`, and the `debian@sha256:`/`node@sha256:` oracle images before `automaticum oracle verify`. List them all with `grep -rhoE '[a-z0-9./-]+@sha256:[0-9a-f]{64}' tasks images internal`. Run `automaticum task build custom/manic_miner` before verifying that task's oracle.
- **[gotcha]** Docker 29.1+ refuses Engine API versions below 1.44; the client used to pin `v1.41` (fine on the dev host's 29.8, which still accepts 1.24+). It now reads the engine's `MinAPIVersion` from the unversioned `/version` and speaks the newer of the two (bug-027). On a new host confirm the engine's range with `docker version --format '{{.Server.APIVersion}} {{.Server.MinAPIVersion}}'`.
- **[env]** Every `automaticum` subcommand that touches the store needs `AUTOMATICUM_CONFIG` set (or `--config`); without it even `run ls -json ... > file` writes `no configuration directory` into the output file and exits. Export it once per shell before a batch of commands.

- **[pattern]** To learn what the Cerebriline SDK really does, read the installed build under `<data_root>/sdk/<release>/node_modules/@cerebriline/`. `data_root` is in the config's `automaticum.toml`, and `automaticum sdk ls` lists the builds. Grep the `.d.ts` files in `core/dist`, `shared/dist` and `agents/dist` for types. For the logic, cut a window out of the minified bundle with `grep -o '.\{200\}<needle>.\{200\}' <pkg>/dist/index.js`. `grep` here is ugrep and rejects some patterns as too complex: `.{0,N}` with alternation, and large bounded classes such as `[^"]\{0,300\}` or `[^|]{0,60}` followed by an alternation. Use `grep -oE` with smaller bounds (about 260 or less) or split the search into two greps. Never guess SDK behaviour; confirm it there or on the stub.
- **[gotcha]** `.wolf/anatomy.md` lists files under `## <dir>/` sections and file names repeat across sections (`cell.go` is in both `internal/config/` and `internal/daemon/`; every `runner/sdk/<build>/` has the same three files). A global regex replace on a file name fails or hits the wrong entry. Edit by walking the lines tracking the current `## ` section, or insert before a unique `## <dir>/` anchor. The OpenWolf post-write hook already adds a stub entry for every new file — replace that line, don't add a second, then grep for duplicates.
- **[gotcha]** Before deciding the SDK "loses" state across sessions, check how the extension wires it. Core makes a fresh read-receipt registry per session unless `ClineCore.create` gets `capabilities.readReceipts` (`sdk.createReadReceipts()`); the runner passes one registry per run. `switch_to_act_mode` is in no SDK release before 4.100.253 — the extension adds it as an `extraTool` (`sdk.createTool`, `lifecycle.completesRun`), ported in `runner/plan.mjs`.
- **[gotcha]** The Caliber pre-commit hook rewrites `CALIBER_LEARNINGS.md` inside the commit, after the leak check ran, and that file is excluded from the check. After every commit run `git show HEAD --stat | grep -i caliber` and, if it changed, grep it with the same private-string pattern. A hit only on the bullet that quotes the grep pattern itself is a false positive; any other hit needs an amend before the next push.
- **[pattern]** For a corpus analysis, dump `run ls -json` to a file on persistent disk, then `run show -json <id>` per id. Each record has `model`, `verdict`, `verdict_reason`, `campaign`, `wall_ms` and `findings[]` with a `detector` name; legacy-imported runs carry `campaign = "legacy-native"`. Imported run ids are not all date-prefixed: some begin with a lane-name prefix, so glob `*.json`, never `2*.json`, or a whole lane's runs silently drop out of the counts.
- **[gotcha]** The CLI uses Go's `flag` package, so flags must come before positional arguments. `automaticum run invalidate <run> "<reason>"` prints only usage; use `automaticum run invalidate --reason "<why>" <run>`. - **[pattern]** To provision a new SDK release `<v>`: the host has no Node, so list what is published with `docker run --rm node@sha256:<digest> npm view @cerebriline/sdk versions --json` (digest from `images/base/Dockerfile`). Copy `runner/sdk/<old>/package.json` to `runner/sdk/<v>/` with the version replaced, write `sdk.toml` with `version` and `source = "registry"`, make the lockfile in the same image with `npm install --package-lock-only --ignore-scripts --no-audit --no-fund` (mount the build dir as `/w`), then `./bin/automaticum sdk add <v>` with `AUTOMATICUM_CONFIG` set. The first install writes `bundle_sha256` into `sdk.toml`; commit it, since no run uses an unpinned build. Then add `arms/stub-sdk-<v>.toml` (`extends = "stub"`) and `arms/stub-plan-sdk-<v>.toml` (`extends = "stub-plan"`), each with `[harness] sdk_release = "<v>"`, and update the `sdk/` and `arms/` lines of `CLAUDE.md` and the matching `.wolf/anatomy.md` sections.
- **[gotcha]** After generating an SDK lockfile, check the zod pins before `sdk add` (bug-009: zod 4.6.7 breaks the SDK's tool-schema builder with `Cannot read properties of undefined (reading 'push')`). Read `packages` in the lockfile: the top-level `node_modules/zod` must be `4.4.3` and `@cerebriline/core`, `llms` and `shared` must depend on exactly `4.4.3`. A newer zod nested under another package (for example a `@sap-ai-sdk` path) is harmless. If the top-level one drifts, add npm `overrides` in the build's `package.json` and regenerate.
- **[pattern]** To prove a new SDK build on the stub, run every demo task with the stub script it needs (the scripts live in the untracked `<work>/stub/`): `demo/answer` with `fix-answer.json`, `demo/scripted` with `fix-scripted.json`, `demo/plan` and `demo/plan-switch` on the plan arm with `fix-plan.json` and `fix-plan-tool.json`, `demo/cancel` and `demo/fork` with `fix-answer-slow.json`. All six must end `PASS`. In a script, wait for the stub with `ss -ltnH 'sport = :7412'` and poll `run ls -limit 5 | grep "^$id" | grep finished`; foreground `sleep` is blocked in this harness, so pause with `timeout <s> tail -f /dev/null`.
- **[gotcha]** The lane image copies runner files one by one, so a new `runner/*.mjs` must be added to the `COPY runner/...` line in `images/base/Dockerfile`. `Protocol` in `internal/run/protocol.go` must match `PROTOCOL` in `runner/runner.mjs`, and `runner/PROTOCOL.md` must be updated with it. The host has no Node: run the runner's unit tests in the pinned image, `docker run --rm --network none -v $PWD/runner:/runner:ro -w /runner node@sha256:<digest from images/base/Dockerfile> sh -c 'node --test test/*.test.mjs'`. After any runner change run `./bin/automaticum image build` before an end-to-end run; check with `docker run --rm --entrypoint ls automaticum-lane:base /opt/automaticum/runner`.
- **[gotcha]** `go test -race` needs cgo, so `CGO_ENABLED=0 go test -race` fails with `-race requires cgo`. Run the `-race` packages with plain `go test -race ...` on the host, or just `make test`. `CGO_ENABLED=0 go vet ./internal/...` fails too: `internal/store/duck` pulls duckdb bindings whose build constraints exclude every file without cgo. Vet only the pure-Go packages you touched, e.g. `CGO_ENABLED=0 go vet ./internal/run/ ./internal/config/ ./internal/ingest/ ./internal/docker/ ./cmd/automaticum/`.
- **[gotcha]** `automaticum run tail <id>` works only on a run in flight and never ends; on a finished run it prints only a hint. Capture a live tail with a bound to persistent disk: `timeout 8 ./bin/automaticum run tail <id> > <work>/tail.jsonl; true`. Read a finished run with `timeout 60 ./bin/automaticum logs <id>`, its wire with `logs <id> --wire`. Wire lines are flat (`request_body`, `response_body` are JSON strings); some have no body or an `error` field, so read with `d.get(...)`. In `logs`, an SDK event is nested as `event.payload.event` (the agent's `type`, `noticeType`, `metadata` live there). `run ls` takes `-limit N` (default 30), not `-n`.
- **[pattern]** When you add a required arm setting (030 §5.1: every guard setting must be stated), make it a pointer with `omitempty` and drop its neutral value in `Arm.Resolved()`, so arms resolved before the field existed keep their id. Prove it: compare `run ls -json` `arm_id` prefixes of past runs with `arm show <arm>` ids. The old `bin/automaticum` refuses the edited `arms/base.toml` with `unknown fields: guards.<new>`, so compare with `CGO_ENABLED=0 go run ./cmd/automaticum arm show <arm>` until you rebuild.
- **[convention]** When you add a metric in `internal/ingest` (`m("name", ...)` in `analyse.go`), bump `AnalysisVersion` in `analyse.go` and document it in 070 §2. If the metric says nothing at zero (a count of something most runs never have), add its prefix to `quietWhenZero` in `internal/daemon/compare.go` and to the zero filter in `cmd/automaticum/client_cmds.go` (`run show`), and extend `TestDropQuietUser`. Runner notes become metrics through `eventLine` fields in `events.go` (`case l.K == "runner"`), not through the SDK event.
- **[gotcha]** In SDK 4.100.258 only the reasoning-loop guard (`metadata.kind: "reasoning_loop"`, phase `cut`, `aborted` or `removed`) and the tool-intent guard (`tool_intent_overrun`, `cut`) announce a trip as a `notice` event. Tool-call loop detection emits nothing: a soft verdict is appended to the tool result text, a hard one goes to the mistake tracker and shows only as the end (`mistake_limit`). The no-tool-call nudge is `kind: "nudge"`, the runtime's, not a guard. Match guards on `metadata.kind`/`phase`, never on message sentences. Enumerate the kinds with `grep -oE 'metadata:\{kind:"[a-z_]+"(,reason:"[a-z_]+")?(,phase:[^,}]+)?' <pkg>/dist/index.js | sort | uniq -c`.
