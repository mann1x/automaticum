- **[convention]** Bumping the runner protocol touches more than the two constants: the `(currently N)` number in `.claude/rules/runner-protocol.md`, the `# The runner: protocol N` title and the `## What protocol N does not do` heading in `runner/PROTOCOL.md`, the dated `**Protocol N (date):**` paragraph inserted before `## In`, and a `runner/test/session.test.mjs` case for the new job field. Then `grep -rn 'protocol 5\|PROTOCOL = 5' --include=*.go --include=*.mjs --include=*.json internal runner cmd`; comments in `internal/run/protocol.go` that cite older protocol numbers are history and stay.
- **[pattern]** To learn what the Cerebriline SDK really does, read the installed build under `<data_root>/sdk/<release>/node_modules/@cerebriline/` on the host that runs the lane (the lane image holds only the runner under `/opt/automaticum`, not the SDK). `data_root` is in the config's `automaticum.toml`, and `automaticum sdk ls` lists the builds. Grep the `.d.ts` files in `core/dist`, `shared/dist` and `agents/dist` for types (`shared/dist/agents/types.d.ts` has the event shapes, `core/dist/runtime/safety/` the guards). For the logic read `core/dist/index.js` or `agents/dist/index.js`; `core/dist/hub/daemon/entry.js` repeats core's code and is what `grep -rl` finds first. The provider layer (the provider list as `id:"<name>",name:`, the effort-to-budget table, the reasoning-history scope and template probe per provider) is in `llms/dist/index.js`; the session-config schema (zod `V.object({...})` with the camelCase field names) and where it is forwarded to the provider config are in `core/dist/index.js`. `grep` here is ugrep and rejects some patterns as too complex: `.{0,N}` with alternation, large bounded classes, and `-o '.\{300\}needle.\{500\}'` returns nothing; `-o "[^;]\{0,250\}needle[^;]\{0,250\}"` on a minified bundle runs past two minutes. For a window around a needle use `python3 -c` with `re.finditer(re.escape(needle), s)` and print `s[m.start()-500:m.start()+700]`. Never guess SDK behaviour; confirm it there or on the stub.
- **[correction]** An endpoint that is an opencoti (or xollama) server gets the SDK provider of that name in `model.provider`, never `openai-compatible` (owner: "why openai-compatible? cerebriline has opencoti provider"). The providers differ in what goes back to the server: for `opencoti`, `ollama`, `xollama` and `cerebras` the SDK's reasoning-history default is `none`, for `openai-compatible` it is `all` (the model's reasoning is re-sent in every request), so the provider changes what the model sees and whether it loops; since D103 the arm's `thinking.reasoning_history` overrides that default. `arm validate` does not check `model.provider` against the SDK's list, so read the provider list in `llms/dist/index.js` yourself before writing an arm. Record such a change as a new D row in `docs/specs/decisions.md` with the revision bumped, and say in the arm's comment that the earlier runs are another arm.

The caliber pre-commit hook then runs `caliber refresh` and may rotate older learnings into the learnings archive, so a bullet that vanished from `CALIBER_LEARNINGS.md` is archived, not lost. Caliber only analyses once it has enough events ("10/25 events recorded — need more before analysis" is normal on a small commit).
