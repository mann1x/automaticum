# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[pattern]** Go edited by a python heredoc is not formatted, and neither `go build` nor `go vet` complains: a new field beside aligned struct fields leaves the file unformatted. Run `gofmt -l internal cmd` after such edits and `gofmt -w` what it lists. When a scripted edit uses a new package, add the import with `grep -q '^\t\"path\"' f.go || sed -i '0,/^import (/s//import (\n\t\"path\"/' f.go`, then let `gofmt -w` put it in order.
- **[gotcha]** The OpenWolf post-write hook adds an anatomy entry and a memory row only for files made with the Write tool, and its description is a stub such as `Struct: written`. Files made with a Bash heredoc (`cat > x_test.go`) get no entry at all. After a batch of new files, run `grep -n '<file>' .wolf/anatomy.md` for each and add the missing ones. Where there is a stub, replace it with the real description: adding a line beside it leaves the file listed twice.
- **[convention]** A mutating route takes its dry run as the query parameter `?dry_run=1`, not a body field: the handler checks `dryRun(r)`. The CLI uses `addMutation(fs)`, `m.on(c, path)` and `m.dryNote()`, which also bring `--idempotency-key`. Read these helpers before adding a new mutating command.
- **[gotcha]** A new map in the daemon's `control` struct must be initialised both in the default literal and in the loader's nil checks. A `control.json` written by an older daemon has no such key, so a map set up in only one place panics with an assignment to a nil map after a restart.
- **[gotcha]** `go build ./...` from the repo root always reports `no required module provides package github.com/northwind/...`. Those are the task checkers under `tasks/train-ml/*/checker`, which import their task's own packages, and the noise can hide a real error. Build the packages you changed instead (`go build ./internal/daemon/`, `CGO_ENABLED=0 go vet ./cmd/automaticum`). A bare `go build ./cmd/automaticum` writes an `automaticum` ELF binary at the repo root, which `git add -A` then stages. Prefer `go vet` or `go build -o /dev/null`, and check `git status --short` for a stray `A  automaticum` before committing.
- **[pattern]** Check for private strings before a commit of this public repo. First check `test -n "$P"`, since an empty pattern matches every line. Then run `git ls-files -z | grep -zv -e CALIBER_LEARNINGS.md -e package-lock.json -e '^tasks/train-sh/' | xargs -0 grep -IlniE "$P"` and `git diff --cached | grep '^+' | grep -niE "$P"`. Clean is an empty output: `xargs` exits 123 and `grep` exits 1 when nothing matches, so read the printed list and don't treat the status as a failure.
- **[pattern]** Thresholds ported from the SDK hold per release, not for the SDK as a whole: the reasoning-loop guard changed at 4.100.258 while the code still cited 4.100.250/251. Before trusting or extending a port, loop over every pinned build's `node_modules/@cerebriline/agents/dist/index.js` (or `core/dist/index.js`). Regex out the default config object (e.g. `=\{minChars:4000,window:60[^}]*\}`) and print a sha1 of the class body. Equal hashes mean the same code, and the first build that differs is where to read. When a replay does not confirm a guard trip, read the SDK's notice metadata for that turn (`kind`, `period`, `cycles`, `sample`) before assuming the detector is wrong: it names the rule the port is missing.
- **[pattern]** Fixtures do not show what a real stream does. To try analysis or a view on a real run, add a temporary env-gated test such as `internal/ingest/zz_real_test.go` or `cmd/automaticum/zz_tmp_test.go`. It skips when `REAL_EVENTS` is empty, reads the events (`ReadEvents`, or `ingest.Events{...}.Read`), runs `Analyse(&store.Run{ID: "x", Harness: os.Getenv("REAL_SDK")}, ev, nil)` or the view's function, and prints the result. Run it with `-count=1 -v`, compare under two `REAL_SDK` values when the rules depend on the release, and `rm` it in the same command line. The event stream stays in a scratch directory, outside the repo.
- **[gotcha]** Detector options reach more than ingest. `detect.Block` is called from `internal/ingest` (`DetectOptions`, `blockOptions`), `handleDetect` in `internal/daemon/api.go`, `automaticum detect` in `cmd/automaticum/client_cmds.go` and `export.Spans`. For any option that depends on the run, run `grep -rn "detect.Options{" --include=*.go internal cmd | grep -v _test` and pass it at every site, or the views disagree with the stored findings.
- **[gotcha]** `TestRunImported` asserts an exact `len(m.findings)`, so a new detector that fires on its stream fails it even when the detector is right. `store.Finding` prints `Evidence` as decimal bytes, which fills the failure output: pull out `Detector`, `Turn` and `Count` with a small regex over the output instead of reading it. - **[gotcha]** A stored run's event stream (`logs <run> --events -json`, or a scratch `.jsonl`) wraps every SDK event twice. Lines look like `{"t":...,"k":"event","event":{"type":"agent_event","payload":{"event":{...}}}}`, mixed with `"k":"runner"` notes. Counting `e["type"]` or `e["event"]["type"]` therefore only gives `agent_event` and `chunk`. Read `e["event"]["payload"]["event"]`: the notice kind is in `.metadata.kind` and the phase in `.metadata.phase`. The runner's own notes (e.g. `guard_trip`) arrive as separate `k:runner` lines right after the SDK's notice of the same trip, so a timeline or count that reads both shows each trip twice unless it folds them.

- **[gotcha]** The daemon has no notification hook for tests: `d.notified` is a `map[string]bool` of waiting runs, not a callback. To assert on a notification, set `g.d.Log = slog.New(slog.NewTextHandler(&logs, nil))` with the `lockedBuffer` from `mutate_test.go` and look for `msg="<kind> <status>"`, since every notification is logged. The other way is `Notify.Command` writing to a file, as in `TestNotifyCommand`. A new notification kind must also go into `config.NotifyEvents`, or `[notify] events` refuses it. Then update the comment in `examples/config/automaticum.toml` and the kind list in 050 §2.
- **[pattern]** A new daemon setting or background job touches six places. (1) A field in `config.Daemon` (`internal/config/local.go`) with its validation. (2) A refusal case in the `cases` table of `config_test.go`. (3) A commented line in `examples/config/automaticum.toml`. (4) The `automaticum.toml` line in 030. (5) For a loop: start it in `Serve` beside `go d.heartbeatLoop(canary)` and give the `Daemon` an `<X>Every time.Duration` field, so the test can tick in milliseconds. (6) For a new dependency: wire it in `cmd/automaticumd/main.go`, which `make test` does not compile.
- **[pattern]** The rows of the spec-vs-code audit (`docs/audit/2026-11-01-spec-vs-code.md`) marked NOT BUILT or PARTIAL were partly grep guesses. A re-check found 17 already built and 20 with wrong evidence. Before building an audit gap, verify it against the code, or hand a read-only re-check to a subagent. To update rows, use a script that splits each row on unescaped `|`. It asserts the first cell starts with the expected spec § for that line number, then sets the status and evidence cells. Line numbers drift, and the assert catches a wrong row.
