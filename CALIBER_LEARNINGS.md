# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** `go test -race` needs cgo, so `CGO_ENABLED=0 go test -race` fails with `-race requires cgo`. Run the `-race` packages (for example `internal/daemon`) with plain `go test -race ...` on the host. Use `CGO_ENABLED=0` only for `go vet` and for `cmd/automaticum`, or just run `make test`, which sets each one correctly.
- **[pattern]** When you add a field to the runner's last line (`End` in `internal/run/protocol.go`) that a harness rule depends on, make it a pointer (`*int`), so that `nil` means "an older runner did not report it" and the old rule still holds for those runs. Document the field in `runner/PROTOCOL.md`. In `internal/run/run_test.go` you can override an `endLine` field by passing the same key again in its `more` argument, because `encoding/json` keeps the last of a repeated key. Add a test row for the new value, for the old value, and for the field being missing.
- **[convention]** When the owner gives a host a new neutral name, add it in four places: the neutral-name lists in `CLAUDE.md` and `.claude/rules/spec-conventions.md`, the real-name row in the untracked `docs/local/hosts.local.md`, and the public-repo memory note. Then add the host's private nickname and ssh alias to the leak-check grep above. Ask for the name before a new host appears in any tracked file.
- **[correction]** When you quote a resource figure (free disk, Docker root, GPUs), say which host and which mount it came from, and measure it on the host where the work will run. BFCL and SWE-bench are tested on blackswan-2, which has its own daemon (D93; its ssh alias is in `docs/local/`), not on the dev host. Lines from `df` under `/var/lib/docker/overlay2/*/merged` only show the filesystem that holds this host's Docker root. The owner asked "122gb free where?" when a dev-host figure was offered as the limit for SWE-bench images.
- **[gotcha]** An endpoint `kind` is not always an SDK provider id. `llamacpp` is an OpenAI-compatible llama-server, and the SDK has no provider of that name. Passing it through gives the agent error `Unknown or disabled provider "llamacpp"` before the first chat request. Since D89 such a run is `ABORTED` (before that it was `FAIL`, cell exit 10). Always map kinds with `config.ProviderFor(kind)`. When you add an endpoint kind, grep the SDK's `@cerebriline/llms/dist/index.js` for the provider id first. A mode C cell with no chat request on the wire is a harness bug, so check `logs <id>` for an `"type":"error"` agent event.
- **[pattern]** To learn what the Cerebriline SDK really does, read the installed build under `<data_root>/sdk/<release>/node_modules/@cerebriline/`. `data_root` is in the config's `automaticum.toml`, and `automaticum sdk ls` lists the builds. Grep the `.d.ts` files in `core/dist`, `shared/dist` and `agents/dist` for types. For the logic, cut a window out of the minified bundle with `grep -o '.\{200\}<needle>.\{200\}' <pkg>/dist/index.js`. `grep` here is ugrep and rejects some patterns as too complex: `.{0,N}` with alternation, and large bounded classes such as `[^"]\{0,300\}`. Use `grep -oE` with smaller bounds (about 260 or less). Never guess SDK behaviour; confirm it there or on the stub.
- **[correction]** When the runner needs behaviour the Cline/Cerebriline extension adds on top of the SDK (e.g. `switch_to_act_mode`, read receipts, a self-continuing mode switch), port it from the extension source; don't design your own. Read the local Cline checkout (path in `docs/local/`, untracked) without checking anything out: `git grep -n <symbol> v4.100.251 -- apps/vscode/src` and `git show v4.100.25x:<path>`. Copy tool descriptions and prompts word for word, confirm the code is identical in every pinned SDK release, and name the source file and tag in a comment and in the 040 spec.
- **[convention]** Metrics that are zero in most runs are hidden where zero (D88) by a prefix check in two places: `quietWhenZero` in `internal/daemon/compare.go` for `compare`, and the `run show` filter in `cmd/automaticum/client_cmds.go`. Prefixes today are `user.` and `mode_switches.`. Add a new family's prefix in both places.
- **[gotcha]** `.wolf/anatomy.md` lists files under `## <dir>/` sections and file names repeat across sections (`cell.go` is in both `internal/config/` and `internal/daemon/`). A global regex replace on a file name fails or hits the wrong entry. Edit by walking the lines tracking the current `## ` section, or insert before a unique `## <dir>/` anchor. The OpenWolf post-write hook already adds a stub entry for every new file — replace that line, don't add a second, then grep for duplicates.
- **[fix]** Run the runner's Node tests in the pinned image with a shell glob: `docker run --rm --network none -v $PWD/runner:/runner:ro -w /runner node@sha256:<digest> sh -c 'node --test test/*.test.mjs'`. Plain `node --test test/` fails on Node 22 with `MODULE_NOT_FOUND`. Take the digest from `grep -o 'node@sha256:[0-9a-f]*' images/base/Dockerfile`, never from notes.
- **[gotcha]** The lane image copies runner files one by one, so a new `runner/*.mjs` must be added to the `COPY runner/...` line in `images/base/Dockerfile`. `Protocol` in `internal/run/protocol.go` must match `PROTOCOL` in `runner/runner.mjs`, and `runner/PROTOCOL.md` must be updated with it. After any runner change run `./bin/automaticum image build` before an end-to-end run; check with `docker run --rm --entrypoint ls automaticum-lane:base /opt/automaticum/runner`.
- **[pattern]** To deploy a rebuilt daemon: `make build SPIKE_ROOT=<dir>`. Get the old pid with `ss -ltnpH 'sport = :7411' | grep -o 'pid=[0-9]*'`, `kill -TERM` it, wait until `kill -0` fails, restart with `nohup ./bin/automaticumd --config $AUTOMATICUM_CONFIG >> <work>/automaticumd.log 2>&1 &`, then poll `curl -sf http://127.0.0.1:7411/v1/status`. Changes under `internal/config` or `internal/daemon` take effect only after this redeploy, because the daemon resolves the arms.
- **[gotcha]** SDK session facts (4.100.25x, seen on the stub): with `interactive: false` the session is disposed when it ends, so a later `core.send()` fails with `session not found`. Use `interactive: true` only when the runner must speak again, and `core.stop()` at the end. The SDK numbers `iteration` from 1 again in each run of a session, so count turns yourself from the lead agent's `iteration_start` events. A `steer` send aborts the request in flight, shown on the wire as an `AbortError` request with no finish reason.
- **[gotcha]** A `python3` replace script with `assert old in s` often fails: on gofmt-aligned struct fields, on code whose tab depth you guessed, and on spec paragraphs whose line breaks you guessed. Look at the exact bytes first with `grep -n -A1 '<phrase>' <file> | cat -A`, or `sed -n <a>,<b>p` for a paragraph; copy the whitespace and wraps, or match with a regex. Run `gofmt -w` after inserting fields.
- **[gotcha]** A stub script plays its turns in order, whatever the SDK asks. The arm's no-tool-call nudge answers every text-only reply once, so a run ends only on the second text-only reply and the script must give one turn to the nudge. The read-before-edit guard refuses an `editor` call until the file was read with `read_files` (a denied read counts as not read). If a run ends `FAIL` with `exit 0`, grep the logs for `"output"` on `editor` before suspecting the harness.
- **[gotcha]** Before deciding the SDK "loses" state across sessions, check how the extension wires it. Core makes a fresh read-receipt registry per session unless `ClineCore.create` gets `capabilities.readReceipts` (`sdk.createReadReceipts()`); the runner passes one registry per run. `switch_to_act_mode` is in no SDK release — the extension adds it as an `extraTool` (`sdk.createTool`, `lifecycle.completesRun`), ported in `runner/plan.mjs`.
- **[gotcha]** The SDK's checkpoints are git commits in the session's cwd; there is no shadow repository, and `checkpoint.enabled` must be true on the session config. Since D87 every lane workspace is a git repo by default, seed as one commit. Read the setting with `Workspace.GitRepo()`, not the `*bool` field. A task can opt out with `[workspace] git = false`, but then a checkpoint-restoring script fails to load. `checkpointRunCount` counts user runs (start prompt = 1, each landed `send` +1), not turns.
- **[gotcha]** `go test -race` needs cgo, so `CGO_ENABLED=0 go test -race` fails with `-race requires cgo`. Run the `-race` packages with plain `go test -race ...` on the host. Use `CGO_ENABLED=0` only for `go vet` and for `cmd/automaticum`, or just run `make test`, which sets each correctly.
- **[pattern]** `.wolf/cerebrum.md`, `.wolf/memory.md`, `.wolf/anatomy.md`, `.wolf/buglog.json` and `.wolf/suggestions.json` are tracked in this public repo, so a host path or name you write into them leaks. Before every commit, `git add -A . ':!.wolf/cron-state.json'` then `git ls-files | grep -v -e CALIBER_LEARNINGS.md -e package-lock.json | xargs grep -IlniE '<private names>|/srv/|/shared/|192\.168|C:/Users|\bbs2\b|/mnt/sdc'`. It must print nothing. Gate the commit on this check with `if grep ...; then stop; else commit; fi` — never chain it with `;`, which pushes a hit anyway.
- **[gotcha]** `automaticum run tail <id>` works only on a run in flight and never ends; on a finished run it prints only a hint. Capture a live tail with a bound to persistent disk: `timeout 8 ./bin/automaticum run tail <id> > <work>/tail.jsonl; true`. Read a finished run with `timeout 60 ./bin/automaticum logs <id>`, its wire with `logs <id> --wire`. Wire lines are flat (`request_body`, `response_body` are JSON strings); some have no body or an `error` field, so read with `d.get(...)`. `run ls` takes `-limit N` (default 30), not `-n`.
- **[pattern]** To test end to end without a GPU, use the stub model server. The `stub` endpoint points at the Docker bridge gateway. Run `automaticum stub serve --script <work>/stub/<file>.json --listen 172.17.0.1:7412`, then `automaticum cell run --suite demo:<task> --arm stub --out <dir> --idempotency-key <k> --poll 2s`. It also speaks llama-server's API. For mode C add `--endpoint-url .../v1 --served-model stub:latest --endpoint-kind <kind> --caller-values <file> --basis-facts <file>`; the facts must agree with `/props` or every run is `SKIPPED` by gate `basis_facts`. Use a new key each attempt and stop the stub afterwards.

- **[gotcha]** The CLI uses Go's `flag` package, so flags must come before positional arguments. `automaticum run invalidate <run> "<reason>"` prints only usage; use `automaticum run invalidate --reason "<why>" <run>`. Likewise `automaticum run start -arm stub demo/answer` fails with usage — the task is a flag: `run start -arm stub -task demo/answer`.

- **[pattern]** To install automaticum on a fresh host: make the tree on a data disk, not the root fs that holds Docker's root (D95); `git clone` the repo and `git checkout` the exact HEAD commit as the install's `repo`; copy the dev host's binaries (they are glibc-2.28-baselined, so portable); rsync the SDK bundles (`data/sdk/`) and their archived packages (`archive/sdk-packages/`); then `automaticum sdk verify <build>` reproduces each offline at its pinned hash. Run the daemon as a systemd unit (`examples/systemd/automaticumd.service`): `Requires=docker.service`, `RequiresMountsFor=<data disk>`.
- **[env]** A fresh host must have every pinned image pulled before the checks that use them: `docker pull` the `node@sha256:` digests before `automaticum sdk verify` and `image build`, and the `debian@sha256:`/`node@sha256:` oracle images before `automaticum oracle verify`. List them all with `grep -rhoE '[a-z0-9./-]+@sha256:[0-9a-f]{64}' tasks images internal`. Run `automaticum task build custom/manic_miner` before verifying that task's oracle.
- **[gotcha]** Docker 29.1+ refuses Engine API versions below 1.44; the client used to pin `v1.41` (fine on the dev host's 29.8, which still accepts 1.24+). It now reads the engine's `MinAPIVersion` from the unversioned `/version` and speaks the newer of the two (bug-027). On a new host confirm the engine's range with `docker version --format '{{.Server.APIVersion}} {{.Server.MinAPIVersion}}'`.
- **[env]** Every `automaticum` subcommand that touches the store needs `AUTOMATICUM_CONFIG` set (or `--config`); without it even `run ls -json ... > file` writes `no configuration directory` into the output file and exits. Export it once per shell before a batch of commands.
