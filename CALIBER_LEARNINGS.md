- **[gotcha]** Detector options reach more than ingest. `detect.Block` is called from `internal/ingest` (`DetectOptions`, `blockOptions`), the daemon's detect handlers, `automaticum detect` and `export.Spans`. For any option that depends on the run, run `grep -rn "detect.Options{" --include=*.go internal cmd | grep -v _test` and pass the option at every site. Otherwise the views disagree with the stored findings. The same applies to the daemon's `compareView`: `compare`, `basis show` and the cell view all call it (`grep -n 'compareView(' internal/daemon/*.go`), so a new parameter must be passed at each call.

- **[pattern]** Never write "the SDK emits no event for X" based on one run's stream. That claim once went into 070 and the audit from a run with the change protocol off, while the bundle does have `atomic_transaction`, `atomic_empty_attempt` and `atomic_plan` notices. First search `node_modules/@cerebriline/core/dist/index.js` for `kind:"<prefix>[a-z_]*"` and its `dispatchAgentEvent` calls. When porting an SDK observer, note that its verdicts land only where the SDK calls `inspect` (for the struggle detector, `content_end` and `iteration_end`). A test's expected firing turn must therefore sit at such an event, not at the notice that changed the state.
- **[gotcha]** A stored run's event stream (`logs <run> --events -json`, or a scratch `.jsonl`) wraps every SDK event twice. Lines look like `{"t":...,"k":"event","event":{"type":"agent_event","payload":{"event":{...}}}}`, mixed with `"k":"runner"` notes. Counting `e["type"]` or `e["event"]["type"]` therefore only gives `agent_event` and `chunk`. Read `e["event"]["payload"]["event"]`: the notice kind is in `.metadata.kind` and the phase in `.metadata.phase`. The runner's own notes (e.g. `guard_trip`) arrive as separate `k:runner` lines right after the SDK's notice of the same trip. A timeline or count that reads both shows each trip twice unless it merges them.
- **[gotcha]** `config.LoadArm` returns the arm already merged with its parents, so `Extends` on the result is empty. Code that reads `arm.Extends` to find the parent always sees "no parent" (`TestArmBaseline` failed on this). Use `config.ArmParent(dir, name)`, which follows the files' `extends` chain. - **[gotcha]** `config.LoadLocal` refuses a directory without a lane and an endpoint (`no lanes: lanes/*.toml is empty`). - **[gotcha]** Before adding an exported helper to a package, run `grep -n 'func <Name>' internal/<pkg>/*.go`. For example, `internal/ingest` already has `ErrorClass` (the 070 §2 tool-error class, stored on `store.ToolCall.ErrorClass`). A second one fails the build with a redeclaration and duplicates a definition. Likewise, a read-only rerun of the whole analysis is `ingest.Load` + `ingest.Derive` (`ingest.Run` is those two plus the write). Reuse them instead of reading a run's blobs again.
- **[gotcha]** A python heredoc that writes Go backtick strings removes one level of backslashes. In a non-raw `'''…'''` python string, `\\\\n` lands in the Go file as `\\n`, a literal backslash-backslash-n, and the test input silently changes. For a Go raw string holding JSON's `\n`, write `\\n` in python, or use `r'''…'''` and write it exactly as in Go. Print the edited line with `sed -n <N>p` before running the tests.

- **[pattern]** A new daemon setting or background job touches six places:
  1. a field in `config.Daemon` (`internal/config/local.go`) with its validation;
  2. a refusal case in the `cases` table of `config_test.go`;
  3. a commented line in `examples/config/automaticum.toml`;

  6. for a new dependency: wire it in `cmd/automaticumd/main.go`, which `make test` does not compile.
- **[pattern]** The rows of the spec-vs-code audit (`docs/audit/2026-11-01-spec-vs-code.md`) marked NOT BUILT or PARTIAL were partly grep guesses: a re-check found 17 already built and 20 with wrong evidence. Before building an audit gap, verify it against the code, or hand a read-only re-check to a subagent. To update rows, use a script that:
  - splits each row on unescaped `|`;
  - asserts that the first cell starts with the expected spec § for that line number;
  - then sets the status and evidence cells.
  Line numbers drift, and the assert catches a wrong row.
- **[convention]** `.wolf/cron-state.json` and `.wolf/suggestions.json` change on their own all the time and are not committed with the work. Stage with `git add -A -- . ':!.wolf/cron-state.json' ':!.wolf/suggestions.json'` and not with a bare `git add -A`. These files are also why `make build` stamps `<sha>-dirty`. The built code still equals the commit.
- **[pattern]** Fixtures do not show what a real stream does. To try analysis, a detector or a view on a real run, add a temporary env-gated test such as `internal/ingest/zz_tmp_test.go` or `cmd/automaticum/zz_tmp_test.go`. The test:
  - skips when `REAL_EVENTS` is empty;
  - reads the events (`ReadEvents`);
  - runs `Analyse(&store.Run{ID: "x", Harness: os.Getenv("REAL_SDK")}, ev, nil)`, the detector or the view's function, and prints the result.
  Run it with `-count=1 -v`: without `-v` a passing test prints nothing. When the rules depend on the release, compare under two `REAL_SDK` values. Delete it with `rm` on the same command line. Fetch the stream read-only from the lane host with `automaticum logs <run> --events -json`. To turn a client's run into a positive control, have the temporary test write `ev.Calls` as JSON into `internal/detect/testdata/` (`json.Unmarshal` back into `[]detect.Call` matches lowercase keys), and check that file for private strings. To check a detector against a client's own scan, run both on the same runs and compare the counts.
- **[pattern]** When a client reports a finding missing from a real run, do three things on the lane host before reading code:
  - run `automaticum detect <detector> <run> --json --firings`, which prints the firings now beside the `stored` count;
  - run `automaticum run show <run>`, which lists the metrics and findings;
  - if the metric is there (e.g. `cap.hits 1`) and the finding is missing even from the fresh `detect`, look for the bug in how the findings are put together, not in the detector.
  The request-level wire comes from `automaticum logs <run> --wire -json`, one JSON line per request with `response_body` as the raw SSE text. Feed it to `ReadWire` and the function under test (e.g. `CapHits`) in a temporary env-gated zz test.
- **[env]** One run's capture can exceed 100 MB. A 30-minute run gave an event stream of 350,000 lines and 124 MB, and one runaway request in a wire capture was a single 34 MB line. The session scratchpad is under `/tmp`, which is tmpfs on this host. Download streams and wire captures to a scratch directory on persistent disk outside the repo, never to `/tmp`.
- **[gotcha]** In `ingest.Analyse`, always add to `res.Findings` with `append`, never assign to it. A single `res.Findings = wireFindings(...)` in the branch for a run with an arm on record (every real run) threw away `cap_hit`, `guard_trip` and `control_markers` for many analysis versions. Their metrics survived, so nobody noticed. Run `grep -n 'res.Findings = [^a]' internal/ingest/*.go` after touching `Analyse`. A test that checks findings from `Analyse` must give the run an arm (`Arm: json.RawMessage(`{"name":"a"}`)`) and assert that the findings of the earlier detectors are still there.
- **[pattern]** Prove that a regression test catches the bug by setting aside only the fixed file and keeping the test: `git stash -q -- <fixed file>; go test -run <Test> -count=1 ./<pkg>; git stash pop -q`. The test must FAIL without the fix and pass with it. Say so in the commit message.
- **[gotcha]** `.claude/rules/runner-protocol.md` states the current `AnalysisVersion` as `(now N)`. When you bump it in `internal/ingest/analyse.go`:
  - update that rule with `sed -i 's/(now N)/(now N+1)/'`;
  - add the dated "From analysis version N" note in 070 §2 naming the new metrics.
  Stored runs keep their old metrics until `automaticum reanalyse` (or `automaticum detect --record`) runs on the lane host after the deploy.
- **[gotcha]** Daemon tests whose background loop ticks in milliseconds (`<X>Every`) run under `-race` in `make test`. Read a fake's state only through accessors that take its mutex (`passes()`, `firstAge()`), never directly as `fa.ages[0]`. Such a race can pass a single `-run` and still fail the full suite (`TestArchiveLoop` did). Confirm a fix with `go test -race -count=20 -run <Test> ./internal/daemon/`.
- **[env]** A full `make test` takes close to 5 minutes, nearly all of it `internal/legacyimport` under `-race`. Pass a Bash timeout of 600000 ms and run it under `claude-hooks-res run <host>:shared -r "<why>" -- make test`. While iterating:
  - use `go test -race -count=1 -run <Test> ./internal/daemon/`;
  - use `CGO_ENABLED=0 go test` for `cmd/automaticum`.
  `make test` does not compile `cmd/automaticumd`, so after changing the daemon's wiring there run `go vet ./cmd/automaticumd/` (cgo, slow: timeout 300000 ms). When you pipe the output through `grep -v "^ok\|cached"`, read the result from `echo rc=${PIPESTATUS[0]}`, since the pipe's own exit status is grep's.
- **[gotcha]** A new detector in `internal/detect` reports nothing until it is in the `available` list in `controls.go`. Ingest checks `detect.Available(name)` and skips the detector without an error or a metric. A new detector, or a widened rule, also needs:
  - a `SelfTest` control in `controls.go`: a control that fails takes down every detector it names;
  - a bump of `detect.Version` (`const Version` in `detect.go`) and a "library version N" note in 070;
  - an entry in the detectors map in `internal/ingest/analyse.go`;
  - an entry in `mainMetrics` in `cmd/automaticum/compare_cmds.go`, if its metric is a headline.
- **[pattern]** In daemon tests, give a stored run an event stream with `g.d.Blobs = memBlobs{"h": stream}` plus `store.BlobRef{RunID: id, Kind: "events", Hash: blob.Hash("h")}` appended to `g.state.refs`. The field is `blob.Hash`, not string, so import `internal/store/blob`. Create the run itself with `putRun`. A run in flight needs two things:
  - `g.d.flights = map[string]*flight{"lane-1": {runID: ..., started: ..., lines: ...}}`, set under `g.d.mu`;
  - a `g.state.Enqueue` of its queue item.
  Event lines need the double wrapping `{"k":"event","event":{"type":"agent_event","payload":{"event":...}}}`. Without a wire capture, `swallowed_argument` learns argument names only from the run's own calls, so the fixture needs one call that did pass the argument.
