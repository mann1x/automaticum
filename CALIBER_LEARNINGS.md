A new or changed flag or verb also goes into the command list of `docs/specs/090-interfaces.md` section 1. A new pure-Go package is added to the `test` target of the `Makefile` (recipe lines start with a tab) and to the `make test` sentence in `CLAUDE.md`; a new binary gets its own `go build` line in the `build` target.
- **[pattern]** Pause inside a run (D77, D83) is built on the SDK's `beforeModel` hook in the same process: the daemon writes a file `hold` beside the job, the runner prints `held`, `holding` (once a minute) and `released` (with `held_ms`) notes, held time is taken out of the wall time and stops the wall and idle limits, and `automaticum run pause <run>` / `run resume <run>` drive it; the SDK has no pause call for the root session and the hook does not see the abort signal, so a hold must be released on abort. When wrapping an SDK hook in `runner/runner.mjs`, keep the hook already set (the prompt-template hooks set one) and call it after your own. To try pause without a GPU, copy a stub script with `delay_ms` on every turn (6,000 ms on each turn of the `demo/answer` fix script gives about 30 s), start `automaticum stub serve --listen <addr> --script <file>` in the background, `run start --arm stub-sdk-4.100.251 --task demo/answer`, `run pause` after a few seconds, `run resume` later, then read `automaticum logs <id> | grep '"note":"\(held\|released\)"'`, `provenance.held_ms` and `provenance.holds` in `run show <id> --json`, and the `wall` line of `run show` ("paused for ... more, which is not counted"). On the stub the daemon logs `the endpoint did not drop its model ... /api/generate gave status 404`: expected, the stub serves only chat; the unload step is tested only on a real Ollama or xOllama endpoint (it was, on 2026-10-14: `the endpoint dropped its models for the pause` within 2 s of the hold).
