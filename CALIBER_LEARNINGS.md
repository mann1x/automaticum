# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[pattern]** Count before you write a number into a spec, a decision row or `CLAUDE.md`, for example `grep -c '^\t{Name: ' internal/detect/thresholds.go` for the registered thresholds. A number estimated from the plan ("50") needed a second edit across three files once the real count (53) was known.
- **[pattern]** When a change moves a daemon default (what a route returns when a parameter is absent), have the CLI ask for the new default explicitly (for example `detect` sends `metric=*`). Also have the CLI fill in any new header field an older daemon leaves empty, using what it asked for. Lane hosts and the local daemon often run an older build, and this way the new CLI behaves the same against both.
- **[convention]** In a daemon JSON answer, an opt-in block must never encode "not asked" the same way as "empty". The rules: no `omitempty` on it; an empty object when it was asked for and nothing matched; `null` only when it was not asked for; and a header field saying what was included. Prefer to make the useful data the default and let a flag narrow it. This comes from bug-094: `detect --json` left out `metrics` unless they were named, and a client's script read the missing block as zeros and divided by zero.
- **[convention]** Every number a detector or a measure decides with is a registered threshold (D148, owner 2026-11-12: "the thresholds comes from the SDK but as defaults. automaticum must be flexible"). Add a new one to the registry in `internal/detect/thresholds.go`. Give it an `Origin` (`sdk` when the SDK has the same rule, `owner` for an owner document or decision, `harness` when no owner decision is on record, which the owner must confirm), a `Source` naming exactly where the default comes from, and a `Doc`. The package constant stays as the registry's `Default`. In a function, read the value as a local at the top (`unitMin := o.T.Int(ThUnitMinChars)`, or `v.Int(...)` for a `Values` argument) so the body is unchanged; a nil `Values` gives every default. A constant used as an array length must become `make([]int, n+1)`. A count the code divides by or takes a modulo of gets `Min: 1`. Never read the bare constant. Call sites that have the installation at hand pass `d.thresholds()` or `opt.T` (ingest, detect, export, guard watch, canary), not nil. Each value is then overridable per installation (`[thresholds]` in `automaticum.toml`) and per read (`detect --threshold name=N`). Any output computed with it must carry the effective value and where it came from (sdk/owner default, config, cli), so results read at different thresholds are never merged unseen. If the SDK has no such rule, tell the client and ask the owner for the default; never invent one.
- **[pattern]** When you port a measure from a client's script (for example loopscan's block repeat count), prove the Go port equal to the script itself. Copy the script's scoring function verbatim into a throwaway Python file in the session scratchpad. Generate varied cases (every separator, accented letters, empty and too-short inputs, a heavy repeat), score them with it into `internal/detect/testdata/<name>.json`, and write a Go test that compares every case. A port checked only against your own reading of the script hides differences in splitting and normalising.
- **[gotcha]** The decisions table in `docs/specs/decisions.md` has three columns: `| id | decision | where |`. The last column is the spec sections (`| 040 §6.1.2, 030 §5 |`), not a date. Put the date and the owner's quote inside the decision text, ending with `). |`. Before you insert a row, check the format with `grep -n '^| id' docs/specs/decisions.md` and the tail of the previous row.
- **[gotcha]** In the private-name scan, `git ls-files -z | xargs -0 grep -Il ...` exits with **123** when nothing matches, not 1, because xargs reports 123 when any grep call returned 1. So `rc=123` on the tracked-files grep means clean. A plain `git diff --cached | grep -E '^\+' | grep -nE "$P"` still gives `rc=1` for clean; run the same grep on `git show HEAD` after the commit. A pipeline that ends in `cut`, `head` or `tail` reports that command's status. `PIPESTATUS` counts from 0: in `git diff --cached | grep -E '^\+' | grep -nE "$P" | head`, the scan is `${PIPESTATUS[2]}` (1 = clean). `${PIPESTATUS[3]}` is `head` and is always 0, so it proves nothing. You can also use `grep -cE` and read the count (0 = clean). To stage without the hook churn files, use `git add -A -- . ':!.wolf/cron-state.json' ':!.wolf/suggestions.json'`. Some hits are expected and are not leaks: npm lockfile `resolved` URLs (`@cerebriline/shared/-/shared-<v>.tgz`, so filter `registry.npmjs.org/` out of the staged diff), the scan patterns in `CALIBER_LEARNINGS.md` itself (they match `/shared/`), and sample paths in the `tasks/train-sh` seeds and checkers. Absolute paths in Go test fixtures that look like host paths also hit the scan, so use neutral ones such as `/data/a` or `/opt/r`. `.wolf/memory.md` and `.wolf/buglog.json` are tracked, so their rows must use the neutral host names too: write "the blackswan-2 build claim", never the private resource name of a claim or GPU, and "the same artefact as the dev build", never the dev machine's name. Mailbox addresses (`<session>@<host>`) also carry the private host name, so write "the SDK owner (ollama)", not the address.
- **[gotcha]** Scripted edits can fail quietly in three ways. (1) `sed -i 's/old/new/'` exits 0 when nothing matches. A guessed pattern changes nothing, and the next build shows the same error. Print the real line with `sed -n Np file` first, or use a Python `sub(old, new)` helper that asserts `s.count(old) == 1`. (2) A parameter or struct field you add can collide with a name already in scope: `v` was already the local verdict in `ingest.Canary`, and `editStreak` was already a counter field of the struggle state. Grep the function body and the struct before you choose the name. (3) Inserting an import with `sed '0,/^import (/s//...'` does nothing in a file that has no `import (` block (`internal/ingest/cap.go` had none). Check with `grep -n '^import' file`; if there is no block, add a single `import "..."` line after `package`.

- **[pattern]** After any change to a task's oracle source, seed or `task.toml`, do these steps. Bump `version`. Run `automaticum task pin -repo <checkout> --write <suite>/<task>`, which rebuilds the artefact and writes its new `sha256`. Then run `automaticum oracle verify -repo <checkout> <suite>/<task>`; every fixture must come out `ok` on each of its 3 runs. A run never builds an artefact: the gate SKIPs a run whose pinned artefact is not built, or whose oracle was not proven for the task's current hash. Even a comment-only edit to `task.toml` changes the task hash, so run `oracle verify` on every installation before the next run there. Never move a lane host's checkout while a client's batch on that task is running or queued. On a lane host, a task-only change needs no binary swap and no daemon restart. Ask the client by mail to hold that task, then run a background script that polls `automaticum status` until it shows `0 queued` and no lane `running`. Have it refuse a dirty checkout, then run `git fetch && git checkout <sha>`, `oracle verify`, `config check` and `task show` (compare `hash` and the artefact `sha256` with the dev build), and mail DONE. `TestLoadAll` in `internal/task/task_test.go` asserts `manic_miner`'s version, so bump it there too. To see what the agent will read, run the built artefact at `<data_root>/artefacts/<sha256>/<output>` with `docker run --rm --network none -v <artefact>:/r:ro -v <fixture>:/w/<file>:ro -w /w <oracle image> /r <file>`.
- **[gotcha]** `TestWatchConfig` in `internal/daemon/reload_test.go` can fail once after about 10 s in a full `-race` run of `internal/daemon` and then pass alone in about 0.3 s (bug-092, a timing flake of the directory watcher). Before you blame your change, rerun it alone with `go test ./internal/daemon/ -count=1 -race -run TestWatchConfig -v`, then on HEAD with `git stash -q && go test ... -count=3 -run TestWatchConfig; git stash pop -q`. - **[pattern]** When you change an exported function's signature, `go build` does not compile `_test.go` files, so it reports only the production callers. Run `go vet ./internal/<pkg>` (it type-checks the tests) on each package until it prints nothing about `not enough arguments`. Then run `go build ./internal/...` for the dependants (`detect` → `ingest` → `daemon`, `export`) and `CGO_ENABLED=0 go vet ./cmd/automaticum`. Where outside packages call the function and do not need the new argument, keep a thin wrapper with the old signature.
- **[gotcha]** `go build ./...` from the repo root fails with `no required module provides package github.com/northwind/...`. The cause is `tasks/train-ml/*/checker/main.go`, whose imports resolve only inside each task's own seed module, so the failure is not your change. Compile-check the libraries with `go build ./internal/...` (cgo on). On the host, linking `cmd/automaticum` with cgo on fails in gcc, because the native archives exist only in the build containers. Check it with `CGO_ENABLED=0 go build -o /dev/null ./cmd/automaticum`. For a throwaway CLI (to run `image build`, `stub serve` or `arm show` locally), use `CGO_ENABLED=0 go build -o <scratchpad>/am ./cmd/automaticum`. `CGO_ENABLED=0 go build ./internal/...` fails instead on `internal/store/duck`, so with cgo off, name the pure-Go packages. `go build ./cmd/automaticum` without `-o` leaves an untracked `automaticum` ELF binary in the repo root, and `git add -A` would commit it.
- **[pattern]** Lane images are built by the CLI without a daemon: `automaticum image build -config examples/config -repo "$PWD" base go rust cpp dotnet typescript`. List `base` first, because the layers and `tb2-*` copy from it. The base takes a few minutes and all layers about 6, so run the full build as a background command and redirect its log to the scratchpad. - **[pattern]** To test a runner change end to end without the daemon, do this. (1) Run `automaticum arm show -config <cfg> -repo "$PWD" -json <arm>` to get the resolved arm. (2) Write a `job.json` with it: `protocol` = current `Protocol`, `endpoint.base_url` = `http://172.17.0.1:<port>`, `workspace` `/workspace`, `out` `/out`, `sdk_release`. (3) Run `automaticum stub serve -listen 172.17.0.1:<port> -script s.json` in the background. Its turns hold `tool_calls` with the SDK's real argument names (`read_files` `{files:[{path}]}`, `editor` `{path, old_text, new_text}`). (4) `docker run --rm --user 1000:1000` the lane image with the workspace, out and job mounted, the SDK build's `node_modules` at `/opt/automaticum/runner/node_modules:ro`, and each edited `runner/*.mjs` bind-mounted over `/opt/automaticum/runner/<file>:ro`. That way you can iterate without rebuilding the image. - **[gotcha]** In the runner's `out/wire.jsonl`, each row's request is `request_body`, a JSON **string**, not a `request.body` object. `json.loads(row['request_body'])` gives the chat body. The tool list the model saw is in `body['tools'][*].function.name`, and the tool results are the `role == 'tool'` messages of the last request.
- **[correction]** automaticum must be usable as a tool by people and by assistants alike. - **[gotcha]** If you edit Go source with `python3 - <<'EOF'` and a plain `'''...'''` string, a Go escape written as `\n` becomes a real newline in the file. That splits the Go string literal, and the next `go vet` fails with no clear message. Write `\\n` inside the Python string, or use `r'''...'''`. Existing struct fields are gofmt-aligned with runs of spaces, so an exact `assert old in s` on a field line fails. Check the real line with `grep -n ... | cat -A` and match it with a regex that allows ` +` between name and type, or anchor on a neighbouring line that has no alignment. If a script asserts partway, its own file is not written, but edits made by earlier steps are. Run `go vet` to see what state you are in. Run `gofmt -l` right after each scripted edit, and look at broken lines with `sed -n A,Bp file | cat -A`. Adding fields to a struct changes gofmt's field alignment, so `gofmt -l` listing the file after a scripted edit usually just means it needs `gofmt -w`. When you append a test with `cat >> file_test.go <<'EOF'`, check its imports first (`head -30 file_test.go | grep '"slices"'`). An import added with `sed` lands out of order, so run `gofmt -w` on the file afterwards.
