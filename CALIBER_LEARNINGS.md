- **[pattern]** Before you add a binary dependency to a lane image, prove its package list in the existing image first. Download the artefact into its own scratchpad directory, `sha256sum` it, and mount it read-only into `docker run --rm --entrypoint bash automaticum-lane:base -c 'apt-get update && apt-get install ...; ldd <bin> | grep "not found"; <bin> --version'`. Only then write the Dockerfile, with the download pinned by that checksum. Take the libraries from the upstream package's own list (Chrome's `chrome-linux64/deb.deps`) and drop the ones that would put new commands on the agent's PATH (`wget`, `xdg-utils`). The `cpp` layer is Debian 13 (gcc image), so the same list needs the `t64` names (`libasound2t64`, `libatk1.0-0t64`, `libcups2t64`, `libcurl4t64`, `libglib2.0-0t64`, ...). Make an npm lockfile for `images/<name>/` (or `runner/sdk/<ver>/`) with the pinned Node image (`NodeImage` in `internal/sdk/sdk.go`), as your own uid: `docker run --rm -v "$PWD/<dir>:/w" -w /w --user "$(id -u):$(id -g)" -e npm_config_cache=<persistent cache dir> node@sha256:<digest> npm install --package-lock-only --ignore-scripts --no-audit --no-fund`.
- **[convention]** Dependabot alerts on the repo are almost all in `runner/sdk/<ver>/package-lock.json`, the SDK's own dependency tree. Never bump them in our lockfile: that changes the SDK build and its `bundle_sha256`. Instead, mail the SDK owner the packages, GHSA ids and fixed versions for their next release. Keep the alerts on the current pins open, and dismiss the older pins' alerts as `tolerable_risk` with a comment. When a release clears them, dismiss the old pins' alerts with a comment that names the fixing release. `tasks/tbench2/*/oracle/requirements.txt` is the pinned scorer and is never edited (dismiss as `tolerable_risk`). `spike/` modules are never built (`not_used`). `images/lsp` alerts come from upstream exact pins: check `registry.npmjs.org/<pkg>/latest` before calling one fixable. Fetch alerts with `gh api -X GET 'repos/<owner>/<repo>/dependabot/alerts?state=open&per_page=100' --paginate --jq '.[] | [.number, .dependency.manifest_path, ...] | @tsv'`; without `--jq`, `--paginate` concatenates JSON arrays and the output is not one valid document. Dismiss with `gh api -X PATCH .../dependabot/alerts/<n> -f state=dismissed -f dismissed_reason=<r> -f dismissed_comment=<c>` (comment under 280 characters). Test it on one alert and read it back, then loop over the rest with a short sleep between calls. The open count can lag a PATCH by a few seconds: list the alerts again before you report a number.

- **[pattern]** To see what really changed between two SDK releases (a dependency-only release, say), diff the installed bundles, not the source. For each of `@cerebriline/{agents,core,shared,llms,sdk}/dist` in the two builds, first compare the files byte for byte after replacing the old version string with the new one. Then diff only the changed `.js` files with `difflib.SequenceMatcher` on token lists split after `;`, `{` and `}` (`re.split(r'(?<=[;{}])', s)`). A character-level SequenceMatcher on the minified bundles ran for over 10 minutes and had to be stopped. Every release also changes core's embedded package.json, its `sdk-v1-<hash>` build key and a build timestamp; those are not code changes. Then import both builds offline and compare the export count and the exports the runner needs (`createLspHost`, `createDiagnosticsCheckFileTool`, `createEditorDiagnosticsHooks`, `createChromeBrowserDriver`, `createChromeRenderDriver`). If agents and shared are byte-identical and core changes no guard code, map the release onto the existing `CallGuard`/rules version in the `callguard_test.go` release map and do not bump the library version.

- **[gotcha]** Smoke runs on a lane host: `automaticum run start` prints the run id alone on its second line as `YYYYMMDD-HHMMSS-xxxxxx`, with no `-NNN` suffix. Parse it with `grep -oE '^[0-9]{8}-[0-9]{6}-[0-9a-f]{6}$'`. With an empty id, `automaticum wait run` prints its usage and returns at once. The `kill` of the stub server that follows then stops it before the run starts, and the run is SKIPPED with `gate model_tag: endpoint stub does not answer /api/version`. Keep `automaticum stub serve` up until `wait run <id>` has returned. Write multi-line remote steps as `ssh <host> bash -s <<'EOF' ... EOF`, not as a quoted `ssh <host> '...'` one-liner. After a deploy moves the repo checkout, a run on a task is refused (`the oracle ... was not proven against its fixtures`) until you run `automaticum oracle verify --repo <repo> <suite>/<task>` on that host.

- **[gotcha]** `node --test` (the runner tests, `cd runner && node --test test/`) prints its summary as `ℹ pass 56` / `ℹ fail 0`, not TAP's `# pass`. A `grep -E '^# (pass|fail)'` matches nothing and makes the whole command exit 1, so grep `'^ℹ (pass|fail)'` or read `| tail -10`. - **[gotcha]** In the private-name scan, `git ls-files -z | xargs -0 grep -Il ...` exits with **123** when nothing matches, not 1, because xargs reports 123 when any grep call returned 1. So `rc=123` on the tracked-files grep means clean. A pipeline that ends in `cut`, `head` or `tail` reports that command's status. Simplest: use `grep -c -i -E "$P"` and read the count (0 = clean), on `git diff --cached | grep '^+' | grep -v 'registry.npmjs.org'` before the commit and on `git show HEAD` after it. To stage without the hook churn files, use `git add -A -- . ':!.wolf/cron-state.json' ':!.wolf/suggestions.json'`. Write "the shared package's dist/index.js" or "agents, shared and llms" instead. A hit in `CALIBER_LEARNINGS.md` after the commit hook has run needs `sed` plus `git commit --amend --no-edit --no-verify`. - **[gotcha]** Smoke runs on a lane host: `automaticum run start` prints the run id alone on its second line as `YYYYMMDD-HHMMSS-xxxxxx`, with no `-NNN` suffix. - **[gotcha]** In the private-name scan, `git ls-files -z | xargs -0 grep -Il ...` exits with **123** when nothing matches, not 1, because xargs reports 123 when any grep call returned 1. Simplest: use `grep -c -i -E "$P"` and read the count (0 = clean), on `git diff --cached | grep '^+' | grep -v 'registry.npmjs.org'` before the commit and on `git show HEAD` after it.
