# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[correction]** Experiment arms, models, runs and lanes never belong in the public repo. Do NOT invent a "private roots beside the repo" split (`private_arms`/`private_models`) — the owner rejected that as confusing. An installation's arms and models live in its own configuration directory (`<config>/arms`, `<config>/models`), beside `endpoints/` and `lanes/`; the repo ships only `examples/config/` (base.toml, the stub arms, the stub model), which the Go tests also load. When the owner says installation data must not be in the repo, put it in the one place the installation already keeps its own data — the config dir — not a second new location (D118).
- **[convention]** An arm's id is a content hash that excludes its file location — moving an arm file (repo ↔ config dir) keeps its id. After any such move, verify with `automaticum arm show <name> | grep ^id` against the recorded ids before you trust that batches still pool.
- **[gotcha]** After `git mv arms examples/config/arms`, a later `git add -A arms models …` fails with `fatal: pathspec 'arms' did not match any files` and aborts the whole `git add` (nothing staged). Stage the new paths (`examples/config`, the package dirs) explicitly; never re-list the moved-away directory names.
- **[pattern]** Go test fixtures load the stub arm/model by relative path (`../../arms`, `../../models`). When those dirs move, `grep -rn --include=*_test.go` for the old paths and repoint them, and give the daemon test rig's `config.Local` a `Dir` field pointing at `examples/config` so `Local.ArmsDir()`/`ModelsDir()` resolve. `make test` catches a miss.
- **[gotcha]** A harness-killed TIMEOUT run (stopped at wall + ~2 min grace, not by the runner at the wall; no runner `end` line; basis says "the run did not record its SDK") whose last agent event is a `capped_thinking` / `thinking-condensing` notice means the SDK's thinking-condensation side call did not honour the session abort (4.100.266: the side call never gets the AbortSignal, and the loop checks `throwIfAborted` only after it returns). It is an SDK defect (bug-045), not a harness bug; the TIMEOUT verdict still stands.
- **[pattern]** A twin arm (same engine, template, sampler, guards and SDK; only the weights differ) is a small file: it `extends` the floor arm, sets a new `endpoint` name on the same `base_url` (so its runs never pool with the floor's), plus `[model] model = <new catalogue tag>`, and needs a matching model entry. These files are the installation's and live in `<config>/arms` and `<config>/models`, never the repo (D118). On linux-gpu-1 `arm validate` answers `names endpoint "…", which this installation does not have` — expected; use `arm diff <floor or previous twin> <new twin>` there (must show only `endpoint` and `model.model`, floor id unchanged). Real validation happens on the lane host once the endpoint file exists.
- **[pattern]** Secret scanning runs from the local, untracked `.git/hooks/pre-commit` as a `# gitleaks:pre-commit:start`…`:end` block after caliber's block; it runs `gitleaks git --staged --redact --no-banner -v` and refuses the commit if gitleaks is missing. A fresh clone lacks this block — re-add it. For a false positive (a made-up token in a Go test trips `generic-api-key`), add a value allowlist to `.gitleaks.toml` pinned to its file with `condition = "AND"`; never allowlist a whole path. Bypass once with `AUTOMATICUM_SKIP_GITLEAKS=1`, on purpose only. The owner wants the staged scan only, no push-time or CI full-history scan.
- **[gotcha]** When renaming to a longer name that contains the old one (`run3` → `run3-s400`), chained `sed` replaces text it already renamed, leaving `run3-s400-s400`. Rename once with a pattern that cannot match the new name, e.g. Python `re.sub(r'run3(?!-s400)', 'run3-s400', s)`, then `grep -c s400-s400` to confirm before restarting the daemon.
- **[pattern]** Before telling a client to queue on an endpoint, verify what the shared port actually serves — clients swap GGUFs behind the same port, so the endpoint name proves nothing. `curl -s -m5 http://172.17.0.1:<port>/props`, compare `model_path` to the arm's weights and the chat_template sha256 to the floor's, and `sha256sum` the GGUF yourself on the lane host. Only then write it into the model entry and confirm.
- **[env]** On linux-gpu-1, `grep` is ugrep. A bounded-repeat pattern (`grep -o '[^"]\{0,200\}<word>'`) over a large session `.jsonl` or a minified SDK `dist/index.js` fails with `error … exceeds complexity limits`. Use a short `python3 -I` script with `re.finditer` to window the match instead.
- **[gotcha]** `automaticum doctor -arm <arm> -task <task>` refuses `model_tag` and `bind_address` whenever the arm's model server is down (e.g. a client holds the GPU). That is expected and says nothing about the deploy. Use `doctor -all … | grep -E 'oracle|harness'` for the gates the deploy decides; a green doctor reads `10 pass, 0 refuse, 0 wait, 5 not looked at` (the 5 need an on-host agent, milestone 7).
- **[correction]** On linux-gpu-1's shared spool disk, "remove anything stale" means only what this project's own sessions created. Never remove other sessions' or projects' directories, however old. Prove ownership first (grep this project's transcripts and `docs/local/hosts.local.md`), list what you will delete with sizes, and ask before any `rm`.
- **[gotcha]** A Bash call whose last command is `diff` (files differ), `grep -c`/`grep -q` (no match), or an `awk` pipeline that yields nothing exits non-zero; the tool then reports FAILURE with empty output and hides the earlier commands' output, even over ssh. End such chains with `; echo rc=$?`, or split the check into its own call.
- **[gotcha]** In a Bash call, never `pkill`/`pgrep -f` a pattern that also appears literally in the same command line — it matches the calling shell and the guard refuses the call. Use the bracket trick `P=$(pgrep -f "[s]tub serve …")` or an anchored pattern, confirm with `ps -o pid,args -p <pid>`, then `kill` in the next call.
- **[pattern]** The lane host keeps ready-made stub scripts under `<install>/work/stub/` (`fix-manic.json`, `say-done.json`, `hang.json`, `loop-reasoning.json`, the plan scripts). Use those for a post-deploy smoke: `nohup ../bin/automaticum stub serve -listen 172.17.0.1:7412 -script ../work/stub/fix-manic.json …`, then `run start -arm stub-sdk-<ver> -task custom/manic_miner`.
- **[gotcha]** The store keeps a task in two columns, `RunFilter.Suite` and `TaskID` (bare id, e.g. `manic_miner`), while every CLI/API names a task `suite/task`. Passing `suite/task` straight into `TaskID` matches nothing and fails silently — split it with `strings.Cut(t, "/")`. The daemon tests' fake store (`memState.ListRuns`) must filter exactly like `where()` in `internal/store/duck/duck.go`; extend the fake whenever you add a filter field.
- **[gotcha]** The daemon test rig's fake runner records no resolved arm (`store.Run.Arm` empty), so a finished run's arm name from `GET /v1/runs` is `""` in the rig. To test code that reads the arm from a record, call it directly on a hand-built `store.Run` whose `Arm` is the JSON `{"name":"stub"}`; don't assert on the rig's own finished runs.
- **[gotcha]** When a Python script rewrites `.wolf/buglog.json`, plain `json.dump(d, f, indent=2)` escapes non-ASCII (`§`→`\u00a7`) and drops the trailing newline, rewriting old entries in the diff. Use `open(p,'w').write(json.dumps(d, indent=2, ensure_ascii=False) + '\n')`, then check `git diff --cached .wolf/buglog.json | grep -c '^-[^-]'` prints 0.
- **[pattern]** Before a commit, run the private-string check besides gitleaks: grep the tracked files (`git ls-files -z | xargs -0 grep -IlniE "$P"`, excluding `CALIBER_LEARNINGS.md`, lockfiles) and the added lines of `git diff --cached` for private host nicknames, absolute paths and addresses. `xargs grep` exiting 123 and `grep` exiting 1 both mean nothing found. Never write the private pattern list itself into a tracked file.
- **[pattern]** For a per-arm gate summary (verdict counts, guard trips, Fisher/Mann-Whitney, basis drift) point clients at `automaticum compare -all -batch <floor> -batch <twin>…` before building anything. `run ls -arm <name>` resolves the arm from the current checkout, so it omits runs of an earlier version of that arm (another id); use `-model` or `-arm-id`. `run start` prints the batch id on its first line; a run-id prefix is not a batch id.
- **[pattern]** To try a new client-side command that only calls routes the deployed daemon already serves, `CGO_ENABLED=0 go build -o <scratch>/am-x ./cmd/automaticum`, `scp` to `<install>/work/`, run it in one ssh call with `AUTOMATICUM_CONFIG=<install>/config` against real ids, then `rm` it — no restart, no idle lane needed.
- **[gotcha]** In `automaticum logs --events <run>`, SDK agent events sit at `.event.payload.event` on `"k":"event"` lines with `event.type == "agent_event"`. A filter on top-level `.event.type == "notice"` matches nothing. `chunk` lines repeat the same events as escaped text — skip them or you double-count. A current notice carries `noticeType`, `message`, `metadata.{kind,phase,cause}`.
- **[convention]** A metric name must never carry free text (a sentence, count, or quoted tool name) — every run would get its own and none would pool in `compare`. Key by stable fields: notices are `notices.<type>.<kind>.<phase>`, else `notices.<reason>`, else `notices.<type>` (D116). Count an event announced at start and end (compaction) once, at phase `completed`.
- **[gotcha]** `.claude/rules/runner-protocol.md` writes out the current `AnalysisVersion` ("now N"). When you bump it in `internal/ingest/analyse.go`, update that rule and the dated note in 070 §2. Stored runs keep their old metrics until `automaticum reanalyse` runs on the lane host after the deploy.
- **[gotcha]** In `internal/ingest/ingest_test.go`, the `stream` const holds only runner prefix lines; the full fixture with agent events is `eventStream()`, read by `events(t)`. A new test reading `stream` sees zero agent events; adding fixture lines also changes the `ev.Lines` count `TestReadEvents` expects.
- **[gotcha]** A command that fetches a blob per run of a batch must skip runs whose verdict is `SKIPPED` (they never started, no event stream). Under `-json`, a nil Go slice prints `null`; initialise results as `[]T{}` to get `[]`.
- **[pattern]** A daemon/CLI-only change (no runner protocol, no lane layer) needs no image rebuild and leaves the basis unchanged: `make build`, `scp` both binaries to `<install>/bin/.new/`, compare `sha256sum` both sides, then in one `set -e` ssh call recheck idle (`lane-1 … idle` and `^0 queued`, else `exit 3`), `systemctl stop`, swap, `git checkout -q <sha>`, `systemctl start`, check `/v1/status`. Tell clients not to use a new flag until you confirm deployed — an older daemon refuses unknown fields.
- **[pattern]** To prove new library code on real lane-host data without a deploy, write a throwaway `internal/<pkg>/zz_real_test.go` that skips unless an env var is set, `go test -c -o <scratch>/<pkg>.test ./internal/<pkg>/`, delete the test file immediately so it's never staged, `scp` the binary and run it with the env var over ssh, then `rm`. Cross-check counts against `run show -json <run>`.
- **[pattern]** The pre-commit hooks (caliber refresh, then gitleaks) make `git commit` slow and noisy. Give the Bash call ~400000 ms timeout and `git commit -q -F - <<'EOF' … 2>&1 | grep -E "caliber:|leaks|scanned|refused"`, then print `echo "commit rc=${PIPESTATUS[0]}"` before `git push` (the grep's own exit code would hide a refused commit).
- **[gotcha]** `.wolf/memory.md` rows use linux-gpu-1's local clock (UTC+1); the lane host and journal use UTC. Get a row's time from `date +%H:%M` on linux-gpu-1. A daemon's `up for` counts from your own deploy's restart; check `systemctl show automaticumd -p NRestarts -p ActiveEnterTimestamp` before suspecting a crash.
