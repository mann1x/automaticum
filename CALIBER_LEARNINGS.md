# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[pattern]** To list what is still unbuilt in one spec, grep the audit rows instead of reading the file: `grep -n "^| 070" docs/audit/2026-11-01-spec-vs-code.md | grep -E "NOT BUILT|PARTIAL" | cut -c1-210`. A row closed by a change gets its status (`BUILT`, `PARTIAL`, or `OPEN` with the `O` id) and its evidence updated in the same commit.
- **[pattern]** To see the metric names ingest writes before naming a new one, run `grep -on 'm("[a-z_.]*"' internal/ingest/analyse.go | sed 's/.*m("//; s/"$//' | sort -u`. Names ending in a dot (`notices.`, `guard_trips.`, `derived.`) are prefixes completed at runtime.
- **[gotcha]** In the daemon, `notifyEnd` runs after a run's end is visible and after the lane is free. In tests, `waitFinished` returning does not mean the notifications went out: use `waitFor` on the count before asserting on captured notifications. A new notification kind also changes exact counts in existing tests such as `TestGates`. In code, state that must hold for the lane's next run (a quarantine, say) cannot be set in `notifyEnd`: the scheduler can start the next run first. Set it in the run's goroutine before `delete(d.flights, ...)`.
- **[convention]** Everything in `Arm`'s resolved JSON goes into its id, because `hash()` hashes `Resolved()`. A new arm field that is placement rather than what is measured (like `requires`) must be `omitempty` and also deleted in `hash()`, or every existing arm changes identity. Pin it with a test comparing the ids of two arms, as `TestRequiresNotIdentity` and `TestStopOnIdentity` do.
- **[convention]** An Open item the owner drops does not become a `D` row: it goes into `docs/specs/decisions.md` section 5 (Not adopted) with its O id and reason, and its audit rows get the status `NOT ADOPTED`. After closing O items, find every marker with `grep -n "O3[1-9]" docs/specs/*.md` (with the ids at hand), since they also sit in 020, 050, 065, 070 and 090, and in the closed-items list of `decisions.md`.
- **[gotcha]** A multi-file python heredoc followed by `; echo ok` or a new line hides a failure: the traceback scrolls past, `ok` still prints, and the files written before the failing step stay changed. Chain with `&&`, write each file with an `assert a in s` on the anchor first, and after a failure rerun only the steps that did not apply, since the earlier replacements are already in place.
- **[gotcha]** `.wolf/cerebrum.md` ends with `## Decision Log` and has no trailing newline, so `s.index('\n', i)` on its last line raises `ValueError` and a plain `>>` glues the new text onto that line. Append a decision with `printf '\n- ...\n' >> .wolf/cerebrum.md`, then `tail -2` to check.
- **[gotcha]** The daemon tests' `memState` embeds a nil `store.State`, so a handler that calls a store method `memState` doesn't override compiles and then panics at runtime. When a new handler uses another store method (e.g. `ToolCalls`), add that method to `memState` first. Its `ListRuns` filter also has its own field list, which ignores `RunFilter.Since`, so a window on `Since` is not exercised in the rig. The rig's `memBlobs` is a read-only map: a test whose handler stores blobs needs a store with a `Put` and a lock, as `syncBlobs` in `rescore_test.go`.
- **[env]** A full `make test` takes close to 5 minutes, nearly all of it `internal/legacyimport` under `-race`, so pass a Bash timeout of 600000 ms. While iterating use `go test -race -count=1 -run <Test> ./internal/daemon/`, and `CGO_ENABLED=0 go test` for `cmd/automaticum`. `make test` does not compile `cmd/automaticumd`, so after changing the daemon's wiring there run `CGO_ENABLED=1 go vet ./cmd/automaticumd/`.
- **[pattern]** Go edited by a python heredoc is not formatted, and neither `go build` nor `go vet` complains: a new field beside aligned struct fields leaves the file unformatted. Run `gofmt -l internal cmd` after such edits and `gofmt -w` what it lists.
- **[gotcha]** The OpenWolf post-write hook adds an anatomy entry and a memory row only for files made with the Write tool, and its description is a stub such as `Struct: written`. Files made with a Bash heredoc (`cat > x_test.go`) get no entry at all. After a batch of new files, run `grep -n '<file>' .wolf/anatomy.md` for each: replace a stub with the real description rather than adding a line beside it, which leaves the file listed twice, and add the missing ones.
- **[convention]** A mutating route takes its dry run as the query parameter, not a body field: the handler checks `dryRun(r)` (`?dry_run=1`), and the CLI uses `addMutation(fs)`, `m.on(c, path)` and `m.dryNote()`, which also bring `--idempotency-key`. Read these helpers before adding a new mutating command.
- **[gotcha]** A new map in the daemon's `control` struct must be initialised in both the default literal and the nil checks of the loader. A `control.json` written by an older daemon has no such key, so a map set up in only one place panics with an assignment to a nil map after a restart.

- **[gotcha]** The daemon tests' `fakeRunner.Execute` in `daemon_test.go` builds its own `store.Run` from `run.Request`. A new field passed through `run.Request` (such as `Cohort`) reads empty in daemon tests until it is copied there too, even though `internal/run` sets it correctly.
- **[gotcha]** In a scripted edit, `assert a in s` followed by `s.replace(a, b, 1)` proves the anchor exists, not that the first hit is the one you meant. `reply(w, http.StatusOK, v)` hit a new wrapper rather than the end of the extracted function, and `rescore_test.go` in `CLAUDE.md`'s Layout hit the `internal/run` line rather than the daemon's. Assert `s.count(a) == 1`, or find the position from a unique earlier anchor with `s.index(a, i)`, and after a refactor grep both sites before scripting a second fix.
- **[gotcha]** `go build ./...` from the repo root always reports `no required module provides package github.com/northwind/...`: those are the task checkers under `tasks/train-ml/*/checker`, which import their task's own packages, and the noise can hide a real error. Build the packages you changed (`go build ./internal/daemon/`, `CGO_ENABLED=0 go vet ./cmd/automaticum`) instead.
- **[pattern]** Check for private strings before a commit of this public repo with `test -n "$P"` first (an empty pattern matches every line), then `git ls-files -z | grep -zv -e CALIBER_LEARNINGS.md -e package-lock.json -e '^tasks/train-sh/' | xargs -0 grep -IlniE "$P"` and `git diff --cached | grep '^+' | grep -niE "$P"`. Clean is an empty output: `xargs` exits 123 and `grep` 1 when nothing matches, so read the printed list, not the status as a failure.
- **[pattern]** Thresholds ported from the SDK hold per release, not for the SDK as a whole: the reasoning-loop guard changed at 4.100.258 while the code still cited 4.100.250/251. Before trusting or extending a port, loop over every pinned build's `node_modules/@cerebriline/agents/dist/index.js`, regex out the default config object (e.g. `=\{minChars:4000,window:60[^}]*\}`) and print a sha1 of the class body: equal hashes mean the same code, and the first differing build is where to read. When a guard trip is unconfirmed by a replay, read the SDK's notice metadata for that turn (`kind`, `period`, `cycles`, `sample`) before assuming the detector is wrong; it names the rule the port is missing.
- **[pattern]** Fixtures do not show what a real stream does. To try analysis on a real run, add a temporary env-gated test `internal/ingest/zz_real_test.go` (skip when `REAL_EVENTS` is empty; `ReadEvents`, then `Analyse(&store.Run{ID: "x", Harness: os.Getenv("REAL_SDK")}, ev, nil)`; print chosen metrics and findings), run it with `-count=1 -v`, compare under two `REAL_SDK` values when rules depend on the release, and `rm` it before staging. The event stream stays in a scratch directory, outside the repo.
- **[gotcha]** Detector options reach more than ingest: `detect.Block` is called from `internal/ingest` (`DetectOptions`, `blockOptions`), `handleDetect` in `internal/daemon/api.go`, `automaticum detect` in `cmd/automaticum/client_cmds.go` and `export.Spans`. For any option that depends on the run, run `grep -rn "detect.Options{" --include=*.go internal cmd | grep -v _test` and pass it at every site, or the views disagree with the stored findings.
- **[gotcha]** `TestRunImported` asserts an exact `len(m.findings)`, so a new detector that fires on its stream fails it even when the detector is right. `store.Finding` prints `Evidence` as decimal bytes, which fills the failure output: pull out `Detector`, `Turn` and `Count` with a small regex over the output instead of reading it. A rule that groups calls by turn must also treat `Turn: 0` as a turn not known, as in an imported stream without iterations, and not as one shared turn.
- **[gotcha]** `.claude/rules/runner-protocol.md` writes out the current `AnalysisVersion`. When you bump it in `internal/ingest/analyse.go`, update that rule and the dated note in 070 §2. Stored runs keep their old metrics until `automaticum reanalyse` runs on the lane host after the deploy. A new ingest detector needs all of: an entry in `owned` (otherwise `reanalyse` keeps its old findings beside the new ones), an entry in `Versions` (otherwise the basis does not name it), and the `AnalysisVersion` bump. A metric family written at zero on every run (`struggle.*`, `transactions.*`) also needs its prefix in the zero-hiding list of `run show` in `cmd/automaticum/client_cmds.go`. A report that reads new metrics must count runs below the new `analysis.version` separately (as `report struggle` does), not as "never held".

- **[fix]** Deploying to the lane host: `scp` onto the running `bin/automaticumd` fails with `Text file busy`, and the same `scp` silently overwrote `bin/automaticum` with no copy to go back to. Copy each binary to `bin/<name>.new` and compare sha256 on both ends. Then, in one `set -e` ssh script: gate on `automaticum status` (lane `idle` and `0 queued`), `systemctl stop`, `mv` the old binary to `.prev`, `mv` `.new` into place, start. On the host the CLI is not on PATH: call `<root>/bin/automaticum` with `AUTOMATICUM_CONFIG=<root>/config`. Full steps are in the `learned-lane-host-deploy` skill.
- **[pattern]** Never write "the SDK emits no event for X" from one run's stream. That claim went into 070 and the audit from a run with the change protocol off, while the bundle has `atomic_transaction`, `atomic_empty_attempt` and `atomic_plan` notices. Search `node_modules/@cerebriline/core/dist/index.js` for `kind:"<prefix>[a-z_]*"` and its `dispatchAgentEvent` calls first. When porting an SDK observer, its verdicts land only where the SDK calls `inspect` (for the struggle detector, `content_end` and `iteration_end`). A test's expected firing turn must therefore sit at such an event, not at the notice that changed the state.
- **[gotcha]** A stored run's event stream (`logs <run> --events -json`, or a scratch `.jsonl`) wraps every SDK event twice. Lines look like `{"t":...,"k":"event","event":{"type":"agent_event","payload":{"event":{...}}}}`, mixed with `"k":"runner"` notes, so counting `e["type"]` or `e["event"]["type"]` only gives `agent_event` and `chunk`. Read `e["event"]["payload"]["event"]`: the notice kind is in `.metadata.kind` and the phase in `.metadata.phase`.
