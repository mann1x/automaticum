# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[pattern]** To prove a new test actually catches the bug it targets, drop only the fix with `git stash push -q <impl-file>`, run the test (it MUST fail, printing the pre-fix state), then `git stash pop -q`. Don't trust a test that was only ever seen passing against the fixed code.
- **[pattern]** A twin arm (same engine, template, sampler, guards and SDK; only the weights differ) is a small file: it `extends` the floor arm, sets a new `endpoint` name on the same `base_url` (so its runs never pool with the floor's), plus `[model] model = <new catalogue tag>`, and needs a matching model entry. These files are the installation's and live in `<config>/arms` and `<config>/models`, never the repo (D118).
- **[gotcha]** `run ls -arm <name>` resolves the name to an id and filters on `arm_id`; a stored run with an empty `arm_id` is invisible to it. The daemon test rig's fake runner records no resolved arm, so a finished run's arm name from `GET /v1/runs` is `""` in the rig — to test code that reads the arm from a record, call it directly on a hand-built `store.Run` whose `Arm`/`ArmID` is set; don't assert on the rig's own finished runs.
- **[gotcha]** When a Python script rewrites `.wolf/buglog.json`, plain `json.dump(d, f, indent=2)` escapes non-ASCII (`§`→`\u00a7`) and drops the trailing newline, rewriting old entries in the diff. Use `open(p,'w').write(json.dumps(d, indent=2, ensure_ascii=False) + '\n')`, then check `git diff --cached .wolf/buglog.json | grep -c '^-[^-]'` prints 0. The same ensure_ascii/newline rule applies to any JSON state file you rewrite.
- **[pattern]** Before a commit, run the private-string check besides gitleaks: grep the tracked files (`git ls-files -z | grep -zv -e CALIBER_LEARNINGS.md -e package-lock.json | xargs -0 grep -IlniE "$P"`) and the added lines of `git diff --cached` for private host nicknames, absolute paths and addresses. `xargs grep` exiting 123 and `grep` exiting 1 both mean nothing found. Never write the private pattern list itself into a tracked file.
- **[gotcha]** The SDK's Ollama provider sends one-time first-use probe chats to `/api/chat` (`options.num_predict == 1`, `stream:false`, a user/assistant/tool message triple) BEFORE the first real turn. The stub answers these at once (empty assistant message, `done_reason` `length`, no `prompt_eval_count` so the SDK decides channel as before) and does NOT record them in `Chats()`, so a `hang` turn holds the real turn and not the probe. To deliberately hold the probe (e.g. to test an abort landing on it), set `hang_probe = true` on the Script.
- **[pattern]** To confirm an SDK probe/abort-signal fix actually shipped, grep the installed `@cerebriline/llms/dist/index.js`: find `options:{num_predict:1}` and check whether `signal` appears within ~900 chars of it (the probe `fetch` carries `signal:o` only after the fix). 4.100.268 → absent, 4.100.269 → present. A rising `AbortSignal.timeout` count across versions is corroborating evidence; window the matches with a `python3 -I` `re.finditer` script.
- **[gotcha]** A clean `git push` prints only `remote:` lines, so `git push … | grep -v "^remote:"` exits 1 (grep matched nothing) even though the push succeeded. Don't read that exit code as failure — confirm with `git log --oneline -1 origin/main` and `git status -sb`.
- **[pattern]** Launch the stub server detached over ssh so it survives the Bash/ssh call: `cd <install>/work && setsid nohup <bin>/automaticum stub serve -listen 172.17.0.1:7412 -script stub/<x>.json >> stub.log 2>&1 < /dev/null &`, then `sleep 2; curl -s -m3 .../api/version`. A plain foreground `stub serve` holds the call open until it times out. Stop it by PID with the bracket trick.
- **[pattern]** To prove a new test actually catches the bug it targets, drop only the fix with `git stash push -q <impl-file>`, run the test (it MUST fail), then `git stash pop -q`. Don't trust a test seen only passing against the fixed code.
- **[pattern]** A daemon/CLI-only change (no runner protocol, no lane layer) needs no image rebuild and leaves the basis unchanged: `make build`, `scp` both binaries to `<install>/bin/.new/`, compare `sha256sum` both sides, then in one `set -e` ssh call recheck idle (`lane-1 … idle` and `^0 queued`, else `exit 3`), `systemctl stop`, swap, `git checkout -q <sha>`, `systemctl start`, check `/v1/status`. Claim the lane host's build resource first and release after. Tell clients not to use a new flag until you confirm deployed — an older daemon refuses unknown fields.
- **[gotcha]** `run ls -arm <name>` resolves the name to an id and filters on `arm_id`; a stored run with an empty `arm_id` is invisible to it (an arm that can't be read, or a run stopped while queued). The daemon test rig's fake runner records no resolved arm, so a finished run's arm name from `GET /v1/runs` is `""` in the rig — to test code that reads the arm from a record, call it directly on a hand-built `store.Run` whose `Arm`/`ArmID` is set; don't assert on the rig's own finished runs.
- **[gotcha]** When a Python script rewrites `.wolf/buglog.json` (or any JSON state file), plain `json.dump(d, f, indent=2)` escapes non-ASCII (`§`→`\u00a7`) and drops the trailing newline, rewriting old entries in the diff. Use `open(p,'w').write(json.dumps(d, indent=2, ensure_ascii=False) + '\n')`, then check `git diff --cached .wolf/buglog.json | grep -c '^-[^-]'` prints 0.
- **[gotcha]** The private-string gate can hit an SDK build's `package-lock.json` on npm registry URLs of `@scope/<name>` packages whose name equals a gate token (e.g. `@cerebriline/shared`). Read each hit: a `"resolved": "https://registry.npmjs.org/..."` URL is a false positive — re-filter only those exact URL lines with an anchored regex and confirm nothing else matches; never skip the check.
- **[gotcha]** `automaticum arm validate` (and `arm validate -repo <dir>`) exits non-zero (rc=1) whenever any arm names an endpoint the installation lacks, even though the ids it prints are valid — a twin arm on a host without its endpoint always does this. In a migration/deploy script never gate on its exit code (`arm validate … || exit`); capture the output and assert on it (`grep -q ": valid,"`), then diff the sorted before/after id lists to prove ids are unchanged.
- **[pattern]** For a per-arm gate summary point clients at `automaticum compare -all -batch <floor> -batch <twin>…`. `run ls -arm <name>` resolves the arm from the current checkout, so it omits runs of an earlier version of that arm (another id); use `-model` or `-arm-id`. `run start` prints the batch id on its first line; a run-id prefix is not a batch id.
- **[convention]** A metric name must never carry free text (a sentence, count, or quoted tool name) — every run would get its own and none would pool in `compare`. Key by stable fields: notices are `notices.<type>.<kind>.<phase>`, else `notices.<reason>`, else `notices.<type>` (D116). Count an event announced at start and end once, at phase `completed`.
- **[gotcha]** `.claude/rules/runner-protocol.md` writes out the current `AnalysisVersion`. When you bump it in `internal/ingest/analyse.go`, update that rule and the dated note in 070 §2. Stored runs keep their old metrics until `automaticum reanalyse` runs on the lane host after the deploy.
- **[correction]** A spec requirement is either built, or the spec says plainly "not built" with its milestone, or a decision drops it. Never leave a requirement in a spec with no milestone and no code; re-audit against `docs/audit/` after each milestone.
- **[correction]** automaticum ships ready-made waiters for client sessions. Never make a session write its own polling loop or `run tail > /dev/null`: use `automaticum wait ...`, `--each` for a Monitor, `--next --seen N` for re-arming.
- **[pattern]** A daemon/CLI-only change (no runner protocol, no lane layer) needs no image rebuild, but `make build` stamps the commit (`-dirty` on a changed tree), so a new binary changes the basis's `harness build` fact: deploy between batches, never mid-batch, and build from a clean tree. `make build`, `scp` both binaries to `<install>/bin/.new/`, compare `sha256sum` both sides, then in one `set -e` ssh call recheck idle (`lane-1 … idle` and `^0 queued`, else `exit 3`), `systemctl stop`, swap, `git checkout -q <sha>`, `systemctl start`, check `/v1/status`. Claim the lane host's build resource first and release after. Tell clients not to use a new flag until you confirm deployed — an older daemon refuses unknown fields.
- **[gotcha]** Before restarting an installed daemon, check `systemctl show automaticumd -p TimeoutStopUSec -p SendSIGKILL`: a unit copied from the old example has 2 minutes and SIGKILL, which kills a run in flight and records it `ABORTED(daemon restart)`. A run held by `run pause` or `batch pause` also ends ABORTED at a restart. Safe sequence: `lane drain`, `automaticum wait idle --until free`, restart, `lane resume`.
- **[gotcha]** `automaticumd` has no version flag (`--version` gives `flag provided but not defined`). Use `automaticum version`; the build a run recorded is `provenance.automaticum` in `run show -json <id>`.
- **[pattern]** Go edited by a python heredoc is not formatted, and neither `go build` nor `make test` flags it. Run `gofmt -l internal cmd` before staging (struct-field alignment is the usual hit), then `gofmt -w` the file and add it again.
- **[convention]** A new `internal/<pkg>` runs in `make test` only once it is on the Makefile's test line (and in CLAUDE.md's `make test` list); a package left out stays green by never running.
- **[gotcha]** In daemon tests, `waitFinished` returning does not mean the notifications went out: `notifyEnd` runs after the run's end is visible. Use `waitFor` on the count before asserting on captured notifications. A new notification kind also changes exact counts in existing tests such as `TestGates`.
