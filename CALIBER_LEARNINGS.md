- **[pattern]** When you change an exported function's signature, `go build` does not compile `_test.go` files, so it reports only the production callers. Run `go vet ./internal/<pkg>` (it type-checks the tests) on each package until it prints nothing about `not enough arguments`. Then run `go build ./internal/...` for the dependants (`detect` → `ingest` → `daemon`, `export`) and `CGO_ENABLED=0 go vet ./cmd/automaticum`. Where outside packages call the function and do not need the new argument, keep a thin wrapper with the old signature.
- **[gotcha]** `go build ./...` from the repo root fails with `no required module provides package github.com/northwind/...`. The cause is `tasks/train-ml/*/checker/main.go`, whose imports resolve only inside each task's own seed module, so the failure is not your change. Compile-check the libraries with `go build ./internal/...` (cgo on). On the host, linking `cmd/automaticum` with cgo on fails in gcc, because the native archives exist only in the build containers. Check it with `CGO_ENABLED=0 go build -o /dev/null ./cmd/automaticum`. - **[pattern]** Lane images are built by the CLI without a daemon: `automaticum image build -config examples/config -repo "$PWD" base go rust cpp dotnet typescript`. List `base` first, because the layers and `tb2-*` copy from it. - **[gotcha]** If you edit Go source with `python3 - <<'EOF'` and a plain `'''...'''` string, a Go escape written as `\n` becomes a real newline in the file. That splits the Go string literal, and the next `go vet` fails with no clear message. Write `\\n` inside the Python string, or use `r'''...'''`. Existing struct fields are gofmt-aligned with runs of spaces, so an exact `assert old in s` on a field line fails. Check the real line with `grep -n ... | cat -A` and match it with a regex that allows ` +` between name and type, or anchor on a neighbouring line that has no alignment. If a script asserts partway, its own file is not written, but edits made by earlier steps are. Run `go vet` to see what state you are in. Run `gofmt -l` right after each scripted edit, and look at broken lines with `sed -n A,Bp file | cat -A`. Adding fields to a struct changes gofmt's field alignment, so `gofmt -l` listing the file after a scripted edit usually just means it needs `gofmt -w`. When you append a test with `cat >> file_test.go <<'EOF'`, check its imports first (`head -30 file_test.go | grep '"slices"'`). An import added with `sed` lands out of order, so run `gofmt -w` on the file afterwards.
