# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** Read a finished run's wire capture with `timeout 60 ./bin/automaticum logs <id> --wire`, or with `curl -s http://127.0.0.1:7411/v1/runs/<id>/blobs/wire`. Each line has `seq`, `url`, `status`, `t_start`, `request_body` and `response_body`. Leave out the `*_body` and `*_headers` fields when printing. Every run has one failed request: `POST /api/engine?...&endpoint=tokenize` answers 404 with `model ... is not loaded; only a running model has an engine to call`. The SDK probes before the first generation has loaded the model, and its next probe gets 200. It is harmless and not a fault of the agent.
- **[gotcha]** The directory of a run in flight exists only while that run runs: `<data root>/m2/runs/<run id>/{job,out,workspace}`, and the live wire is `out/wire.jsonl` there. List that directory instead of using `find /`. Once the run ends, read its material through the daemon.
- **[gotcha]** `automaticum run tail <id>` never ends and replays the run's stream from the start. It carries only `"k":"event"` lines, not the runner's notes. Capture it bounded to a file on persistent disk, then grep the file: `timeout 8 ./bin/automaticum run tail <id> > <work>/tail.jsonl; true`. Read the runner's notes with `automaticum logs <id>`. A plain grep for `holding` also matches the model's reasoning.
- **[pattern]** A model's control tokens come from its tokenizer, never from a hand list. Call `POST <base_url>/api/show` with `{"model":"<tag>","verbose":true}` and take the tokens with `token_type` 3. `<think>` and `<tool_call>` are type 4. The answer is about 8 MB, so write it to persistent disk, never /tmp, and delete it afterwards. In code, use `run.ControlTokens`.
- **[gotcha]** On the host, `go build ./...` and plain `go run ./cmd/automaticum` fail at link (cgo store), and `cmd/automaticumd` cannot be built on the host at all. Iterate with `CGO_ENABLED=0 go vet|test` on the packages, and with `CGO_ENABLED=0 go run ./cmd/automaticum detect --self-test`. Leave full builds to `make build`, writing its log under the work directory. A control in `internal/detect/controls.go` lists every detector that fires on it: write the text, read the `FIRED` column, then decide. Filler in tests must not be periodic.
- **[env]** Every command that talks to the daemon needs `AUTOMATICUM_CONFIG=<data dir>/config` (the path is in `docs/local/`). Without it, the command answers `no configuration directory`. Use the built `./bin/automaticum`, not `go run`. `cd` into the data directory resets the shell's working directory, so use absolute paths.
- **[pattern]** A model's control tokens come from its tokenizer, never from a hand list. Call `POST <base_url>/api/show` with `{"model":"<tag>","verbose":true}` and take the tokens in `model_info.tokenizer.ggml.tokens` whose `tokenizer.ggml.token_type` is 3. `<think>` and `<tool_call>` are type 4, not control tokens. The answer is about 8 MB, so write it to persistent disk, never /tmp, and delete it afterwards. In code, use `run.ControlTokens`. It loads nothing on the server.
- **[pattern]** A rebuilt `bin/automaticumd` is not the daemon that is running. Restart only while `automaticum status` shows the lane idle with nothing queued or paused. The sequence: `make build SPIKE_ROOT=<dir> > <work>/build.log 2>&1`, take the PID from `ss -ltnpH 'sport = :7411'`, `kill -TERM` it and wait until `kill -0` fails, start `nohup ./bin/automaticumd --config $AUTOMATICUM_CONFIG >> <work>/automaticumd.log 2>&1 &`, then poll `curl -sf http://127.0.0.1:7411/v1/status`. Foreground `sleep` is blocked, so wait in loops with `timeout 0.5 tail -f /dev/null`.
- **[pattern]** After any change to ingest (a new metric, finding or verdict rule), deploy the daemon and run `automaticum reanalyse`. With no flags it analyses every run again (about 50 runs in a few seconds). Use `--run <id>` or `--batch <b>` to limit it. Until runs are analysed again, `compare` treats a missing metric as "analysed before the feature existed". For the cap audit, that makes the arm `UNVERIFIED`.
- **[gotcha]** On the host, `go build ./...` and plain `go run ./cmd/automaticum` fail at link (cgo store), and `cmd/automaticumd` cannot be built on the host at all. Iterate with `CGO_ENABLED=0 go vet|test` on the packages, and with `CGO_ENABLED=0 go run ./cmd/automaticum detect --self-test`. Leave full builds to `make build`, with its log under the work directory. A control in `internal/detect/controls.go` lists every detector that fires on it: write the text, read the `FIRED` column, then decide. Filler in tests must not be periodic.
- **[gotcha]** `human.Count` takes an `int64`. Metric values and `stats.Summary` fields are `float64`, so pass `human.Count(int64(x))`. Otherwise `CGO_ENABLED=0 go vet ./cmd/automaticum` fails.
- **[pattern]** To find where a number in a spec came from, run `git log --format='%h %ad %s' --date=short -S"<phrase>" -- docs/specs/<file>.md`, then `git show -s --format=%B <hash>`. Commit messages name the source: omnimergekit's code, or a session's review. When the source is another project's code that is not in the repo, mail that project's session (omnimergekit is `backup_models@solidpc`) for the file, the commit and a fixture set. Number your questions so each one can be confirmed or corrected. Build with the spec's numbers, labelled as taken from that code, and compare once the code arrives. Nothing of theirs goes into the public repo, only the numbers.
- **[pattern]** Edit Go and specs with a `python3` replace script. `assert old in s` on each replacement, or print `MISSING` for it, so that a stale anchor is not skipped silently. Run `gofmt -l internal cmd` and `go vet` of the touched packages in the same call.
- **[correction]** When an Ollama or xOllama server can be asked or told something, automaticum asks or does it itself. It does not ask the owner to do it.
- **[convention]** A metric shows in `compare` without `--all` only when it is in `mainMetrics` in `cmd/automaticum/compare_cmds.go`. A counting metric that is absent from runs where nothing happened needs its prefix in `counter` in `internal/daemon/compare.go`. In `store.Run`, the SDK build is the field `Harness`. `SDKRelease` exists only in the API views. A new ingest finding must also be added to the `owned` map in `internal/ingest/analyse.go`, or `reanalyse` will not replace its old findings.
- **[gotcha]** Read a finished run's wire capture with `timeout 60 ./bin/automaticum logs <id> --wire`, or with `curl -s http://127.0.0.1:7411/v1/runs/<id>/blobs/wire`. Each line has `seq`, `url`, `status`, `t_start`, `request_body` and `response_body`. Leave out the `*_body` and `*_headers` fields when printing. The agent's requests are the `/api/chat` lines whose request has `tools`. The output limit they send is `options.num_predict` (and `max_output_tokens`). The last NDJSON line of `response_body` has `done_reason`, `eval_count` and `think_budget_tokens`. Every run has one failed request: `POST /api/engine?...&endpoint=tokenize` answers 404 while the model is not loaded yet, and the SDK's next probe gets 200. That 404 costs at most one unbooked side call. It is not a fault of the agent.
- **[gotcha]** The Caliber pre-commit hook runs on every `git commit` and prints `caliber: refreshing docs...`. Commit with `git add -A . ':!.wolf/cron-state.json'`, and run the public-repo name scan over `git ls-files` (excluding `CALIBER_LEARNINGS.md` and `package-lock.json`) before you commit.
- **[env]** Every command that talks to the daemon needs `AUTOMATICUM_CONFIG=<data dir>/config` (the path is in `docs/local/`). Without it, the command answers `no configuration directory`. Use the built `./bin/automaticum`, not `go run`. A `cd` into the data directory resets the shell's working directory, so use absolute paths.
- **[convention]** A new command in `cmd/automaticum` is one entry in the `cmds` map of `main.go` under `"<noun> <verb>"`, plus one line of usage. One-word commands go in the `one` map. Parse flags with `args = parse(fs, args)`, not `fs.Parse(args)`, because Go's `flag` stops at the first argument that is not a flag. `cmd/automaticum` is one package that already has helpers (`short`, `sorted`, `table()`, `printJSON`, `letter`, `addClient`). Run `grep -n '^func <name>' cmd/automaticum/*.go` before you add one, because a second copy fails vet with `redeclared`.
- **[gotcha]** xOllama's `/api/show` lists a tag's parameters in an order that changes between releases (0.40.3-xollama.3 against .4), with the same values. Never hash or compare the raw text. Use `run.ParametersKey`, which sorts the lines. Otherwise `compare` shows `CHANGED BETWEEN RUNS` for `tag parameters`, and the before/after probe can make a run `INVALID`. A `CHANGED BETWEEN RUNS` row is real only when the values differ.
- **[pattern]** Compare runs with `automaticum compare <batch> [<batch> ...]`. Use `--all` for every metric and `--json` for the numbers. It needs the running daemon on the current build. A batch started with `--idempotency-key <key>` is named `k-<key>`. Queue several arms as one interleaved batch with `run start --arm A --arm B --task <suite>/<task> -n <n>`, and check it with `--dry-run` first. Read `what differs between A and B` and the basis section before any number. Both must show only the variable under test. `automaticum basis diff <batch[/arm]> <batch[/arm]>` lists exactly the 020 §5 facts that differ. `basis show <batch> [--arm A]` lists every fact and marks `MIXED` where a group's own runs differ (for example, a server upgrade in the middle of a batch).
- **[convention]** Detector versions of ingest's own findings live in the `Versions` map in `internal/ingest/analyse.go`. Never put a literal `DetectorVersion: "1"` there. Whenever a version in that map changes, or a detector is added, bump `AnalysisVersion` and run `automaticum reanalyse`. Every run records it as the metric `analysis.version`, and the basis reads which detectors a run was analysed with from that metric.

- **[convention]** When you port a rule from another project's code (for example omnimergekit's cap audit), the spec section must say which parts are theirs, with the file and the commit ("checked against ... at `01f5ed3`"). It must label the parts that are automaticum's own as automaticum's own. Port their logic exactly as written, including what a row is and whether counts are of requests or of tasks. Defer the parts that belong to another kind of suite to the milestone of that suite, with their fixture file named.
- **[pattern]** On "chk mail": call `mailbox-list` (load it via ToolSearch `select:mcp__pgvector__mailbox-list`), then `mailbox-read` with the ids it prints. Act on the message, then `mailbox-ack` the id with a note that says what was ported and what was deferred.
