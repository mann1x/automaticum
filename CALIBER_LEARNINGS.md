# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** `RunView.Verdict` (what `g.waitFinished` returns) is a plain string, while `store.Run.Verdict` is `store.Verdict`. In daemon tests compare with `string(store.Pass)`, or the test package fails to build with `mismatched types`.
- **[gotcha]** `make test` covers only `internal/store/blob` of the store, so a change in `internal/store/duck` (a new `RunFilter` field, say) stays untested there. The daemon rig's `memState` has its own filter too. Add the case to `duck_test.go` and run `make test-store SPIKE_ROOT=<dir>` under a host claim (`claude-hooks-res run <host>:shared -r "..." -- make test-store ...`), with the log under `<dir>/work/`, not `/tmp`. `SPIKE_ROOT` is in neither the repo nor `docs/local/`: look in the shared memory for an earlier `make build SPIKE_ROOT=` command, and never write it into a tracked file.
- **[env]** A full `make test` takes close to 5 minutes, nearly all of it `internal/legacyimport` under `-race`, so pass a Bash timeout of 600000 ms. While iterating use `go test -race -count=1 -run <Test> ./internal/daemon/`, and `CGO_ENABLED=0 go test` for `cmd/automaticum`.
- **[gotcha]** When a script rewrites rows of a markdown table in `docs/audit/` or `docs/specs/`, never `split('|')`: item cells hold escaped pipes (`report run\|batch`), and a plain split silently cuts the row while the replacement count still looks right. Split on unescaped pipes (`re.split(r'(?<!\\)\|', line)`) and grep the changed rows afterwards. A literal pipe written into a table cell must be `\|`.
- **[gotcha]** The OpenWolf post-write hook adds an anatomy entry and a memory row only for files made with the Write tool, and its description is a stub such as `Struct: written`. Files made with a Bash heredoc (`cat > x_test.go`) get no entry at all. After a batch of new files, check each with `grep -q` in `.wolf/anatomy.md`, add the missing ones and replace the stubs with real descriptions.
- **[pattern]** Stage a commit with `git add -A -- . ':!.wolf/cron-state.json' ':!.wolf/suggestions.json'`: those two are runtime state that changes on its own and stays out of commits, while `anatomy.md`, `buglog.json`, `cerebrum.md` and `memory.md` go in.
- **[gotcha]** When a Python script rewrites `.wolf/buglog.json` (or any JSON state file), plain `json.dump(d, f, indent=2)` escapes non-ASCII (`§`→`\u00a7`) and drops the trailing newline, rewriting old entries in the diff. Use `open(p,'w').write(json.dumps(d, indent=2, ensure_ascii=False) + '\n')`, then check `git diff --cached .wolf/buglog.json | grep -c '^-[^-]'` prints 0. The committed file can also end up without its trailing newline, so check with `tail -c 1`; a count of 1 whose only removed line is `-}` is just that newline coming back, and is harmless.
- **[pattern]** To read what the SDK really does, go to the bundles, not the types: `dist/types` under `@cerebriline/*` had no match for retry options, while the behaviour sits in the minified `dist/index.js` of `llms` and `agents`. Slice around a stable string with `python3 -I -c` (for retries `provider_error_retry`, for the error lists the literal `ECONNREFUSED`) and pipe to `cut -c`, since each bundle is effectively one line. Minified names (`_k`, `Mk`, `lW`) belong to one release, so find them by content again on each new SDK and recheck anything ported from them, such as `run.Fault`.
- **[pattern]** Before building an audit row, check its evidence and check whether the SDK already does the work. The audit's `050 §4` infrastructure-retry row pointed at a `retryable:false` that belongs to the plan-mode tool, not to model requests, and the SDK already retries such errors itself; the real gap was only the verdict. Correct the evidence in the row when you close it.
- **[gotcha]** The daemon tests' `memState` embeds a nil `store.State`, so a handler that calls a store method `memState` doesn't override compiles and then panics at runtime. When a new handler uses another store method (e.g. `ToolCalls`), add that method to `memState` in `daemon_test.go` first. Its `ListRuns` filter also has its own field list, which ignores `RunFilter.Since`, so a window on `Since` is not exercised in the rig.
- **[gotcha]** `Daemon.armFor` takes `d.mu` itself, so calling it (or a helper built on it) while holding `d.mu` deadlocks. In the scheduler loop, unlock first and take the lock again afterwards, then recheck `d.flights`, because the lane may have been taken in between.
- **[gotcha]** `encoding/json` decodes into an existing map by merging keys, so a test polling `g.call(..., &h)` into one struct keeps stale keys and reports impossible states (two lane states in a one-lane rig). Decode into a fresh value on every poll, and prefer a deterministic read such as `GET /v1/heartbeat?now=1` over racing a short ticker.
- **[convention]** A metric name must never carry free text (a sentence, count, or quoted tool name) — every run would get its own and none would pool in `compare`. Key by stable fields: notices are `notices.<type>.<kind>.<phase>`, else `notices.<reason>`, else `notices.<type>` (D116). Count an event announced at start and end once, at phase `completed`. The name also sets how a value prints: `human.Metric` reads the last dotted segment (`_ms`, `_s`, `tok_s`, containing `share`, `available`), so name a 0–1 ratio `*_share` to get a percentage.
- **[gotcha]** `.claude/rules/runner-protocol.md` writes out the current `AnalysisVersion`. When you bump it in `internal/ingest/analyse.go`, update that rule and the dated note in 070 §2. Stored runs keep their old metrics until `automaticum reanalyse` runs on the lane host after the deploy. A new ingest detector needs all of: an entry in `owned` (otherwise `reanalyse` keeps its old findings beside the new ones), an entry in `Versions` (otherwise the basis does not name it), and the `AnalysisVersion` bump.
- **[convention]** Before adding a key to existing `task.toml` files, check whether the value can be derived from a stored blob at ingest. A new key changes the task's hash and so its basis, while a derivation at ingest leaves the tasks alone and `reanalyse` gives it to earlier runs too.
- **[gotcha]** In `internal/run` tests, `fakeEngine.Run` never executes an oracle's `command`: any container without the label `automaticum=run` is treated as the oracle, which reads `answer.txt` under `/w` and prints `RESULT ok` or `RESULT wrong`. To get two oracles with different results in a test, vary their `expect_pattern`, not their commands.
- **[gotcha]** When a script rewrites rows of a markdown table in `docs/audit/` or `docs/specs/`, never `split('|')`: item cells hold escaped pipes (`report run\|batch`), and a plain split silently cuts the row while the replacement count still looks right. Split on unescaped pipes (`re.split(r'(?<!\\)\|', line)`) and grep the changed rows afterwards. A literal pipe written into a table cell must be `\|`, inside backticks too.
- **[pattern]** To list what is still unbuilt in one spec, grep the audit rows instead of reading the file: `grep -n "^| 070" docs/audit/2026-11-01-spec-vs-code.md | grep -E "NOT BUILT|PARTIAL" | cut -c1-210`. A row closed by a change gets its status (`BUILT`, `PARTIAL`, or `OPEN` with the `O` id) and its evidence updated in the same commit.
- **[pattern]** To see the metric names ingest writes before naming a new one, run `grep -on 'm("[a-z_.]*"' internal/ingest/analyse.go | sed 's/.*m("//; s/"$//' | sort -u`. Names ending in a dot (`notices.`, `guard_trips.`, `derived.`) are prefixes completed at runtime.
- **[gotcha]** In the daemon, `notifyEnd` runs after a run's end is visible and after the lane is free. In tests, `waitFinished` returning does not mean the notifications went out: use `waitFor` on the count before asserting on captured notifications. A new notification kind also changes exact counts in existing tests such as `TestGates`. In code, state that must hold for the lane's next run (a quarantine, say) cannot be set in `notifyEnd`: the scheduler can start the next run first. Set it in the run's goroutine before `delete(d.flights, ...)`.
- **[convention]** Everything in `Arm`'s resolved JSON goes into its id, because `hash()` hashes `Resolved()`. A new arm field that is placement rather than what is measured (like `requires`) must be `omitempty` and also deleted in `hash()`, or every existing arm changes identity. Pin it with a test comparing the ids of two arms, as `TestRequiresNotIdentity` and `TestStopOnIdentity` do.
- **[convention]** An Open item the owner drops does not become a `D` row: it goes into `docs/specs/decisions.md` section 5 (Not adopted) with its O id and reason, and its audit rows get the status `NOT ADOPTED`. After closing O items, find every marker with `grep -n "O3[1-9]" docs/specs/*.md` (with the ids at hand), since they also sit in 020, 050, 065, 070 and 090, and in the closed-items list of `decisions.md`.
- **[gotcha]** A multi-file python heredoc followed by `; echo ok` or a new line hides a failure: the traceback scrolls past, `ok` still prints, and the files written before the failing step stay changed. Chain with `&&`, write each file with an `assert a in s` on the anchor first, and after a failure rerun only the steps that did not apply, since the earlier replacements are already in place.
- **[gotcha]** `.wolf/cerebrum.md` ends with `## Decision Log` and has no trailing newline, so `s.index('\n', i)` on its last line raises `ValueError` and a plain `>>` glues the new text onto that line. Append a decision with `printf '\n- ...\n' >> .wolf/cerebrum.md`, then `tail -2` to check.
- **[gotcha]** The daemon tests' `memState` embeds a nil `store.State`, so a handler that calls a store method `memState` doesn't override compiles and then panics at runtime. When a new handler uses another store method (e.g. `ToolCalls`), add that method to `memState` first. Its `ListRuns` filter also has its own field list, which ignores `RunFilter.Since`, so a window on `Since` is not exercised in the rig. The rig's `memBlobs` is a read-only map: a test whose handler stores blobs needs a store with a `Put` and a lock, as `syncBlobs` in `rescore_test.go`.
- **[env]** A full `make test` takes close to 5 minutes, nearly all of it `internal/legacyimport` under `-race`, so pass a Bash timeout of 600000 ms. While iterating use `go test -race -count=1 -run <Test> ./internal/daemon/`, and `CGO_ENABLED=0 go test` for `cmd/automaticum`. `make test` does not compile `cmd/automaticumd`, so after changing the daemon's wiring there run `CGO_ENABLED=1 go vet ./cmd/automaticumd/`.
- **[pattern]** Go edited by a python heredoc is not formatted, and neither `go build` nor `go vet` complains: a new field beside aligned struct fields leaves the file unformatted. Run `gofmt -l internal cmd` after such edits and `gofmt -w` what it lists.
- **[gotcha]** The OpenWolf post-write hook adds an anatomy entry and a memory row only for files made with the Write tool, and its description is a stub such as `Struct: written`. Files made with a Bash heredoc (`cat > x_test.go`) get no entry at all. After a batch of new files, run `grep -n '<file>' .wolf/anatomy.md` for each: replace a stub with the real description rather than adding a line beside it, which leaves the file listed twice, and add the missing ones.
- **[convention]** A mutating route takes its dry run as the query parameter, not a body field: the handler checks `dryRun(r)` (`?dry_run=1`), and the CLI uses `addMutation(fs)`, `m.on(c, path)` and `m.dryNote()`, which also bring `--idempotency-key`. Read these helpers before adding a new mutating command.
- **[gotcha]** A new map in the daemon's `control` struct must be initialised in both the default literal and the nil checks of the loader. A `control.json` written by an older daemon has no such key, so a map set up in only one place panics with an assignment to a nil map after a restart.
