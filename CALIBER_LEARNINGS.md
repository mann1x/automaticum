- **[fix]** Deploying to the lane host: `scp` onto the running `bin/automaticumd` fails with `Text file busy`, and the same `scp` silently overwrote `bin/automaticum` with no copy to go back to. Copy each binary to `bin/<name>.new` and compare sha256 on both ends, then do the swap in one `set -e` ssh script. The steps are in the `learned-lane-host-deploy` skill.
- **[gotcha]** The daemon has no notification hook for tests: `d.notified` is a `map[string]bool` of waiting runs, not a callback. To assert on a notification, set `g.d.Log = slog.New(slog.NewTextHandler(&logs, nil))` with the `lockedBuffer` from `mutate_test.go` and look for `msg="<kind> <status>"`, since every notification is logged. The other way is `Notify.Command` writing to a file, as in `TestNotifyCommand`. A new notification kind must also go into `config.NotifyEvents`, or `[notify] events` refuses it. Then update the comment in `examples/config/automaticum.toml` and the kind list in 050 §2.
- **[pattern]** A new daemon setting or background job touches six places. (1) A field in `config.Daemon` (`internal/config/local.go`) with its validation. (2) A refusal case in the `cases` table of `config_test.go`. (3) A commented line in `examples/config/automaticum.toml`. (4) The `automaticum.toml` line in 030. (5) For a loop: start it in `Serve` beside `go d.heartbeatLoop(canary)` and give the `Daemon` an `<X>Every time.Duration` field, so the test can tick in milliseconds. (6) For a new dependency: wire it in `cmd/automaticumd/main.go`, which `make test` does not compile.
- **[pattern]** The rows of the spec-vs-code audit (`docs/audit/2026-11-01-spec-vs-code.md`) marked NOT BUILT or PARTIAL were partly grep guesses. A re-check found 17 already built and 20 with wrong evidence. Before building an audit gap, verify it against the code, or hand a read-only re-check to a subagent. To update rows, use a script that splits each row on unescaped `|`. It asserts the first cell starts with the expected spec § for that line number, then sets the status and evidence cells. Line numbers drift, and the assert catches a wrong row.
- **[pattern]** Go code edited by a python heredoc, by a `cat > f.go` heredoc or even by the Write tool is not formatted, and neither `go build` nor `go vet` complains. For example, a new field placed beside aligned struct fields leaves the file unformatted. After such edits, run `gofmt -l internal cmd` and then `gofmt -w` on each file it lists. When a scripted edit uses a new package, add the import with `grep -q '^\t"path"' f.go || sed -i '0,/^import (/s//import (\n\t"path"/' f.go`, then let `gofmt -w` put the imports in order.
- **[gotcha]** The OpenWolf post-write hook adds an anatomy entry and a memory row only for files made with the Write tool, and the description it writes is a stub such as `Struct: written`. Files made with a Bash heredoc (`cat > x_test.go`) get no entry at all. After a batch of new files, run `grep -n '<file>' .wolf/anatomy.md` for each one and add the missing entries. Where there is a stub, replace it with the real description: adding a second line beside it lists the file twice.
- **[convention]** A mutating route takes its dry run as the query parameter `?dry_run=1`, not as a body field: the handler checks `dryRun(r)`. The CLI uses `addMutation(fs)`, `m.on(c, path)` and `m.dryNote()`, which also bring `--idempotency-key`. Every request also carries the `Automaticum-Client` header from `client.open` (`--client`, default `<user>@<host>`). Read these helpers before adding a new mutating command or request header.
- **[gotcha]** A new map in the daemon's `control` struct must be initialised in two places: the default literal and the loader's nil checks. A `control.json` written by an older daemon has no such key. A map set up in only one place then panics with an assignment to a nil map after a restart.
- **[gotcha]** `go build ./...` from the repo root always reports `no required module provides package github.com/northwind/...`. That comes from the task checkers under `tasks/train-ml/*/checker`, which import their task's own packages, and the noise can hide a real error. Build only the packages you changed (`go build ./internal/daemon/`, `CGO_ENABLED=0 go vet ./cmd/automaticum`). A bare `go build ./cmd/automaticum` writes an `automaticum` ELF binary at the repo root, which `git add -A` then stages. Prefer `go vet` or `go build -o /dev/null`, and check `git status --short` for a stray `A  automaticum` before committing.
- **[pattern]** Check for private strings before every commit of this public repo. First check `test -n "$P"`: an empty pattern matches every line. Then run `git ls-files -z | grep -zv -e CALIBER_LEARNINGS.md -e package-lock.json -e '^tasks/train-sh/' | xargs -0 grep -IlniE "$P"` and `git diff --cached | grep '^+' | grep -niE "$P"`. A clean result is empty output. `xargs` exits 123 and `grep` exits 1 when nothing matches, so read the printed list and do not treat those exit codes as failures.
- **[pattern]** Thresholds ported from the SDK hold per release, not for the SDK as a whole. For example, the reasoning-loop guard changed at 4.100.258 while the code still cited 4.100.250/251. Before trusting or extending a port, loop over every pinned build's `node_modules/@cerebriline/agents/dist/index.js` (or `core/dist/index.js`). Extract the default config object with a regex (e.g. `=\{minChars:4000,window:60[^}]*\}`) and print a sha1 of the class body. Equal hashes mean the same code, and the first build whose hash differs is where to read. When a replay does not confirm a guard trip, read the SDK's notice metadata for that turn (`kind`, `period`, `cycles`, `sample`) before assuming the detector is wrong: it names the rule the port is missing.
- **[pattern]** Fixtures do not show what a real stream does. To try analysis, a detector or a view on a real run, add a temporary env-gated test such as `internal/ingest/zz_tmp_test.go` or `cmd/automaticum/zz_tmp_test.go`. The test:
  - skips when `REAL_EVENTS` is empty;
  - reads the events (`ReadEvents`);
  - runs `Analyse(&store.Run{ID: "x", Harness: os.Getenv("REAL_SDK")}, ev, nil)`, the detector or the view's function, and prints the result.
  Run it with `-count=1 -v`: without `-v` a passing test prints nothing. When the rules depend on the release, compare under two `REAL_SDK` values. Delete it with `rm` on the same command line. Fetch the stream read-only from the lane host with `automaticum logs <run> --events -json`. To turn a client's run into a positive control, have the temporary test write `ev.Calls` as JSON into `internal/detect/testdata/` (`json.Unmarshal` back into `[]detect.Call` matches lowercase keys), and check that file for private strings. To check a detector against a client's own scan, run both on the same runs and compare the counts.
- **[env]** One run's event stream can exceed 100 MB: a 30-minute run gave 350,000 lines and 124 MB. The session scratchpad is under `/tmp`, which is tmpfs on this host. Download streams to a scratch directory on persistent disk outside the repo, never to `/tmp`.
- **[gotcha]** Detector options reach more than ingest. `detect.Block` is called from `internal/ingest` (`DetectOptions`, `blockOptions`), the daemon's detect handlers, `automaticum detect` and `export.Spans`. For any option that depends on the run, run `grep -rn "detect.Options{" --include=*.go internal cmd | grep -v _test` and pass the option at every site. Otherwise the views disagree with the stored findings. The same applies to the daemon's `compareView`: `compare`, `basis show` and the cell view all call it (`grep -n 'compareView(' internal/daemon/*.go`), so a new parameter must be passed at each call.
- **[gotcha]** `TestRunImported` asserts an exact `len(m.findings)`, so a new detector that fires on its stream fails it even when the detector is right. `store.Finding` prints `Evidence` as decimal bytes, which floods the failure output. Pull out `Detector`, `Turn` and `Count` with a small regex over the output instead of reading it. A rule that groups calls by turn must treat `Turn: 0` as an unknown turn (an imported stream without iterations), not as one shared turn.

- **[pattern]** Never write "the SDK emits no event for X" based on one run's stream. That claim once went into 070 and the audit from a run with the change protocol off, while the bundle does have `atomic_transaction`, `atomic_empty_attempt` and `atomic_plan` notices. - **[gotcha]** A stored run's event stream (`logs <run> --events -json`, or a scratch `.jsonl`) wraps every SDK event twice. Lines look like `{"t":...,"k":"event","event":{"type":"agent_event","payload":{"event":{...}}}}`, mixed with `"k":"runner"` notes. Counting `e["type"]` or `e["event"]["type"]` therefore only gives `agent_event` and `chunk`. Read `e["event"]["payload"]["event"]`: the notice kind is in `.metadata.kind` and the phase in `.metadata.phase`. The runner's own notes (e.g. `guard_trip`) arrive as separate `k:runner` lines right after the SDK's notice of the same trip. A timeline or count that reads both shows each trip twice unless it merges them.
- **[gotcha]** `config.LoadArm` returns the arm already merged with its parents, so `Extends` on the result is empty. Code that reads `arm.Extends` to find the parent always sees "no parent" (`TestArmBaseline` failed on this). Use `config.ArmParent(dir, name)`, which follows the files' `extends` chain. In daemon tests, `newRig` sets `Local.Dir` to `examples/config`, so `config.LoadArm(examplesConfig(t)+"/arms", "stub-sdk-4.100.266")` gives a real arm with a parent chain (`stub-sdk-*` to `stub` to `base`).

When you pipe the output through `grep -v "^ok\|cached"`, read the result from `echo rc=${PIPESTATUS[0]}`, since the pipe's own exit status is grep's.

- **[gotcha]** `config.LoadLocal` refuses a directory without a lane and an endpoint (`no lanes: lanes/*.toml is empty`). - **[gotcha]** Before adding an exported helper to a package, run `grep -n 'func <Name>' internal/<pkg>/*.go`. For example, `internal/ingest` already has `ErrorClass` (the 070 §2 tool-error class, stored on `store.ToolCall.ErrorClass`). A second one fails the build with a redeclaration and duplicates a definition. Likewise, a read-only rerun of the whole analysis is `ingest.Load` + `ingest.Derive` (`ingest.Run` is those two plus the write). Reuse them instead of reading a run's blobs again.
- **[gotcha]** A python heredoc that writes Go backtick strings removes one level of backslashes. In a non-raw `'''…'''` python string, `\\\\n` lands in the Go file as `\\n`, a literal backslash-backslash-n, and the test input silently changes. For a Go raw string holding JSON's `\n`, write `\\n` in python, or use `r'''…'''` and write it exactly as in Go. Print the edited line with `sed -n <N>p` before running the tests.
- **[pattern]** In daemon tests, give a stored run an event stream with `g.d.Blobs = memBlobs{"h": stream}` plus `store.BlobRef{RunID: id, Kind: "events", Hash: blob.Hash("h")}` appended to `g.state.refs`. The field is `blob.Hash`, not string, so import `internal/store/blob`. Create the run itself with `putRun`. A run in flight needs two things:
  - `g.d.flights = map[string]*flight{"lane-1": {runID: ..., started: ..., lines: ...}}`, set under `g.d.mu`;
  - a `g.state.Enqueue` of its queue item.
  Event lines need the double wrapping `{"k":"event","event":{"type":"agent_event","payload":{"event":...}}}`. Without a wire capture, `swallowed_argument` learns argument names only from the run's own calls, so the fixture needs one call that did pass the argument.
