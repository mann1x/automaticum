# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[pattern]** A twin arm (same engine, template, sampler, guards and SDK; only the weights differ) is a small file. It `extends` the floor arm and sets a new `endpoint` name on the same `base_url`, so its runs never pool with the floor's, plus `[model] model = <new catalogue tag>`. It also needs a `models/<tag>.toml` entry. On linux-gpu-1, `arm validate` answers `names endpoint "...", which this installation does not have`; that is expected, so use `arm diff <previous twin> <new twin>` there (it must show only `endpoint` and `model.model`). The real validation happens on the lane host once the endpoint file exists. Prefer a scratch copy of the deployed repo (`cp -a <repo>/. <work>/twin-check/`). If you `scp` the files straight into the deployed repo, they stay untracked there: remove them before the next `git checkout` on that host, or the checkout of the commit that tracks them stops with an "untracked working tree files would be overwritten" error.
- **[pattern]** Secret scanning runs from the local, untracked `.git/hooks/pre-commit`. It is a `# gitleaks:pre-commit:start` … `# gitleaks:pre-commit:end` block placed after caliber's block, so caliber's autostaged docs get scanned too. It runs `gitleaks git --staged --redact --no-banner -v` and refuses the commit if gitleaks is missing. A fresh clone does not have this block, so add it again. For a false positive (a made-up token constant in a Go test trips `generic-api-key`), add a value allowlist to `.gitleaks.toml`, pinned to its file with `condition = "AND"`. Never allowlist a whole path. Bypass the scan once with `AUTOMATICUM_SKIP_GITLEAKS=1`, and only on purpose. The owner wants the staged scan only: no push-time or CI full-history scan. To test the hook, copy the block into a scratch file with `sed -n '/# gitleaks:pre-commit:start/,/# gitleaks:pre-commit:end/p'`. Then stage a planted `zz-canary.sh`, run `sh <block>`, `git restore --staged` it and delete the canary.

- **[gotcha]** When you rename to a longer name that contains the old one (`run3` → `run3-s400`), chained `sed -e 's/...run3-BF16.../...run3-s400-BF16.../' -e 's/bm889-run3/bm889-run3-s400/g'` replaces the text it already renamed and leaves `run3-s400-s400`. Rename once, with a pattern that cannot match the new name, for example Python `re.sub(r'run3(?!-s400)', 'run3-s400', s)`. Then `grep -c s400-s400` the result before you restart the daemon.
- **[pattern]** Before you tell a client to queue on an endpoint, check what the shared port actually serves. Clients swap GGUFs behind the same port, so the endpoint name proves nothing. Run `curl -s -m5 http://172.17.0.1:<port>/props | python3 -c 'import json,sys,hashlib; d=json.load(sys.stdin); print(d.get("model_path")); print(hashlib.sha256(d["chat_template"].encode()).hexdigest())'`. Compare `model_path` with the arm's weights and the template hash with the floor's. Also run `sha256sum` on the GGUF yourself on the lane host and match it to the client's value. Only then write it into the model entry and mail "confirmed". A server on the wrong weights means its runs pool under the wrong arm.
- **[env]** On linux-gpu-1, `grep` is ugrep. A bounded-repeat pattern such as `grep -o '[^"]\{0,200\}<word>'` over a large session `.jsonl` fails with `error at position N ... exceeds complexity limits`. Use a short `python3` script with `re.finditer` to print the context around a match instead.
- **[gotcha]** `automaticum doctor -arm <arm> -task <task>` refuses `model_tag` and `bind_address` whenever the arm's model server is down, for example while a client's training holds the GPU. That is expected and says nothing about the deploy. Use `doctor -all ... | grep -E 'oracle|harness'` to see the gates the deploy does decide. A green doctor reads `10 pass, 0 refuse, 0 wait, 5 not looked at`. The 5 not looked at (`free`, `gpu_residency`, `gpu_ownership`, `server_log_level`, `expert`) need an agent on the host (milestone 7), so that is normal. `arm validate` takes an arm file under `arms/`; given a name from the model catalogue (`models/`), it answers `no arm "..."`.
- **[correction]** On linux-gpu-1's shared spool disk, "remove anything stale" means only what this project's own sessions created. Never remove other sessions' or projects' directories, however old they are. automaticum's scratch and build caches live under its own work root (`cache/`, `m2/`, `work/`, e.g. old spike binaries in `work/bin`), not on the spool. Prove ownership first: grep this project's session transcripts and `docs/local/hosts.local.md` for the path. A directory another project's session created belongs to that session. - **[gotcha]** A Bash call whose last command is `diff` (files differ), `grep -c`/`grep -q` (no match) or an `awk` pipeline that yields nothing exits non-zero. The tool then reports a FAILURE with empty output, even over ssh, and hides the useful output of the earlier commands. End such chains with `; echo rc=$?`, or put the check in a separate call.
- **[gotcha]** In a Bash call, never `pkill`/`pgrep -f` a pattern that also appears literally in the same command line. It matches the calling shell itself, and the process guard refuses the call. Find the PID in one call with the bracket trick, `P=$(pgrep -f "[s]tub serve -listen 172.17.0.1:7412")`, or with an anchored pattern (`pgrep -f "^../bin/automaticum stub serve"`), and confirm it with `ps -o pid,args -p <pid>`. Then `kill` it in the next call and check with `ps -p <pid> >/dev/null && echo still || echo stopped`. A mistyped PID fails silently with `2>/dev/null` and leaves the stub server running.
- **[pattern]** The lane host keeps ready-made stub scripts under `<install>/work/stub/`. They include `fix-manic.json` (a `custom/manic_miner` PASS in about 9 s), `say-done.json`, `hang.json`, `loop-reasoning.json` and the plan scripts. Use those for a post-deploy smoke instead of writing a new script. Start `nohup ../bin/automaticum stub serve -listen 172.17.0.1:7412 -script ../work/stub/fix-manic.json > ../work/<log> 2>&1 < /dev/null &`, then `run start -arm stub-sdk-4.100.266 -task custom/manic_miner`.
- **[gotcha]** The store keeps a task in two columns, `store.RunFilter.Suite` and `TaskID`, where `TaskID` is the bare id (e.g. `manic_miner`). Every CLI command and API route names a task `suite/task`. Passing `suite/task` straight into `TaskID` matches no finished run and fails silently. Split it with `strings.Cut(t, "/")` wherever a task name reaches a `RunFilter`. The daemon tests' fake store (`memState.ListRuns` in `internal/daemon/daemon_test.go`) must filter exactly like `where()` in `internal/store/duck/duck.go`. When you add or start using a filter field, extend the fake too. Otherwise the tests pass while the real store gives a different answer.
- **[gotcha]** The daemon test rig's fake runner records no resolved arm (`store.Run.Arm` is empty), so in the rig a finished run's arm name from `GET /v1/runs` is `""`. To test code that reads the arm from a record (`view()`, `askedOf()`), call it directly on a hand-built `store.Run` whose `Arm` is the JSON `{"name":"stub"}`. Do not assert on the rig's own finished runs.
- **[gotcha]** When a Python script rewrites `.wolf/buglog.json`, plain `json.dump(d, f, indent=2)` escapes every non-ASCII character (`§` → `\u00a7`, `…` → `\u2026`) and drops the trailing newline, so the staged diff rewrites old entries. Write it with `open(p,'w').write(json.dumps(d, indent=2, ensure_ascii=False) + '\n')`. Then check that `git diff --cached .wolf/buglog.json | grep -c '^-[^-]'` prints 0, meaning the diff only adds lines.
- **[pattern]** Before a commit, also run the private-string check, besides gitleaks. Grep the tracked files (`git ls-files -z | xargs -0 grep -IlniE "$P"`, leaving out `CALIBER_LEARNINGS.md` and lockfiles) and the added lines of `git diff --cached` for private host nicknames, absolute paths and addresses. Here `xargs grep` exiting 123 and `grep` exiting 1 both mean nothing was found, so the tree is clean. Any file name or line it prints must be fixed before you commit. Never write the private pattern list itself into a tracked file.
- **[pattern]** When a client asks for a per-arm gate summary (verdict counts, guard trips, Fisher/Mann-Whitney between arms, basis drift), point them at `automaticum compare -all -batch <floor> -batch <twin>...` before building anything new. It already prints the arm diff, the basis diff (e.g. runner protocol 8 vs 9), verdicts with Wilson intervals, and every metric with its median, range and Mann-Whitney p. `run ls -arm <name>` resolves the arm from the current checkout, so it leaves out runs of an earlier version of that arm (another id); use `-model` or `-arm-id` for those. `run start` prints the batch id on its first line. A run id prefix is not a batch id, and `run show -json <run>` gives a run's batch.
- **[pattern]** To try a new client-side command (one that only calls routes the deployed daemon already serves, such as `GET /v1/runs/{id}/blobs/events`) on real runs before you deploy, run `CGO_ENABLED=0 go build -o <scratch>/am-x ./cmd/automaticum` and `scp` it to `<install>/work/`. Then, in one ssh call, run it with `AUTOMATICUM_CONFIG=<install>/config` against real run or batch ids and `rm` it. This needs no restart and no idle lane, so you can prove the output before you ask for a deploy window.
- **[env]** On linux-gpu-1, `grep` is ugrep. A bounded-repeat pattern such as `grep -o '[^"]\{0,200\}<word>'` over a large session `.jsonl` or a minified SDK `dist/index.js` fails with `error at position N ... exceeds complexity limits`. Use a short `python3` script with `re.finditer` to print the context around a match instead.
- **[gotcha]** In `automaticum logs --events <run>`, the SDK's agent events sit at `.event.payload.event`, on lines with `"k":"event"` and `event.type == "agent_event"`. A filter on a top-level `.event.type == "notice"` matches nothing and prints empty output. `chunk` lines repeat the same events as escaped text, so skip them or you count everything twice. A current SDK notice carries `noticeType`, `message` and `metadata.{kind,phase,cause}`, and usually no `reason`. To survey a field before you key on it, pipe several real runs' `logs --events` into a Python `Counter` over `(noticeType, metadata.kind, metadata.phase)`. Then confirm the values in the SDK's minified `node_modules/@cerebriline/*/dist/index.js` with a Python regex window, because ugrep is too slow on those files.
- **[convention]** A metric name must never carry free text such as a sentence, a count or a quoted tool name. Every run would get metrics of its own and none would pool in `compare`. Key a metric by stable fields: notices are `notices.<type>.<kind>.<phase>`, else `notices.<reason>`, else `notices.<type>` (D116). Read the sentences with `automaticum notices (<run> ... | --batch B) [--key K]`, where the key is the one `compare -all` prints and a shorter key takes every phase under it. Count an event that is announced at start and at end (compaction) once, at phase `completed`, as the SDK does.
- **[gotcha]** `.claude/rules/runner-protocol.md` writes out the current `AnalysisVersion` ("now N"). When you bump it in `internal/ingest/analyse.go`, update that rule as well as the dated note in 070 §2. Runs already stored keep their old metrics until `automaticum reanalyse` runs on the lane host after the deploy.
- **[gotcha]** In `internal/ingest/ingest_test.go`, the `stream` const holds only the runner prefix lines; the full fixture with the agent events is `eventStream()`, which `events(t)` reads. A new test that reads `stream` sees no agent events and fails with zero counts. Adding fixture lines also changes the `ev.Lines` count that `TestReadEvents` expects.
- **[gotcha]** A command that fetches a blob for each run of a batch (`GET /v1/runs?batch=...`, newest first) must leave out runs whose verdict is `SKIPPED`: they never started and have no event stream. Under `-json`, a nil Go slice prints `null`, so initialise the result as `[]T{}` to get `[]`.
- **[pattern]** A change to the daemon or CLI only (no runner protocol, no lane layer, e.g. a new `run start` flag) needs no image rebuild and leaves the basis unchanged. Run `make build`, `scp` both binaries to `<install>/bin/.new/` and compare `sha256sum` on both sides. Then do the swap in one ssh call, `set -e`. First recheck idle (`lane-1 ... idle` and `^0 queued`, else `exit 3`), then `systemctl stop`, move the binaries in, `rmdir .new`, `git checkout -q <sha>`, `systemctl start`, check `/v1/status`, and grep `<cmd> -h` for the new flag. Exit code 3 means "busy again": go back to polling. Tell the client not to use the new flag until you mail "deployed", because an older daemon refuses unknown fields. If the owner approves a second deploy in the same idle window, first mail the client to hold their queue.

- **[pattern]** The pre-commit hooks (caliber refresh, then gitleaks) make `git commit` slow and noisy. Give the Bash call a long timeout (about 400000 ms) and filter the output with `git commit -q -F - <<'EOF' 2>&1 | grep -E "caliber:|leaks|scanned|refused"`. Then print the real exit code with `echo "commit rc=${PIPESTATUS[0]}"` before you `git push`. The grep's own exit code would otherwise hide a refused commit.
- **[pattern]** To prove new library code (export, detectors, ingest) on the real data that sits on the lane host, without a deploy, write a throwaway test file such as `internal/<pkg>/zz_real_test.go`. Its test skips unless an env var (e.g. `ZZ_ROOT`) is set. Run `go test -c -o <scratch>/<pkg>.test ./internal/<pkg>/`, then delete the test file right away so it is never staged. `scp` the binary to `<install>/work/` and run it in one ssh call with `ZZ_ROOT=<data> <install>/work/<pkg>.test -test.run ZZReal -test.v`, then `rm` it. Cross-check its counts against what the deployed analysis stored: `run show -json <run>` gives the `metrics` and `findings` per detector.
- **[pattern]** Before you build a new kind of export span or metric that a client asked for, look at what they already receive. Find their exports on the lane host (`find <disk> -maxdepth 5 -name loop_spans.jsonl`) and count `(source, field, detail)` with a Python `Counter`. A client may be asking for something the export already gives (detector spans were there, but only the guard lines had been read), so you may only need to point them at it.
- **[gotcha]** `.wolf/memory.md` rows use linux-gpu-1's local clock, which is UTC+1, while the lane host and its journal use UTC. Get the time for a row from `date +%H:%M` on linux-gpu-1; do not estimate it or copy a UTC time from the lane host. A daemon's `up for` in `status` counts from your own deploy's restart, so check `systemctl show automaticumd -p NRestarts -p ActiveEnterTimestamp` before you suspect a crash.
