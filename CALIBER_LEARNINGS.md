Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[pattern]** To find where a number in a spec came from, run `git log --format='%h %ad %s' --date=short -S"<phrase>" -- docs/specs/<file>.md`, then `git show -s --format=%B <hash>`. If the source is another project's code that is not in the repo, mail that project's session with numbered questions and a proposal for each. omnimergekit is `backup_models@solidpc`, and the Cerebriline SDK is `ollama@solidpc`. Record the agreed answer in the spec before you build.
- **[pattern]** To learn what the Cerebriline SDK really does, read the installed build under `<data_root>/sdk/<release>/node_modules/@cerebriline/`. `data_root` is in the config's `automaticum.toml`, and `automaticum sdk ls` lists the builds. Grep the `.d.ts` files in `core/dist`, `shared/dist` and `agents/dist` for types. For the logic, cut a window out of the minified bundle with `grep -o '.\{200\}<needle>.\{200\}' agents/dist/index.js`. Don't use `.{0,N}` with alternation, because ugrep rejects it as too complex. Never guess SDK behaviour; confirm it there or on the stub.
- **[correction]** When the runner needs behaviour that the Cline/Cerebriline extension adds on top of the SDK (for example `switch_to_act_mode`, read receipts, a mode switch that continues by itself), port it from the extension source; don't design your own. Read the local Cline checkout (its path is in `docs/local/`, which is untracked) without checking anything out: `git grep -n <symbol> v4.100.251 -- apps/vscode/src` and `git show v4.100.25x:<path>`. Copy tool descriptions and prompts word for word, and confirm the code is the same in every SDK release the repo pins. Name the source file and tag in a comment and in the 040 spec.
- **[convention]** Detector versions of ingest's own findings live in the `Versions` map in `internal/ingest/analyse.go`. Whenever a detector's output, or a metric it reads, changes, bump its version (`WireArmVersion`, `CapHit`, ...) and `AnalysisVersion`, then run `automaticum reanalyse`.
- **[convention]** Metrics that are zero in most runs are hidden where zero (D88) by a prefix check in two places: `quietWhenZero` in `internal/daemon/compare.go` for `compare`, and the `run show` filter in `cmd/automaticum/client_cmds.go`. The prefixes today are `user.` and `mode_switches.`. When you add a new family of rarely non-zero metrics, add its prefix in both places.
- **[gotcha]** `.wolf/anatomy.md` lists files under `## <dir>/` sections, and file names repeat across sections (`cell.go` is in both `internal/config/` and `internal/daemon/`). A global regex replace on a file name fails or hits the wrong entry. Edit by walking the lines and tracking the current `## ` section, or insert before a unique `## <dir>/` anchor. The OpenWolf post-write hook already adds a stub entry for every new file. Replace that line instead of adding a second one, then grep for duplicates.
- **[fix]** Run the runner's Node tests in the pinned image, with a shell glob: `docker run --rm --network none -v $PWD/runner:/runner:ro -w /runner node@sha256:<digest> sh -c 'node --test test/*.test.mjs'`. Plain `node --test test/` fails on Node 22 with `MODULE_NOT_FOUND`. Take the digest from `grep -o 'node@sha256:[0-9a-f]*' images/base/Dockerfile`, never from notes, which may hold a shortened digest.
- **[gotcha]** The lane image copies runner files one by one, so a new `runner/*.mjs` must be added to the `COPY runner/...` line in `images/base/Dockerfile`. Bump the protocol whenever the job's meaning changes. `Protocol` in `internal/run/protocol.go` must match `PROTOCOL` in `runner/runner.mjs`, and `runner/PROTOCOL.md` must be updated with it. After any runner change, run `./bin/automaticum image build` before an end-to-end run. Check the result with `docker run --rm --entrypoint ls automaticum-lane:base /opt/automaticum/runner`.
- **[pattern]** To deploy a rebuilt daemon: run `make build SPIKE_ROOT=<dir>`. Get the old daemon's pid with `ss -ltnpH 'sport = :7411' | grep -o 'pid=[0-9]*'`, `kill -TERM` it, and wait until `kill -0` fails. Restart it with `nohup ./bin/automaticumd --config $AUTOMATICUM_CONFIG >> <work>/automaticumd.log 2>&1 &`, then poll `curl -sf http://127.0.0.1:7411/v1/status`. Stop and restart the stub on port 7412 the same way.
- **[env]** Foreground `sleep` is blocked in this environment. Inside a polling loop, wait with `timeout 1 tail -f /dev/null` instead.
- **[gotcha]** A new or changed task is `SKIPPED` by the `oracle` gate (cell exit 20) until `automaticum oracle verify <suite>/<task>` has proven the oracle against its fixtures. Run it right after you create or edit a `task.toml`. To make a demo task, copy a sibling under `tasks/demo/` (`seed/`, `fixtures/`, `task.toml`) and change `id`.
- **[gotcha]** SDK session facts (4.100.25x, seen on the stub): with `interactive: false` the session is disposed when it ends, so a later `core.send()` fails with `session not found`. Use `interactive: true` only when the runner must speak again (scripted user, or an arm that starts in plan mode, where the agent can switch modes itself), and `core.stop()` it at the end. The SDK numbers `iteration` from 1 again in each run of a session, so count turns yourself from the lead agent's `iteration_start` events. A `steer` send aborts the request in flight, which shows on the wire as an `AbortError` request with no finish reason.
- **[gotcha]** A `python3` replace script with `assert old in s` often fails: on Go struct fields that gofmt aligned, on code whose tab depth you guessed, and on spec paragraphs whose line breaks you guessed. The failure message names the anchor. First look at the exact bytes with `grep -n -A1 '<phrase>' <file> | cat -A`, or with `sed -n <a>,<b>p` for a spec paragraph. Copy the whitespace and line wraps from that output, or match with a regex. Run `gofmt -w` after you insert fields.
- **[gotcha]** A stub script plays its turns in order, whatever the SDK asks. The arm's no-tool-call nudge answers every text-only reply once, so a run ends only on the second text-only reply, and the script must give one turn to the nudge. The read-before-edit guard refuses an `editor` call until the file was read with `read_files`. A denied read counts as not read. If a run ends `FAIL` with `exit 0`, grep the run's logs for `"output"` on `editor` before you suspect the harness.
- **[gotcha]** Before you decide that the SDK "loses" state across sessions, check how the Cerebriline extension wires it. Core makes a fresh read-receipt registry for each session unless `ClineCore.create` gets `capabilities.readReceipts` (`sdk.createReadReceipts()`); the runner passes one registry per run. `switch_to_act_mode` is not in any SDK release. The extension adds it as an `extraTool` (built with `sdk.createTool`, `lifecycle.completesRun`), and the runner ports it in `runner/plan.mjs`.
- **[gotcha]** The SDK's checkpoints are git commits in the session's cwd. There is no shadow repository, and `checkpoint.enabled` must be true on the session config. Since D87, every lane workspace is a git repository by default, with the seed as one commit. Read the setting with `Workspace.GitRepo()`, not the `*bool` field. A task can opt out with `[workspace] git = false`, but then a script that restores a checkpoint fails to load. `checkpointRunCount` counts user runs, not turns.
- **[gotcha]** `go test -race` needs cgo, so `CGO_ENABLED=0 go test -race` fails with `-race requires cgo`. Run the `-race` packages with plain `go test -race ...` on the host. Use `CGO_ENABLED=0` only for `go vet` and for `cmd/automaticum`, or just run `make test`.

- **[pattern]** To learn what the Cerebriline SDK really does, read the installed build under `<data_root>/sdk/<release>/node_modules/@cerebriline/`. `data_root` is in the config's `automaticum.toml`, and `automaticum sdk ls` lists the builds. - **[gotcha]** `automaticum run tail <id>` works only on a run in flight, and it never ends. On a finished run it prints only a hint. Capture a live tail with a bound, to a file on persistent disk: `timeout 8 ./bin/automaticum run tail <id> > <work>/tail.jsonl; true`. Read a finished run's full event stream with `timeout 60 ./bin/automaticum logs <id>`. Read its wire capture with `logs <id> --wire` or `curl -s http://127.0.0.1:7411/v1/runs/<id>/blobs/wire`. Wire lines are flat: `request_body` and `response_body` are JSON strings, with no nested `request.body`. Some lines (such as `GET /props`) have no body or have an `error` field instead, so read them with `d.get(...)`, never `d['...']`. To find the model request, pick the first body that has both `messages` and `tools`. Leave out the `*_body` and `*_headers` fields when you print. `run ls` takes `-limit N` (default 30), not `-n`.
- **[pattern]** To test end to end without a GPU, use the stub model server. The `stub` endpoint in the local config points at the Docker bridge gateway. Run `automaticum stub serve --script <work>/stub/<file>.json --listen 172.17.0.1:7412`, then `automaticum cell run --suite demo:<task> --arm stub --out <dir> --idempotency-key <k> --poll 2s`. The stub also speaks llama-server's API (`/v1/chat/completions` with SSE, `/v1/models`, `/props`). For mode C, add `--endpoint-url http://172.17.0.1:7412/v1 --served-model stub:latest --endpoint-kind <kind> --caller-values <file> --basis-facts <file>`. `--caller-values` is a JSON or TOML file (sampler and thinking each need `"owner": "arm"`), and `--basis-facts` is JSON or a JSON file. The facts must agree with the stub's `/props` (`{"quantization":"none","n_parallel":1,"ctx_per_slot":32768,"gpu":"none (stub)"}`), or every run is `SKIPPED` by gate `basis_facts`. Use a new key for each attempt, and stop the stub afterwards.
- **[gotcha]** An endpoint `kind` is not always an SDK provider id. `llamacpp` is an OpenAI-compatible llama-server, and the SDK has no provider of that name. Passing it through gives the agent error `Unknown or disabled provider "llamacpp"` before the first chat request, and the run ends `FAIL` (cell exit 10). Always map kinds with `config.ProviderFor(kind)`. When you add an endpoint kind, grep the SDK's `@cerebriline/llms/dist/index.js` for the provider id first. A mode C cell that fails with no chat request on the wire is a harness bug, so check `logs <id>` for an `"type":"error"` agent event.
- **[gotcha]** The CLI uses Go's `flag` package, so flags must come before the positional arguments. `automaticum run invalidate <run> "<reason>"` prints only the usage text. The correct form is `automaticum run invalidate --reason "<why>" <run>`. Invalidate any run that a harness bug broke, and name the bug id in the reason, so its verdict does not count.
