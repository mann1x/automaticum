# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[convention]** When you add a metric in `internal/ingest` (`m("name", ...)` in `analyse.go`), bump `AnalysisVersion` in `analyse.go` and document it in 070 §2. If the metric says nothing at zero (a count of something most runs never have), add its prefix to `quietWhenZero` in `internal/daemon/compare.go` and to the zero filter in `cmd/automaticum/client_cmds.go` (`run show`), and extend `TestDropQuietUser`. Runner notes become metrics through `eventLine` fields in `events.go` (`case l.K == "runner"`), not through the SDK event.
- **[gotcha]** In SDK 4.100.258 only the reasoning-loop guard (`metadata.kind: "reasoning_loop"`, phase `cut`, `aborted` or `removed`) and the tool-intent guard (`tool_intent_overrun`, `cut`) announce a trip as a `notice` event. Tool-call loop detection emits nothing: a soft verdict is appended to the tool result text, a hard one goes to the mistake tracker and shows only as the end (`mistake_limit`). The no-tool-call nudge is `kind: "nudge"`, the runtime's, not a guard. Match guards on `metadata.kind`/`phase`, never on message sentences. Enumerate the kinds with `grep -oE 'metadata:\{kind:"[a-z_]+"(,reason:"[a-z_]+")?(,phase:[^,}]+)?' <pkg>/dist/index.js | sort | uniq -c`.
- **[pattern]** Requests for SDK behaviour (a new notice, a shared tool) go to the Cerebriline session by mail (`mailbox-send` of the pgvector MCP), with what you read in the bundle, the exact names you want and the release you need it in. Note the gap in `runner/PROTOCOL.md` and 040 §8 until it lands, and reply to their open items in the same mail.
- **[convention]** When the owner gives a host a new neutral name, add it in four places: the neutral-name lists in `CLAUDE.md` and `.claude/rules/spec-conventions.md`, the real-name row in the untracked `docs/local/hosts.local.md`, and the public-repo memory note. Then add the host's private nickname and ssh alias to the leak-check grep above. Ask for the name before a new host appears in any tracked file.
- **[pattern]** To learn what the Cerebriline SDK really does, read the installed build under `<data_root>/sdk/<release>/node_modules/@cerebriline/`. `data_root` is in the config's `automaticum.toml`, and `automaticum sdk ls` lists the builds. Grep the `.d.ts` files in `core/dist`, `shared/dist` and `agents/dist` for types (`shared/dist/agents/types.d.ts` has the event shapes, `core/dist/runtime/safety/` the guards). For the logic read `core/dist/index.js` or `agents/dist/index.js`; `core/dist/hub/daemon/entry.js` repeats core's code and is what `grep -rl` finds first. `grep` here is ugrep and rejects some patterns as too complex: `.{0,N}` with alternation, large bounded classes, and `-o '.\{300\}needle.\{500\}'` returns nothing. For a window around a needle use `python3 -c` with `re.finditer(re.escape(needle), s)` and print `s[m.start()-500:m.start()+700]`. Never guess SDK behaviour; confirm it there or on the stub.
- **[pattern]** For a corpus analysis, dump `run ls -json` to a file on persistent disk, then `run show -json <id>` per id. In `run ls -json` not every row has `model` (use `.get`), legacy-imported runs carry `campaign = "legacy-native"`, and imported ids are not all date-prefixed (some begin with a lane name), so glob `*.json`, never `2*.json`. In `run show -json`, `metrics` is a list of `{name, value}` objects, not a map, `findings[]` carry a `detector` name, and `blobs[]` lists the stored streams (`events`, `wire`, `oracle`, `session`) with hash and size.
- **[pattern]** To prove a new SDK build or a runner protocol change on the stub, run every demo task with the stub script it needs (the scripts live in the untracked `<work>/stub/`): `demo/answer` with `fix-answer.json`, `demo/scripted` with `fix-scripted.json`, `demo/plan` and `demo/plan-switch` on the plan arm with `fix-plan.json` and `fix-plan-tool.json`, `demo/cancel` and `demo/fork` with `fix-answer-slow.json`. All six must end `PASS`. In a script, wait for the stub with `ss -ltnH 'sport = :7412'` and poll `run ls -limit 5 | grep "^$id" | grep finished`; foreground `sleep` is blocked in this harness, so pause with `timeout <s> tail -f /dev/null`.
- **[gotcha]** Arm, endpoint, lane and campaign names must match `^[a-z0-9][a-z0-9_.-]*$` (`armNameRE` in `internal/config/arm.go`): an uppercase letter gives `"<name>" is not a valid arm name`, and the file must be renamed, not just its contents. When validating in a loop, `CGO_ENABLED=0 go run ./cmd/automaticum arm validate <arm> 2>&1 | tail -1` shows only `exit status 1` and hides the message; build once with `CGO_ENABLED=0 go build -o <scratch>/am ./cmd/automaticum` and call the binary.
- **[gotcha]** `automaticum arm validate` also checks that the arm's endpoint exists in the local installation (`names endpoint "x", which this installation does not have`), so an arm written for another host's endpoints cannot pass here. `automaticum arm show <arm>` still resolves it and prints every value with the file it came from, which is enough to check the arm itself and its id.
- **[pattern]** To run an arm meant for a llama-server endpoint against the stub: add `<config>/endpoints/stub-openai.toml` with `kind = "llamacpp"`, `base_url = "http://172.17.0.1:7412/v1"`, a `host` and `capacity = 1`, add the name to `endpoints = [...]` in `<config>/lanes/lane-1.toml` (the lane gate refuses an endpoint the lane may not use), and drop a temporary `arms/zz-<name>.toml` that `extends` the template, names that endpoint and `model = "stub:latest"` (the stub's model name; `"stub"` is not listed). The daemon reads the repo's `arms/` directly, so no scratch copy of the repo is needed. Delete the `zz-` arm before committing. The stub answers `/props` with `chat_template_caps`, so the template gate holds; a `SKIPPED` run names the gate that refused it in its reason.
- **[pattern]** After `make build`, restart the daemon by hand: `pid=$(ss -ltnpH 'sport = :7411' | grep -o 'pid=[0-9]*' | head -1 | cut -d= -f2); kill -TERM $pid`, wait until `kill -0 $pid` fails, then `nohup ./bin/automaticumd --config $AUTOMATICUM_CONFIG >> <work>/automaticumd.log 2>&1 &` and poll `curl -sf http://127.0.0.1:7411/v1/status` before the first `automaticum` command. The daemon listens on 7411, the stub on 7412.
- **[gotcha]** With SDK 4.100.258 and the `openai-compatible` provider, `[thinking] owner = "arm"`, `enabled = true` puts nothing on the wire: only an `effort` level is sent, as `reasoning_budget_tokens` (`high` → 48000). Every run then carries the `wire_arm` warning `stated, not sent: thinking.enabled = true`. For a llama-server endpoint either state an effort or use `thinking.owner = "tag"` and let the server's template settings decide; `thinking.blocks` in `run show` tells whether the model thought. Check what reached the server with the first line of `logs -wire <id>`: decode `request_body` and drop `messages` and `tools`.
- **[gotcha]** Go's `json.Marshal` escapes `<`, `>` and `&` as `\u003c`, `\u003e`, `\u0026`, so a test that does `strings.Contains(string(id.Details), `"eos_token":"<turn|>"`)` fails although the value is there. Assert on `json.RawMessage` fields (`Identity.Details`, event payloads) by unmarshalling into the struct, never by substring on the raw bytes.
- **[convention]** When the owner gives a host a new neutral name, add it in four places: the neutral-name lists in `CLAUDE.md` and `.claude/rules/spec-conventions.md`, the real-name row in the untracked `docs/local/hosts.local.md`, and the public-repo memory note. Then add the host's private nickname and ssh alias to the leak-check grep that runs before every commit. Ask for the name before a new host appears in any tracked file.
- **[gotcha]** `automaticum run tail <id>` works only on a run in flight and never ends; on a finished run it prints only a hint. Capture a live tail with a bound to persistent disk: `timeout 8 ./bin/automaticum run tail <id> > <work>/tail.jsonl; true`. Read a finished run with `timeout 60 ./bin/automaticum logs <id>`, its wire with `logs -wire <id>` (there is no `-kind wire`). Wire lines are flat (`request_body`, `response_body` are JSON strings); some have no body or an `error` field, so read with `d.get(...)`. In `logs`, an SDK event is nested as `event.payload.event` (the agent's `type`, `noticeType`, `metadata` live there). `run ls` takes `-limit N` (default 30), not `-n`.
- **[gotcha]** `.wolf/anatomy.md` lists files under `## <dir>/` sections and file names repeat across sections (`cell.go` is in both `internal/config/` and `internal/daemon/`; every `runner/sdk/<build>/` has the same three files). A global regex replace on a file name fails or hits the wrong entry. Edit by walking the lines tracking the current `## ` section, or insert before a unique `## <dir>/` anchor. The OpenWolf post-write hook already adds a stub entry for every new file: replace that line, don't add a second, then grep for duplicates.
- **[gotcha]** Before deciding the SDK "loses" state across sessions, check how the extension wires it. Core makes a fresh read-receipt registry per session unless `ClineCore.create` gets `capabilities.readReceipts` (`sdk.createReadReceipts()`); the runner passes one registry per run. `switch_to_act_mode` is in no SDK release before 4.100.253: the extension adds it as an `extraTool` (`sdk.createTool`, `lifecycle.completesRun`), ported in `runner/plan.mjs`.
- **[gotcha]** The CLI uses Go's `flag` package, so flags must come before positional arguments. `automaticum run invalidate <run> "<reason>"` prints only usage; use `automaticum run invalidate -reason "<why>" <run>`. Likewise `run start -arm stub demo/answer` fails with usage: the task is a flag, `run start -arm stub -task demo/answer`, and the run id is the last line it prints. Several `-arm` flags with `-n 10 -order interleaved -lane <lane>` make one interleaved batch.
- **[pattern]** To provision a new SDK release `<v>`: the host has no Node, so list what is published with `docker run --rm node@sha256:<digest> npm view @cerebriline/sdk versions --json` (digest from `images/base/Dockerfile`). Copy `runner/sdk/<old>/package.json` to `runner/sdk/<v>/` with the version replaced, write `sdk.toml` with `version` and `source = "registry"`, make the lockfile in the same image with `npm install --package-lock-only --ignore-scripts --no-audit --no-fund` (mount the build dir as `/w`), then `./bin/automaticum sdk add <v>` with `AUTOMATICUM_CONFIG` set. The first install writes `bundle_sha256` into `sdk.toml`; commit it, since no run uses an unpinned build. Then add `arms/stub-sdk-<v>.toml` (`extends = "stub"`) and the stop and plan variants, each with `[harness] sdk_release = "<v>"`, and update the `sdk/` and `arms/` lines of `CLAUDE.md` and the matching `.wolf/anatomy.md` sections.
- **[pattern]** In `logs -wire <id>`, the `response_body` of a streamed chat completion is the raw SSE text: split on lines starting `data: {`, concatenate `choices[].delta.content` and `delta.reasoning_content`, collect `delta.tool_calls`; `finish_reason` is on the last choice chunk and `usage` in the final chunk. Decode `request_body` and drop `messages` and `tools` to see which sampler and `max_tokens` reached the server.
- **[pattern]** When you add a required arm setting (030 §5.1: every guard setting must be stated), make it a pointer with `omitempty` and drop its neutral value (false, or an empty list) in `Arm.Resolved()`, so arms resolved before the field existed keep their id. Prove it: compare `run ls -json` `arm_id` prefixes of past runs with `arm show <arm>` ids. The old `bin/automaticum` refuses the edited `arms/base.toml` with `unknown fields: guards.<new>`, so compare with `CGO_ENABLED=0 go run ./cmd/automaticum arm show <arm>` until you rebuild. When renaming or replacing an arm setting, grep the old name with `--include=*.go --include=*.toml --include=*.mjs --include=*.md`: `.claude/rules/runner-protocol.md` and the specs (020, 030, 040, 070) reference arm fields too.
- **[gotcha]** From SDK 4.100.259 every guard announces its action as a `notice` with `metadata.kind` (`loop_detection`, `reasoning_loop`, `tool_intent_overrun`, `nudge`, `edit_verification`, `checklist_close_out`, `team_obligation`, `struggle`) and `metadata.phase`; a nudge's phase is `metadata.nudge`. `reasoning_loop`, `tool_intent_overrun` and the nudge emitter are in `agents/dist/index.js`; `loop_detection`, the completion guards and `struggle` are in `core/dist/index.js`, so grep both with `grep -oE 'kind:"(<kinds>)"[^}]{0,120}'`. To trip `loop_detection` on the stub, a script with three or more identical `tool_calls` turns is enough (`{"turns":[{"thinking":"...","tool_calls":[{"name":"read_files","arguments":{...}}]}, ..., {"content":"..."}]}`); soft fires from the third and keeps firing on every repeat, and `edit_verification.nudge` shows up at completion too.
- **[correction]** Which guard trips end a run, and any other run behaviour the owner chooses (thresholds, sets of signals), is arm configuration under `[guards]` in the arm TOML (`guards.stop_on`, D100), never a constant or hard-coded list in `runner/*.mjs` or the Go harness. The owner rejected a runner-side loop-signal table: "this is obviously a configuration for the runs, it's not a static configuration". `guards.stop_on` names are validated against `guardPhases` in `internal/config/arm.go`, so a new SDK guard kind must be added there and in `runner/guards.mjs` together.

Take a relayed owner statement literally; when arms or counts are ambiguous, ask the owner before `run start`, not the peer session.

- **[pattern]** Deploying to blackswan-2: push the commit first, then claim the host's build resource with `claude-hooks-res acquire <host>/build:shared -r "<why>"` before `image build` there. scp the new `bin/automaticum` and `bin/automaticumd` into `<install>/bin/.new/`, `systemctl stop automaticumd`, move them into place, `systemctl start automaticumd` and poll `curl -sf http://127.0.0.1:7411/v1/status`. The daemon there is a systemd unit and reads arms from `<install>/repo/`, a checkout pinned with `git fetch -q && git checkout -q <commit>`. Every endpoint or lane file change needs `systemctl restart automaticumd`; then `arm validate` each arm and run `doctor -all -arm <arm> -task <task>` before the first batch on a new endpoint (`-all` shows every gate's answer; without it only refusals and unchecked gates). Release the claim when the image build is done.
- **[gotcha]** A batch id is not the run ids' prefix (runs `...-819b65-NNN` belonged to batch `b...-524ef9`), and `batch pause` with the prefix answers `has no run queued or in flight`. Take the batch id from the first line `run start` prints (`... batch b<id>`) or from `run show -json <run>` field `batch`. `batch pause` holds the in-flight run before its next model request: the run stays `running` and the lane stays busy until `run abort <id>`; the "endpoint freed of its model" part applies to Ollama-kind endpoints only, a llama-server endpoint is never unloaded. `batch stop` records every queued run `SKIPPED` and lets the in-flight one finish.
- **[gotcha]** The canary judges a batch's first requests even when their runs were later marked INVALID (bug-030, open): resuming a paused batch after invalidating its first runs gets it stopped at once (`the canary stopped the batch: <run>#2: ended by length`) and every queued run is SKIPPED. After invalidating a batch's early runs, stop that batch and start a fresh one; `batch show <id>` lists the requests the canary judged and its problems.
- **[gotcha]** Before a batch on a new llama-server endpoint, do not trust `/props` `default_generation_settings.params.chat_format` and `reasoning_format`: they read `Content-only` and `none` even when tool parsing and the reasoning channel work, because they are the idle defaults, not what a chat request gets. The evidence is a run's `tool_calls` and `thinking.blocks`. Have the server owner confirm the GGUF is the instruct file (`general.name` ending `-it`) and curl one tools + thinking request first: a base model served by mistake answers off-task text with no tool calls and no reasoning, and the run FAILs in seconds. If the first run shows 0 tool calls and `thinking.blocks 0`, pause the batch and mail the server owner instead of letting it run.
