- **[env]** The tests of `internal/docker` and `internal/task` start real containers on the local Docker engine; they skip themselves with `-short`, without a socket, or when an image cannot be pulled. They bind-mount `t.TempDir()` into containers, so `TMPDIR` must be a directory on a real disk that the engine can see, and `AUTOMATICUM_TEST_ARTEFACTS=<dir>` keeps the built oracle (about 150 MB) between runs instead of rebuilding it each time: `mkdir -p <tmp> && TMPDIR=<tmp> AUTOMATICUM_TEST_ARTEFACTS=<cache> go test -count=1 ./internal/task/`.
- **[gotcha]** A `docker.Mount` source must be an absolute host path. A relative one (a task loaded from `../../tasks` in a test) is taken by the engine for a volume name and the create call fails with `docker: 400: ... includes invalid characters for a local volume name`; make the path absolute where it is loaded (`filepath.Abs`), not at each call. The oracle of `tasks/custom/manic_miner` is a Node single executable and needs `libatomic.so.1`: in a plain `debian:bookworm-slim` it dies with `error while loading shared libraries: libatomic.so.1`, so run it in the Node image pinned in `task.toml`, or in an image that has `libatomic1`.
- **[convention]** Files under `tasks/` are kept byte for byte, because every file of a task is hashed into its identity and the `manic_miner` seed has CRLF line endings on purpose. `.gitattributes` marks `tasks/**/*.html` and `tasks/**/oracle/*.js` as `-text`; after staging a task run `git ls-files --eol tasks` and expect `i/crlf w/crlf attr/-text` for the seed and the fixtures. Never let an editor, a formatter or a `sed` without care normalise them, and add a `-text` line for any new file type whose bytes matter.
- **[convention]** A task artefact is pinned twice in `task.toml`: its build image by digest (`node@sha256:...`) and its result by `sha256`. Build it in a container with `--network none`, twice into two directories, and compare the two hashes before writing the pin; any change to an input (`oracle/build.mjs`, `oracle/run_game.logic.js`) or to the image gives another binary, and `task.Env.Build` then refuses it with `ErrArtefactChanged`. Fix that by rebuilding and updating the pin in the same change, never by loosening the check. After building, confirm the fixtures: the known-good page passes and the seed and the weakened page fail.

- **[env]** `CGO_ENABLED=0 go build -o <scratch>/automaticum ./cmd/automaticum` builds the command line on the host without the link image; that binary has the arm, task, oracle, lane and endpoint commands, and `legacy import` and `store check` answer "this build has no store". `go vet` and `go test` on `./cmd/automaticum/` need `CGO_ENABLED=0` on the host as well. `arm validate|show|diff` and `task ls|show` need only the checkout (run from the repo root or pass `--repo`); `task build`, `oracle verify`, `lane ls` and `endpoint ls` need a configuration directory (`--config` or `AUTOMATICUM_CONFIG`). - **[convention]** A new command in `cmd/automaticum` is one entry in the `cmds` map of `main.go` under its `"<noun> <verb>"` key plus one line in the usage text. Parse its flags with `args = parse(fs, args)`, not `fs.Parse(args)`: Go's `flag` stops at the first argument that is not a flag, so `automaticum oracle verify demo/answer -repeats 2` printed the usage error until the helper was used. A command that opens the store goes in `store_cgo.go` with a stub returning `errNoStore` in `store_nocgo.go`. A new pure-Go package is added to the `test` target of the `Makefile` (recipe lines start with a tab) and to the `make test` sentence in `CLAUDE.md`.
- **[convention]** An arm states every setting; nothing has a default and an unknown field is an error. An arm that exists only to be extended carries `template = true` at the top (the mark is not inherited); without it `automaticum arm validate` lists what it leaves unstated and exits 1. A child switches a feature off by stating only the switch (`enabled = false`, `owner = "tag"`, `mode = "off"`): the settings inherited under it are dropped, and restating one of them beside the switch is refused. `internal/config/config_test.go` reads `arms/base.toml`, so after any edit under `arms/` run both `automaticum arm validate` and `go test -count=1 ./internal/config/`.
