# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[convention]** Every view of a batch's numbers goes through `compareView(ctx, batches, leave)` in `internal/daemon/compare.go`. `leave` holds run ids that must not be counted, such as runs a retry replaced. Reuse it for `compare`, `basis` and `cell` instead of grouping runs a second time. The map from a retry to the run it replaced is `d.ctl.Retries` (new → old), read under `d.mu`.
- **[gotcha]** xOllama's `/api/show` lists a tag's parameters in an order that changes between releases, with the same values. Never hash or compare the raw text. Use `run.ParametersKey`, which sorts the lines. Otherwise `compare` shows `CHANGED BETWEEN RUNS` for `tag parameters`, and the before/after probe can make a run `INVALID`. A `CHANGED BETWEEN RUNS` row is real only when the values differ.
- **[pattern]** Compare runs with `automaticum compare <batch> [<batch> ...]`. Use `--all` for every metric and `--json` for the numbers. It needs the running daemon on the current build. A batch started with `--idempotency-key <key>` is named `k-<key>`. Queue several arms as one interleaved batch with `run start --arm A --arm B --task <suite>/<task> -n <n>`, and check it with `--dry-run` first. Read `what differs between A and B` and the basis section before any number. `automaticum basis diff <batch[/arm]> <batch[/arm]>` lists exactly the 020 §5 facts that differ. `basis show <batch> [--arm A]` marks `MIXED` where a group's own runs differ.
- **[convention]** A new command in `cmd/automaticum` is one entry in the `cmds` map of `main.go` under `"<noun> <verb>"`, plus one line of usage. One-word commands go in the `one` map. Parse flags with `args = parse(fs, args)`, not `fs.Parse(args)`, because Go's `flag` stops at the first argument that is not a flag. `cmd/automaticum` is one package that already has helpers (`short`, `sorted`, `table()`, `printJSON`, `letter`, `addClient`, `errFailed`, `exitCode`). Run `grep -n '^func <name>' cmd/automaticum/*.go` before you add one, because a second copy fails vet with `redeclared`. A command that needs its own exit code returns `exitCode(n)`, and `main` exits with it.
- **[pattern]** Edit Go and specs with a `python3` replace script. Use `assert old in s` on each replacement, or print `MISSING` for it, so that a stale anchor is not skipped silently. Replace with count 1 (`s.replace(old,new,1)`). An unbounded replace also hits text that an earlier replace in the same script just inserted. Run `gofmt -l internal cmd` and `go vet` of the touched packages in the same call. Before you write code against a struct from another package, grep its fields (for example `grep -n 'type ControlResult' -A8 internal/detect/controls.go`; the field is `OK`, not `Pass`).
- **[convention]** When a feature from a spec is built, add an `**As built (milestone N, date):**` paragraph or a `§x.1 As built` section to that spec. It says what exists, how it was proved (for example on the stub), and a `**Not built yet:**` list. Bump the spec's `**Status:**` draft number, and add the command and the route to 090 §1.
- **[gotcha]** On the host, `go build ./...` and plain `go run ./cmd/automaticum` fail at the link step because the store needs cgo. `cmd/automaticumd` cannot be built on the host at all. Iterate with `CGO_ENABLED=0 go vet|test` on the packages, and with `CGO_ENABLED=0 go run ./cmd/automaticum detect --self-test`. Leave full builds to `make build`, with its log under the work directory. A control in `internal/detect/controls.go` lists every detector that fires on it: write the text, read the `FIRED` column, then decide. Filler text in tests must not be periodic.
- **[pattern]** To find where a number in a spec came from, run `git log --format='%h %ad %s' --date=short -S"<phrase>" -- docs/specs/<file>.md`, then `git show -s --format=%B <hash>`. When the source is another project's code that is not in the repo, mail that project's session (omnimergekit is `backup_models@solidpc`) and ask for the file, the commit and a fixture set. Number your questions so each one can be confirmed or corrected. Build with the spec's numbers, labelled as taken from that code. Nothing of theirs goes into the public repo, only the numbers. When a feature depends on the other side's half of a contract (for example `cell run` mode C), build your own half, then mail numbered questions with a proposal for each, and build the rest from their answers.
- **[convention]** When you port a rule from another project's code (for example omnimergekit's cap audit), the spec section must say which parts are theirs, with the file and the commit ("checked against ... at `01f5ed3`"). It must label automaticum's own parts as automaticum's own. Port their logic exactly as written, including what a row is and whether counts are of requests or of tasks. Defer the parts that belong to another kind of suite to that suite's milestone, and name their fixture file.
- **[pattern]** Edit Go and specs with a `python3` replace script:
  - Use `assert old in s` on each replacement, or print `MISSING` for it, so that a stale anchor is not skipped silently.
  - Replace with count 1 (`s.replace(old,new,1)`). An unbounded replace also hits text that an earlier replace in the same script just inserted.
  - Never move a handler's body into a function with a bulk regex. The regex that turns `fail(w, ...); return` into `return resp, code, err` also rewrites the new wrapper's own decode error. Early returns then use `resp` before it is declared (`vet: undefined: resp`). Declare the result at the top of the new function, and check the wrapper by hand.
  - Run `gofmt -l internal cmd` and `go vet` of the touched packages in the same call.
  - Before you write code against a struct or helper from another package, grep its fields and names (for example `grep -n 'type ControlResult' -A8 internal/detect/controls.go`; the field is `OK`, not `Pass`).
- **[gotcha]** Package-level regexps are not shared across packages. In `internal/config` the name pattern is `armNameRE` (in `arm.go`). `nameRE` exists only in `internal/task`. Run `grep -n 'regexp.MustCompile' internal/<pkg>/*.go` before you reuse one, or vet fails with `undefined: nameRE`.
- **[convention]** Daemon state that must survive a restart goes in the `control` struct in `internal/daemon/control.go` (it is saved as `control.json`). A new map needs its nil-map initialisation in both places: after the load and in the fresh literal. Change it under `d.mu`, followed by `d.saveControl()`.
- **[gotcha]** `internal/daemon` tests run with `-race`. Never read a `*State` from `d.ctl` after `d.mu.Unlock()`, because the loop goroutine mutates it. Copy what you need while you hold the lock: a value copy plus `append([]T(nil), slice...)` for its slices. Build every API view from a `snapshot()`, never from `*c`. A race shows as `testing.go: race detected during execution of test`. To find the line, filter the output with `grep -A6 'WARNING: DATA RACE\|Previous'`.
- **[pattern]** A daemon test that needs the real arms and tasks (for example to start a batch or a campaign) makes a `t.TempDir()`, symlinks the absolute paths of `../../arms` and `../../tasks` into it, writes its own files beside them (for example `campaigns/<name>.toml`), and sets `g.d.Repo` to that directory. Set a loop interval such as `g.d.CampaignEvery` to 10 ms. Use `newRig`, `g.call`, `g.runner.hold` and `g.runner.started`, and `g.waitFinished`. Run new tests with `-count=3` to catch flakes.
- **[convention]** A new field on a run (for example `Campaign`) has to be added in every one of these places:
  - `run.Request` in `internal/run/run.go`
  - the record literal in the executor (`ID: req.ID, Batch: req.Batch, ...`)
  - the fake runner in `internal/daemon/daemon_test.go` (`r := &store.Run{...}`)
  - the place in `daemon.go` that builds the request
  - the run view in `internal/daemon/api.go`
  - the `line(...)` call in `run show` in `cmd/automaticum/client_cmds.go`
- **[pattern]** To deploy a rebuilt daemon:
  1. Run `make build SPIKE_ROOT=<dir> > <work>/build-X.log 2>&1`.
  2. Find the PID with `P=$(ss -ltnpH 'sport = :7411' | grep -o 'pid=[0-9]*' | cut -d= -f2)` and send `kill -TERM $P`.
  3. Wait until `kill -0 $P` fails.
  4. Start it with `nohup ./bin/automaticumd --config $AUTOMATICUM_CONFIG >> <work>/automaticumd.log 2>&1 &`.
  5. Poll `curl -sf http://127.0.0.1:7411/v1/status` until it answers.
- **[env]** Foreground `sleep` is blocked in this environment. Inside a polling loop, wait with `timeout 0.5 tail -f /dev/null` (or `timeout 5 ...`), and bound the loop with `for i in $(seq 1 N)`.
- **[gotcha]** The Caliber pre-commit hook runs on every `git commit` and prints `caliber: refreshing docs...`. Stage with `git add -A . ':!.wolf/cron-state.json'`. Before you commit, run the public-repo name scan over `git ls-files`, excluding `CALIBER_LEARNINGS.md` and `package-lock.json`. The scan must print `CLEAN`.
- **[correction]** When an Ollama or xOllama server can be asked or told something, automaticum asks it or does it itself. It does not ask the owner to do it.
- **[convention]** These are the places to update for compare, ingest and reanalyse:
  - A metric shows in `compare` without `--all` only when it is in `mainMetrics` in `cmd/automaticum/compare_cmds.go`.
  - A counting metric that is absent from runs where nothing happened needs its prefix in `counter` in `internal/daemon/compare.go`.
  - In `store.Run`, the SDK build is the field `Harness`. `SDKRelease` exists only in the API views.
  - A new ingest finding must also be added to the `owned` map in `internal/ingest/analyse.go`. Otherwise `reanalyse` will not replace its old findings.
- **[convention]** Detector versions of ingest's own findings live in the `Versions` map in `internal/ingest/analyse.go`. Never put a literal `DetectorVersion: "1"` there. Whenever a version in that map changes, or a detector is added, bump `AnalysisVersion` and run `automaticum reanalyse`. Every run records it as the metric `analysis.version`, and the basis reads from that metric which detectors a run was analysed with.
- **[pattern]** After any change to ingest (a new metric, finding, verdict rule or detector version), deploy the daemon and run `automaticum reanalyse`. With no flags it analyses every run again. Use `--run <id>` or `--batch <b>` to limit it. Until runs are analysed again, `compare` and `basis` treat a missing metric as "analysed before the feature existed" (`UNVERIFIED`, or `not recorded: ...`).
- **[gotcha]** Read a finished run's wire capture with `timeout 60 ./bin/automaticum logs <id> --wire`, or with `curl -s http://127.0.0.1:7411/v1/runs/<id>/blobs/wire`. Each line has `seq`, `url`, `status`, `t_start`, `request_body` and `response_body`. Leave out the `*_body` and `*_headers` fields when you print.
  - The agent's requests are the `/api/chat` lines whose request has `tools`.
  - The output limit they send is `options.num_predict`.
  - The last NDJSON line of `response_body` has `done_reason`, `eval_count` and `think_budget_tokens`.
  - Every run has one harmless failed request: `POST /api/engine?...&endpoint=tokenize` answers 404 before the model is loaded, and the SDK's next probe gets 200.
- **[gotcha]** `automaticum run tail <id>` never ends and replays the run's stream from the start. It carries only `"k":"event"` lines. Capture it bounded, to a file on persistent disk: `timeout 8 ./bin/automaticum run tail <id> > <work>/tail.jsonl; true`. Read the runner's notes with `automaticum logs <id>`. A plain grep for `holding` also matches the model's reasoning.

- **[pattern]** To test end to end without a GPU, use the stub model server. The `stub` endpoint in the local config points at the Docker bridge gateway.
  - Start it with `nohup ./bin/automaticum stub serve --script <data dir>/work/stub/<script>.json --listen 172.17.0.1:7412 > <work>/stub.log 2>&1 &`.
  - Wait until `ss -ltnH 'sport = :7412'` shows it. The default `127.0.0.1` listen address cannot be reached from a lane container.
  - The scripts include `fix-answer.json`, `fix-answer-slow.json` (6 s per turn), `fix-manic.json`, `hang.json` and `say-done.json`.
  - Use the `stub` arm with `demo/answer`. `campaigns/stub-demo.toml` is a ready campaign on it.
  - Afterwards, kill the stub by the PID from `ss -ltnpH 'sport = :7412'`.
- **[pattern]** To test resume after a crash:
  1. Start the work in the background with the slow stub script.
  2. Wait until `automaticum status` shows `running`.
  3. Send `kill -TERM` to the daemon twice. The second signal aborts the run in flight, which ends `ABORTED` with reason `daemon stop`.
  4. Restart the daemon and run the same command again with the same key.
