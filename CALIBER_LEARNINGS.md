# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[pattern]** To deploy a rebuilt daemon, run `make build SPIKE_ROOT=<dir>`. Find the pid with `ss -ltnpH 'sport = :7411'`, send it `kill -TERM`, and poll `kill -0` until it is gone. Then run `nohup ./bin/automaticumd --config $AUTOMATICUM_CONFIG >> <work>/automaticumd.log 2>&1 &`, and poll `curl -sf http://127.0.0.1:7411/v1/status` until it answers. Check `automaticum status` first to make sure nothing is in flight.
- **[env]** Foreground `sleep` is blocked in this environment. Inside a polling loop, wait with `timeout 1 tail -f /dev/null`, and bound the loop with `for i in $(seq 1 N)`.
- **[gotcha]** The Caliber pre-commit hook runs on every `git commit`. Stage with `git add -A . ':!.wolf/cron-state.json'`. Before you commit, run the public-repo name scan over `git ls-files`, leaving out `CALIBER_LEARNINGS.md` and `package-lock.json`. It must print `CLEAN`.
- **[correction]** When an Ollama or xOllama server can be asked or told something, automaticum asks it or does it itself. It does not ask the owner to do it. The exception is a mode C cell's endpoint: the caller owns it, so automaticum never loads or unloads anything there.
- **[convention]** Detector versions of ingest's own findings live in the `Versions` map in `internal/ingest/analyse.go`. Whenever a detector's output changes, bump its version (for example `WireArmVersion`) and `AnalysisVersion`, then run `automaticum reanalyse`.
- **[gotcha]** A detector that expects an Ollama `options.*` field (for example `num_ctx`) must check the request's protocol with `Request.OpenAI`. OpenAI-compatible chat (llama-server, vLLM) has no per-request context field. Without the check, every mode C run gets `stated_not_sent` warnings. Ingest maps OpenAI body fields to Ollama option names (`max_tokens` → `num_predict`, `reasoning_effort` → `think`).
- **[pattern]** After any change to ingest, deploy the daemon and run `automaticum reanalyse`, limited with `--run <id>` or `--batch <b>` if needed. Until runs are analysed again, `compare` and `basis` show a missing metric as `UNVERIFIED` or `not recorded: ...`.
- **[gotcha]** Read a finished run's wire capture with `timeout 60 ./bin/automaticum logs <id> --wire`, or with `curl -s http://127.0.0.1:7411/v1/runs/<id>/blobs/wire`. Don't guess a path under the work directory: the runs directory is not `<work>/runs`. Leave out the `*_body` and `*_headers` fields when you print.
- **[gotcha]** `automaticum run tail <id>` never ends. Capture it bounded, to a file on persistent disk: `timeout 8 ./bin/automaticum run tail <id> > <work>/tail.jsonl; true`. Read the runner's notes with `automaticum logs <id>`.
- **[pattern]** To test end to end without a GPU, use the stub model server. The `stub` endpoint in the local config points at the Docker bridge gateway. The stub also speaks llama-server's API (`/v1/chat/completions` with SSE, `/v1/models`, `/props`). To test mode C, run `automaticum stub serve --script <file> --listen 172.17.0.1:7412`, then `automaticum cell run --suite demo:answer --arm stub -n 2 --out <dir> --idempotency-key <k> --endpoint-url http://172.17.0.1:7412/v1 --served-model stub:latest --caller-values <file> --basis-facts '<json>'`. Use a new key for each attempt, and stop the stub afterwards.
- **[gotcha]** On an OpenAI-compatible provider, an arm or caller values with thinking owner `"tag"` make the SDK send its own `thinking.budgetTokens = 1024`, and every run is `INVALID`. Mode C caller values must state `thinking` (`owner = "arm"`, enabled, effort).
- **[gotcha]** llama-server's `GET /props` is at the server root, not under `/v1`: strip `/v1` from the base URL. `default_generation_settings.n_ctx` is the context of one slot, `total_slots` is `-np`, and `build_info` is `b<number>-<commit>`. The context of a slot is not always `-c` divided by `-np` (unified KV cache), so never derive one from the other. vLLM returns 404, so treat 404 as "cannot check".
- **[gotcha]** `.wolf/anatomy.md` lists files under `## <dir>/` sections, and file names repeat across sections (`cell.go` is in both `internal/config/` and `internal/daemon/`). A global regex replace on a file name fails or hits the wrong entry. Edit by walking the lines and tracking the current `## ` section.
- **[pattern]** To find where a number in a spec came from, run `git log --format='%h %ad %s' --date=short -S"<phrase>" -- docs/specs/<file>.md`, then `git show -s --format=%B <hash>`. When the source is another project's code that is not in the repo, mail that project's session and ask numbered questions with a proposal for each. omnimergekit is `backup_models@solidpc`, and the Cerebriline SDK is `ollama@solidpc`. Build your own half of the contract, then build the rest from their answers. Record the agreed answer in the spec before you build. Mail again when an experiment answers a question or makes it concrete.
- **[pattern]** To learn what the Cerebriline SDK really does, read the installed build under `<data_root>/sdk/<release>/node_modules/@cerebriline/` (`data_root` is in the config's `automaticum.toml`). Grep the `.d.ts` files in `core/dist`, `shared/dist` and `agents/dist` for types. For the logic, cut a window out of the minified bundle with `grep -o '.\{200\}<needle>.\{200\}' agents/dist/index.js`. Don't use `.{0,N}` with alternation, because ugrep rejects it as too complex. Never guess SDK behaviour; confirm it there or on the stub.
- **[convention]** Detector versions of ingest's own findings live in the `Versions` map in `internal/ingest/analyse.go`. Whenever a detector's output or a metric it reads changes (for example the `finish.*` counts the cap audit uses), bump its version (`WireArmVersion`, `CapHit`, ...) and `AnalysisVersion`, then run `automaticum reanalyse`.
- **[gotcha]** `automaticum run tail <id>` works only on a run in flight, and it never ends. On a finished run it prints only a hint. Capture a live tail with a bound, to a file on persistent disk: `timeout 8 ./bin/automaticum run tail <id> > <work>/tail.jsonl; true`. Read a finished run's full event stream with `timeout 60 ./bin/automaticum logs <id>` and its wire capture with `logs <id> --wire` (or `curl -s http://127.0.0.1:7411/v1/runs/<id>/blobs/wire`). Don't guess a path under the work directory. Leave out the `*_body` and `*_headers` fields when you print. `run ls` takes `-limit N` (default 30), not `-n`.

The OpenWolf post-write hook already adds a stub entry ("Struct: X", "Declares y") for every new file. Replace that line, don't add a second one, then grep for duplicates.
- **[fix]** Run the runner's Node tests in the pinned image, with a shell glob: `docker run --rm --network none -v $PWD/runner:/runner:ro -w /runner node@sha256:<digest> sh -c 'node --test test/*.test.mjs'`. Plain `node --test test/` fails on Node 22 with `MODULE_NOT_FOUND`, because it treats `test` as a module. Take the digest from `grep -o 'node@sha256:[0-9a-f]*' images/base/Dockerfile`, never from notes, which may hold a shortened digest.
- **[gotcha]** The lane image copies runner files one by one. A new `runner/*.mjs` must be added to the `COPY runner/...` line in `images/base/Dockerfile`. After any runner change (or a `Protocol` bump in `internal/run/protocol.go`, which must match `PROTOCOL` in `runner/runner.mjs`), run `./bin/automaticum image build` before an end-to-end run. Otherwise the old runner runs or refuses the job. Check with `docker run --rm --entrypoint ls automaticum-lane:base /opt/automaticum/runner`.
- **[gotcha]** A new or changed task is `SKIPPED` by the gate `oracle` (cell exit 20) until `automaticum oracle verify <suite>/<task>` has proven the oracle against its fixtures. Run it right after you create or edit a `task.toml`. To make a demo task, copy `tasks/demo/answer` (`seed/`, `fixtures/`, `task.toml`) and change `id`.
- **[gotcha]** SDK session facts (4.100.25x, seen on the stub): with `interactive: false` the session is disposed when it ends, so a later `core.send()` fails with `session not found`. Use `interactive: true` only when the runner must speak again, and `core.stop()` it at the end. The SDK numbers `iteration` from 1 again in each run of a session (after a resume or a queued message), so count turns yourself from `iteration_start` events of the lead agent. A `steer` send aborts the request in flight, which shows on the wire as an `AbortError` request with no finish reason.
- **[gotcha]** Finding severities in this codebase are `note` and `warning`, not `info`. Run `grep -o 'Severity: "[a-z]*"' internal/ingest/*.go internal/detect/*.go | sort | uniq -c` before you choose one for a new finding.
- **[pattern]** After any change to ingest, deploy the daemon and run `automaticum reanalyse`, limited with `--run <id>` or `--batch <b>` if needed. Until runs are analysed again, `compare` and `basis` show a missing metric as `UNVERIFIED` or `not recorded: ...`. To report what a reanalysis changed, save `run ls -limit 1000 -json`, `run show -json <id>` for each own run (drop `provenance`, `resolved_arm` and `blobs`) and `compare -json <batches>` before it. Save them again after, then diff verdicts, metrics and findings, leaving the version fields out.
- **[gotcha]** `automaticum run tail <id>` works only on a run in flight, and it never ends. On a finished run it prints only a hint. Capture a live tail with a bound, to a file on persistent disk: `timeout 8 ./bin/automaticum run tail <id> > <work>/tail.jsonl; true`. Read a finished run's full event stream with `timeout 60 ./bin/automaticum logs <id>` and its wire capture with `logs <id> --wire` (or `curl -s http://127.0.0.1:7411/v1/runs/<id>/blobs/wire`). Wire lines are flat: `request_body` and `response_body` are JSON strings, and there is no nested `request.body`. Don't guess a path under the work directory. Leave out the `*_body` and `*_headers` fields when you print. `run ls` takes `-limit N` (default 30), not `-n`.
- **[gotcha]** A stub script plays its turns in order, whatever the SDK asks. The arm's no-tool-call nudge answers every text-only reply once ("[SYSTEM] Your last message contained no tool calls…"), so a run ends only on the second text-only reply, and the script must give one turn to the nudge. The read-before-edit guard refuses an `editor` call until the file was read with `read_files` in the same session. A denied read, a mode switch and a fork all count as not read (a switch or a fork starts a new session). If a run ends `FAIL` with `exit 0`, grep the run's logs for `"output"` on `editor` before you suspect the harness.
- **[gotcha]** A `python3` replace script with `assert old in s` fails on Go struct fields that gofmt aligned (`User     *task.User   ...`) and on code whose tab depth you guessed. The failure message names the anchor. Run `grep -n` on the line first and copy its exact whitespace, or match with a regex such as `\tUser +\*task\.User +`. Run `gofmt -w` after you insert fields.
- **[gotcha]** The lane image copies runner files one by one. A new `runner/*.mjs` must be added to the `COPY runner/...` line in `images/base/Dockerfile`. Bump the protocol whenever the job's meaning changes, so an old runner refuses the job instead of playing it wrongly. `Protocol` in `internal/run/protocol.go` must match `PROTOCOL` in `runner/runner.mjs`, and `runner/PROTOCOL.md` must be updated with it. After any runner change, run `./bin/automaticum image build` before an end-to-end run. Check with `docker run --rm --entrypoint ls automaticum-lane:base /opt/automaticum/runner`.
- **[gotcha]** The SDK's checkpoints are git commits in the session's cwd. There is no shadow repository, and `checkpoint.enabled` must be true on the session config. A lane workspace is not a repository unless the task says `[workspace] git = true`, which makes the runner commit the seed. Without it every restore fails with "No checkpoint found at or before run N". `checkpointRunCount` counts user runs (the start prompt is 1, and each `send` that lands as a user message adds one), not turns.
